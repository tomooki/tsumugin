## 判明したこと

### 1. ★ 観測集合を跨いだ Rwp/BIC 比較は構造的に壊れている (T1 で発覚)

初回実装では **T1 で `adaptive` が `default` に BIC で勝った** (16784.5 < 17875.1)。しかし
Rwp 差はわずか 0.019 であり、勝因は**適応候補がレンジを切って観測点数を 5752 → 5535 に
減らしたこと**である: χ² = GOF²·(n_obs − n_params) は観測点数に比例するので、
**データを捨てた候補ほど BIC が下がる**。

対処: 順位キーに**観測集合**を入れ、基準 (列挙順で最初に結果を返した候補) と点数が違う候補は
**Rwp/BIC では上位に来られない**ようにした。勝てるのは tier (収束・妥当性) だけである。
これは適応レンジ本来の動機と一致する — T4 の非収束はレンジ未設定が主因なので、レンジを切った
候補は「**収束する**」ことで勝つべきであって、「点数が減って χ² が小さい」ことで勝つべきではない。
恒久ガード: `tests/autorietveld/test_search.py::test_a_candidate_that_dropped_data_cannot_win_on_bic`
(実測値そのままを使用) と `..._still_wins_when_it_is_the_only_converged_one`。

### 2. 収束 tier は実データで実際に効く

**T3 の `default` は GSAS 自身の `converged=False`** (S4 uiso 段) だった。仮に `serious` の
Rwp がもう少し悪くても、収束層が優先されて `serious` が選ばれる。収束フィルタは机上の
安全弁ではなく、6 データ中 1 つで既に発火している。

### 3. 順序依存の警告 (REQ-SAR-501) が実データで発火

T3 で `serious` と `adaptive` は **Rwp 差 0.361 と僅差なのに格子が 0.16% 違う**
(PbSO4 a 8.47385 vs 8.48749 / b 5.39410 vs 5.40278)。精密化された格子の esd はこれより
1-2 桁小さいので、この食い違いは数値誤差では説明できない = **設定依存**である。
探索の副産物として「答えの信頼度」が言えることの実例。
