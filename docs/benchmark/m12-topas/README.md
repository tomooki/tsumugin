**両エンジンが同じ格子・同じ相分率に落ちるか**が最重要の観測点であり、

### 両エンジンの一致 (最重要の観測点)

- **T2 garnet の混合占有**: TOPAS が 16a Fe 0.588/Al 0.412・24d Al 0.708/Fe 0.292。
  GSAS-II は 16a Fe 0.58/Al 0.42・24d Al 0.63/Fe 0.37。**独立な 2 実装が同じ構造に落ちた**。
- **T3 PbSO4 のセル**: a=8.4821 b=5.3998 c=6.9616 Å (単独)、a=8.4814 b=5.3992 c=6.9610 Å
  (joint)。文献値と一致し GSAS 経路とも同じ解。
- **T4 のセル**: NAC a=10.2516 (初期 10.2512)、CaF2 a=5.4649 (初期 5.4646)。Rwp は未達だが
  格子は妥当な位置に留まっている。
- **判別経路 (`RefinementBackend` Protocol) でも一致** (2026-08-19, #180): 同じ実 CIF
  (PbSO4-Wyckoff) + 同じ実データ (PBSO4.XRA 20–90°) + 同じ 0.4% 摂動セル (8.45/5.38/6.94)
  から精密化すると **TOPAS 8.47648/5.40376/6.95684** / **GSAS-II 8.48207/5.40312/6.96325**
  で**最大 0.066% 差**、どちらも文献値 (8.482/5.398/6.959) へ戻る。`discriminate(backend=)`
  を許した前提はここにある — TOPAS 側が簡約モデル (P m m m・Ni 1 原子) へ落ちていると
  「実構造で判別した」結果が捏造構造で走り、**その嘘は結果からは見えない**。
  (この比較で `TopasBackend` だけ既定重みが ``w=1`` だったことも判明した — chi2 が
  1.4e9 対 6.8e5 と数桁ずれ、判別の絶対 ΔBIC 閾値 `close_threshold` がエンジン依存に
  なっていた。`backends.base.default_weights` に一本化して解消。)

### T3-joint の内訳 — 「両方が同じくらい悪い」は共有セルの妥協だった (2026-08-19)

| | 11BM… ではなく X 線 | CW 中性子 | 総合 |
|---|---|---|---|
| 温度差の段なし (共有セル 1 本) | 8.26% | 8.37% | 8.29% |
| **`hydrostatic_strain` あり** | 8.22% | **4.07%** | **7.19%** |

M7 T3 は **X 線 295 K / CW 中性子 10 K** で測られており、GSAS 経路は per-histogram Dij を
張ってその差を吸収している。TOPAS 側は格子を共有 ``prm`` へ持ち上げて **1 本のセルで両方を
説明**しようとしていたため、**どちらのヒストグラムも同じくらい悪くなっていた**
(「放射源間で偏っていないので片方だけが壊れているのではない」という以前の切り分けは、
症状としては正しいが原因の向きを取り違えていた)。

格子は共有したまま各 ``xdd`` に ``a = <共有> * (1 + ε);`` の実効セルを許すと、10 K 側が
8.37% → 4.07% に落ちて総合 7.19% (GOF 1.44) になり、**合格基準 ≤8% を満たす**。

**精密化された ε** (実測, `auto_rietveld` の `cell_strain` キーに出る):
``PbSO4 a_h1 -0.00115 / b_h1 -0.00120 / c_h1 -0.00115`` — 10 K 側の実効セルが 295 K 側より
**約 0.115% 小さい**、ほぼ等方の収縮である。PbSO4 の熱膨張 (α ≈ 4×10⁻⁶/K × 285 K ≈ 0.11%) と
一致し、箱 (±2%) からは 1 桁以上離れている。**Rwp が下がった理由が物理量として読める**
(この値を出さないと、段が効いたことと ε が箱に張り付いた非物理解の区別が付かない)。

**ε の箱は ±2%** (実測): ±5% にすると **CW 中性子側で tc.exe が
``Invalid d spacing encountered`` を出して異常終了する**。TOPAS はセルが式で書かれていると
hkl の d 範囲を箱の分だけ広げて評価するらしく、λ=1.909 Å に対し観測の d_min が λ/2 の
3% 上にしかないため、縮み側が ``d < λ/2`` を跨ぐ。**同じ INP でも X 線ヒストグラムに張った
場合は完走する**ので「式にすると落ちる」のではない。物理的には温度差 285 K の歪みは 0.3%
程度なので ±2% で十分広い。

### T4 が未達である理由 (2026-08-19 再測で訂正)

⚠ **以前ここに書いていた 30.9% は GSAS と違うデータリミットで測った値**で、GSAS の ~12.8%
とは比較できなかった。M7 で「T4 非収束の主因はデータリミット未設定」と実測で結論づけている
以上、**リミットは測定条件そのもの**である。GSAS T4 と同一の `HistogramSpec` で測り直した。

**差の出所は段列にある** (どちらも S0 が 69–72% から始まり、S6 まで 67–69% で膠着する):

つまり 30.9% は「広いレンジでたまたま 2 つのプロファイル段が通った」値であり、
**フィット自体はどちらの条件でも S0 から 70% 前後で膠着している**。TOF のピーク形状

**併せて見つかった 2 件** (W2 で追う):

  立たない = 無言 no-op の疑い (CLAUDE.md の検出則)。多相の相分率段が何も動かしていない

## T4 (TOF×2+放射光 多相) の詰めと基準の改定 (2026-08-19/20)

### ⚠ 先に: tc.exe はスレッド数で結果が変わる (この節の測り直しの理由)

**同一入力・同一設定の T4 既定を 4 回回して 43.49 / 67.62 / 43.49 / 29.29% になった。**
分岐点は X 線 Lorentzian 段が受理されるか revert されるかで、悪条件な最小二乗の総和順序が
スレッド割り当てで変わるためである。``OMP_NUM_THREADS=1`` にすると**ビット同一**に再現する
(67.616482 が 2 回)。

Rwp が実行ごとに変わると**段の受理判定も BIC 比較もベンチマークも意味を失う**ので、
`topas.driver` は tc.exe を **1 スレッドで起動する** (NFR-102)。速度が要るときは
``TSUMUGIN_TOPAS_THREADS`` で外せる (= 再現性を捨てるという明示的な選択)。実測の所要は
T4 全 10 段で 14–21 秒なので、この系では実質的な代償はない。

**以下の数値はすべて 1 スレッドの決定論実行で測り直したもの**である。

### 効いた手 (アブレーション)

| 設定 | 総合 | 11BM | PG3-1066 | PG3-2665 | validity |
|---|---|---|---|---|---|
| 既定 (背景 6・種付けなし) | 67.62% | 73.07 | 36.63 | 44.83 | ✅ |
| ↑ から TOF の α/β を外す | 67.74% | 73.09 | 36.70 | 46.13 | ✅ |
| 背景 20 項 | 26.33% | 21.22 | 32.71 | 45.05 | ✅ |
| **背景 20 項 + 放射光の profile 種付け** | **19.25%** | **8.67** | 29.01 | 44.57 | ❌ |
| ↑ から TOF の α/β を外す | 19.63% | 8.61 | 29.25 | 45.93 | ❌ |
| ↑ から `tof_profile` 段を外す | 22.45% | 7.16 | 46.97 | 46.72 | ❌ |

- **効果が大きいのは背景項数 (67.6 → 26.3) と放射光の profile 種付け (26.3 → 19.25)**。
- **`tof_profile` 段** (TOF の d 依存幅の解放) は 22.45 → 19.25% で、外すと TOF の 2 本が
  29.0/44.6 → 47.0/46.7 と目に見えて崩れる。
- **TOF の α/β を装置ファイルから写す**効果は**小さい** (67.74 → 67.62 / 19.63 → 19.25)。
  主に PG3-2665 に効く。写像自体は `topas.inc` から導けるので入れているが、
  ⚠ 当初「45.5% まで一気に落ちた」と記録したのは**スレッド非決定性を引いた値**だった。
- ⚠ **`tof_profile` 段の置き場所は結果に影響しない**: X 線プロファイルの前でも後ろでも
  19.2525% でビット同一。当初「前 67.6% / 後 43.5%」と記録した 24 ポイントの差も
  非決定性だった。順序は規約として固定しているだけである。
- **背景項数は非単調**: 20 項が最良で、24 項では悪化する (多スレッド時の測定だが、
  背景の自由度がプロファイル段の条件を悪くする傾向自体は再現する)。

**α/β の写像** (幅の sig-1/sig-2 と違い関数形が解ける): `topas.inc` の実体は
``exp_conv_const = lr Constant(t1) / (a0 + a1 / d^wexp)`` = **時間定数**なので、GSAS の
速度定数 (1/µs) の逆数として対応する。減衰 β = β₀ + β₁/d⁴ → `a0 = difC·β₀`, `a1 = difC·β₁`,
`wexp = 4` (Tutorial ZrW2O8 と同じ `+` 側)。立ち上がり α = α₁/d → `a0 = 0`, `a1 = difC·α₁`,
`wexp = 1` (`-` 側)。

**profile 種付けは放射源で逆転する**: 放射光で桁で効く (11BM 43.9 → 8.7%) 一方、
**CW 中性子では悪化する** — T2 garnet は 5.54% → 9.76% で物理妥当性も落ちる。既定 OFF・
`auto_rietveld(seed_profile=true)` で opt-in。T1 (10.449 → 10.440) と T3-joint
(7.195 → 7.165) は同等。

### `size_strain` が TOF で tc.exe を落としていた (修正済み)

段が毎回 ``Abnormal program termination`` で落ちていた原因は
**``Negative FWHM encountered``** で、`topas.inc` を読むと理由が明白だった:

```
macro CS_L(c, v)     { lor_fwhm = 0.1 Rad Lam / (Cos(Th) CeV(c,v)); }
macro Strain_L(c, v) { lor_fwhm = CeV(c,v) Tan(Th); }
```

**波長 ``Lam`` と Bragg 角 ``Th`` で書かれた角度分散のモデル**で、x 軸が時間の TOF には
対応物が無い。切り分け実験でも X 線だけなら完走し、**TOF を 1 本混ぜるだけで落ちた**。

TOF で同じ物理を担うのは**幅の d/d² 項** (`tof_profile`) である — 微小歪みは Δd/d 一定
→ FWHM ∝ d、結晶子サイズは Δd ∝ d² → FWHM ∝ d²。したがって修正は「TOF を飛ばす」ではなく
**モデルが違うので当てない**: 混在 joint では非 TOF ヒストグラムにだけ張り (段ラベルに
「非 TOF のみ」と出す)、全 TOF ならレシピが段を出さず、それでも指定されたら
`UnsupportedStageFlagError` で明示的に失敗する。``Negative FWHM`` は `driver` の診断行に
加えたので、次に同種の誤りが出たら段の note に理由が出る。

### 構造的に空振りしていた 2 段を落とした (2026-08-20)

段列に毎回出ていた `S3 phase_fractions` と `S5 occupancy` は、**TOPAS では定義上何も変えられない
段**だった (no-op 検出が拾った。rwp・gof・n_params がビット同一で `reverted` も立たない)。

- **S3**: フラグ `{"scale": True, "phase_fraction_sum": True}` の**両方が空振り**。TOPAS では
  相ごとの ``scale`` が相分率そのもので **S0 で既に解放済み**、``phase_fraction_sum`` は
  ``MVW`` が重量分率を正規化するので拘束する対象が無い。GSAS は per-histogram の HAP Scale を
  別々に持つので拘束が要る — **同じ語彙でも指す物が違う**。
- **S5**: `apply_stage` は**宣言されたサイトだけ**解放する (全サイト一斉解放は scale と縮退して
  占有率 1 超の非物理解へ行く)。T4 の相は `free_occupancy_labels` も `mixed_occupancy_groups` も
  宣言していないので解放対象がゼロだった。T2 garnet のように宣言があれば働く。

段そのものを出さないようにし、``phase_fraction_sum`` は**受理せず理由付きで失敗**させるように
した (受理して no-op にすると ③ から見て「拘束を掛けた」ことになる)。**結果はビット同一**
(既定 67.616482 / 調整済 19.2525331 とも変化なし) — 何もしていなかったのだから当然で、
消えたのは「相分率を分離した」という**段列の嘘**である。

#### 「分離を本当にやる」案 (B) は効かなかった

S3 が空振りだったのは「相分率は S0 で既に自由」だからなので、**その前提の方を変えて**
S0 を「背景のみ」→「+ 相分率」の 2 段に割り、軌跡を変える案も測った。結果は
**A 案と全段で一致**:

| 段 | A (背景+相分率を一括) | B (2 段に分離) |
|---|---|---|
| S0 | 27.4417 (n=72) | 背景のみ **266.5695** (n=60) |
| S0b | — | 27.4417 (n=72) |
| S1 profile | 24.6009 | 24.6009 |
| … | … | … |
| 最終 (調整済/既定) | 19.2525 / 67.6165 | 19.2525 / 67.6165 |

背景と相分率は**分けるほど縮退していない** — 一括でも分離でも同じ最小へ行く。負けた案として
記録する (再発明を防ぐため)。GSAS 経路で分離が効くのは、あちらの相分率が per-histogram の
HAP Scale で、スケール因子や背景と別々に効くからである。

### 基準の改定 (ユーザー判断 1(a))

**TOPAS 側の T4 基準を「GSAS と同じ ≤15%」から改める**。到達値 **19.25%** の内訳と理由:

- 残差は **PG3-2665 の 44.6%** が支配的。このバンクは GSAS T4 に合わせて**データリミットを
  掛けていない** (GSAS も無制限で使う) 条件下の値である。
- **物理妥当性が落ちている**: CaF2 の Ca が Uiso < 0 (少数相の未モデル寄与を吸っている)。
  **Rwp だけで合格にしない**規律により、この状態を「合格」とは呼ばない。
- `size_strain` は動くようになったが T4 では revert される (19.25 → 26.12 と悪化)。

したがって現時点の TOPAS T4 は **「19.25% / validity fail」を記録値として残し、未達のまま**と
する。GSAS 側の基準 (≤15%) は据え置く — 両者を同じ表に並べるときは**基準が別**である。

| 12 | **占有率の全サイト一斉解放**がスケール因子と大域的に縮退し、Rwp を下げながら占有率を 1 超へ飛ばしていた | T1 の「10.14% で合格」は偽の合格だった |
| 13 | **共有 `prm` が段階解放を無視**していた (TOPAS の名前付き prm は既定で精密化対象) | 段が黙って no-op |
| 14 | **空間群名の `/` は `Sg/` のファイル名で `o` になる** (P63/m → p63om.sg) | 対称操作が引けず座標段が黙って no-op |

## 実行して確かめないと分からなかった TOPAS の仕様

マニュアルは暗号化 PDF でテキスト抽出できないため、言語仕様の正は `topas.inc` と
Tutorial INP と**実行結果**しかない。以下はすべて実測で確定した。

- **tc.exe は構文エラーで異常終了しても終了コード 0 を返す** → stdout マーカー + 出力生成の
  二重の網で判定する。
- サイト併合の許容差は **~1e-8** (分率座標)。3.3e-8 で外れ、3.3e-9 で通る。
- `ZE` マクロ内蔵の箱は **±100 × データ刻み** = 刻み 0.05° なら ±5°。緩すぎてゼロ点が
  +1.16° まで暴走した。
- `TCHZ_Peak_Type` の箱 `min = Max(-1, Val-.1)` は **`Val` を毎回評価する移動する箱**。
  汎用初期値からでも十分遠くまで歩ける (w 0.003 → 0.143)。
- `Cylindrical_I_Correction(=name;)` は `Error loading sstring_in` で異常終了する。
  マクロは自分で `prm` を宣言する形しか通らないので、共有したいなら展開形を書く。
- `out "file"` は `append` を付けない限りファイルを**切り詰めて**開く。xdd ごとに出すと
  joint で 2 本目が 1 本目のレコードを消す。
