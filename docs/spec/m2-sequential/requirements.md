# m2-sequential 要件定義書

## 概要

Tsumugin マイルストーン M2: **シーケンシャル解析基盤**を実装する。時系列 (時間/温度軸) の
フレーム列に対する warm-start 逐次精密化、changepoint 検出と近傍の局所木探索 (M1 再利用)、
相ライフサイクル追跡、トラジェクトリ出力を提供する。併せて **高温シーケンシャルモード**
(温度同期・熱膨張ベースライン・転移温度推定)、**ledger/snapshot の永続化** (追記専用ファイル)、
**最終選択 2 モード** (agent/human + エスカレーション + Review Queue 最小版) を実装する。

上位仕様: [docs/tsumugin_spec_v0.3.md](../../tsumugin_spec_v0.3.md) §7 (FR-300/320)・§8 (FR-402/403)・§13 M2。
M0/M1 資産 (StagedRefinementEngine / HypothesisTreeSearch / Ledger / SnapshotStore / evidence) の上に構築する。

## 機能要件（EARS記法）

**【信頼性レベル凡例】**: 🔵 仕様書・M0/M1 実装に依拠 / 🟡 妥当な推測で確定 (根拠記載) / 🔴 根拠なし推測

### 通常要件 — シーケンシャル基盤 (FR-300)

- REQ-001: システムはフレーム列 (2θ 共通グリッド + フレームごとの強度 + 軸値) に対する
  **逐次精密化**を実行し、フレームごとの精密化結果を時系列で返さなければならない 🔵 *FR-301/P5*
- REQ-002: 各フレームの精密化は**前フレームの確定 phases を warm start** として開始し、
  継承対象 (phases 全体 / scale のみ等) を設定で指定できなければならない 🔵 *FR-301*
- REQ-003: システムは **changepoint を複合指標** — (a) 残差時系列 (Rwp) の跳ね、(b) 格子定数の
  フレーム間微分、(c) 新規未マッチピーク数 — で検出しなければならない 🔵 *FR-303*
- REQ-004: システムは**相ライフサイクル** (birth_frame / death_frame / confidence) を追跡し、
  **ヒステリシス** (連続 N フレームの存在/不在で確定、既定 N=3) で点滅を抑制しなければならない 🔵 *FR-305 (N の既定値は 🟡)*
- REQ-005: システムは**トラジェクトリ** (フレーム軸値・相ごとの scale/wt_frac・格子±σ・Rwp/GOF・
  changepoint フラグ・ライフサイクル) を構造化データとして返し、**CSV へ書き出せなければならない**
  (stdlib csv。parquet は M2 スコープ外) 🔵 *FR-306 (CSV 限定は 🟡 interview Q3)*
- REQ-006: システムは **ExternalChannel** (kind=temperature 等, frame_index→value の同期写像) を
  データモデルに追加し、シーケンシャル解析でフレームへ紐付けられなければならない 🔵 *§4/FR-321*

### 通常要件 — 高温モード (FR-320)

- REQ-007: 温度チャネル同期時、システムは**格子定数-温度曲線の熱膨張ベースライン**を
  多項式 (既定 1 次) でフィットし、ベースラインからの逸脱を分離できなければならない 🔵 *FR-322 (次数既定は 🟡。Debye-Grüneisen は M-later)*
- REQ-008: システムは**相転移を検出**し、転移温度を **onset / midpoint ± σ** で推定しなければ
  ならない (相分率トラジェクトリのシグモイド遷移から推定) 🔵 *FR-323 (推定式は 🟡)*
- REQ-009: システムは等温セグメント・反応経路解析用の**外部委譲出口**として、トラジェクトリの
  CSV 出力 (REQ-005) を流用できることを保証すればよい (JMAK 解析等は非スコープ) 🔵 *FR-324/325*

### 通常要件 — 永続化 (P2/NFR-101/105)

- REQ-010: システムは Ledger を**追記専用 JSONL ファイル**へ永続化でき、プロセス再起動後に
  再オープンして (a) `verify()` が True、(b) 続きから追記可能、でなければならない 🔵 *NFR-105 (JSONL 形式は 🟡 interview Q4)*
- REQ-011: システムは SnapshotStore を同様に永続化でき、再オープン後に任意 snapshot_id へ
  revert できなければならない 🔵 *P2*
- REQ-012: 永続化ストアは **in-memory 実装と同一のインターフェース**を持ち、既存エンジン
  (StagedRefinementEngine / HypothesisTreeSearch) に無改変で注入できなければならない 🔵 *P7 踏襲*

### 通常要件 — 最終選択 2 モード (FR-402/403)

- REQ-013: システムは `final_selection_mode: agent | human` を持つ**最終選択エンジン**を提供し、
  仮説の `accepted` 化を単一の API 経由でのみ行わなければならない 🔵 *FR-402*
- REQ-014: 裁定は**根拠 (evidence 値・確率・僅差競合・未知相フラグ) 付きで ledger に記録**され、
  `accepted_by: agent|human` が仮説に記録されなければならない 🔵 *FR-402*
- REQ-015: システムは**エスカレーション条件** — (a) 全仮説高 R、(b) 未知相フラグ、(c) 僅差競合
  (ΔBIC < 閾値)、(d) ガード 3 連続発動 (escalated report) — を検出し、**Review Queue** (追記型)
  へ通知しなければならない。**処理はブロックしない** (暫定裁定 + 要確認フラグ) 🔵 *FR-403*

### 条件付き要件

- REQ-101: changepoint が検出された場合、システムは**当該フレーム近傍のみ** M1 の
  `HypothesisTreeSearch` による**局所木探索**を実行し、相構成の変化 (新相候補) を評価
  しなければならない。非 changepoint フレームでは木探索を行わない 🔵 *FR-303/304*
- REQ-102: `agent` モードでは、最良仮説が僅差競合なし・未知相フラグなしのとき、システムは
  **自動で accepted 化**しなければならない。僅差競合等のエスカレーション条件下では
  暫定裁定 + Review Queue 通知としなければならない 🔵 *FR-402/403*
- REQ-103: `human` モードでは、システムは推奨順位と根拠の提示のみ行い、accepted 化は
  **human の明示的 API 呼び出しでのみ**行われなければならない 🔵 *FR-402*
- REQ-104: モードは実行中いつでも切替可能で、切替は ledger に記録されなければならない 🔵 *FR-402*
- REQ-105: シーケンシャル実行エンジンは**オーケストレーション方式の選択インターフェース**
  (independent: 独自 warm-start 逐次 / native: GSAS-II sequential) を持たなければならない。
  M2 の実装は independent のみとし、native は未実装エラーでよい 🔵 *FR-302 (実装範囲は 🟡)*

### 状態要件

- REQ-201: 相が death 判定された後、ヒステリシス窓内に再出現した場合は death を取り消し
  連続とみなさなければならない (点滅抑制) 🔵 *FR-305*
- REQ-202: accepted 仮説が差し戻された場合、status は `superseded` へ遷移し、履歴 (旧裁定) は
  ledger に保持されなければならない (削除しない) 🔵 *FR-402/P2 (status 遷移の詳細は 🟡)*

### 制約要件

- REQ-401: 永続化ストアにも削除・上書き・改変 API を実装してはならない (追記 + revert のみ) 🔵 *P2/NFR-101*
- REQ-402: 同一入力・同一設定でシーケンシャル解析の全出力はビット同一でなければならない 🔵 *NFR-102*
- REQ-403: 非探索区間 (changepoint なしフレーム) の処理は 10 秒/フレーム以内を目標とする
  (M2 では SimulatedBackend の合成 100 フレームで smoke 検証) 🔵 *NFR-103 (検証方法は 🟡)*
- REQ-404: データモデル拡張 (`Hypothesis.frame_range` / `PhaseInstance.lifecycle` /
  `ExternalChannel`) は**既存 API 後方互換の非破壊追加** (既定値付きフィールド) でなければ
  ならない 🔵 *§4 / note.md 差分表*

## 非機能要件

- NFR-001: 合成 100 フレームのシーケンシャルテストが 60 秒以内 (CI 実用性) 🟡
- NFR-201: 永続 ledger は再オープン検証込みで `verify()` True (NFR-105 の実装保証) 🔵
- NFR-202: 乱数不使用・安定ソートの決定論 (NFR-102) 🔵
- NFR-203: 永続化ファイルの書き込みは追記モード (`"a"`) のみ。既存バイト列を書き換えない 🔵 *P2*

## Edgeケース

### エラー処理

- EDGE-001: 空のフレーム列 → 空トラジェクトリを返す (例外なし) 🔵 *M0/M1 の縮退規約踏襲*
- EDGE-002: あるフレームの精密化が失敗 (chi2=inf) → 当該フレームを警告付きで記録し、
  次フレームは**最後に成功したフレームの phases** から warm start して続行 🟡 *EDGE-004 踏襲*
- EDGE-003: 永続 ledger ファイルが破損 (ハッシュ不整合) → 再オープン時に `verify()` False を
  検出し明示エラー。**ファイルを修復・上書きしない** 🔵 *P2/NFR-105*
- EDGE-004: agent モードで裁定対象仮説がゼロ → accept せずエスカレーションのみ 🟡

### 境界値

- EDGE-101: 単一フレームのシーケンス → 単発解析と等価な結果 + 長さ 1 のトラジェクトリ 🔵
- EDGE-102: 温度チャネルに欠損 (フレーム数と不一致) → 欠損フレームの軸値は None とし警告
  (例外にしない) 🟡
- EDGE-103: 全フレームが changepoint 判定 → 全フレームで局所木探索が走っても完走する 🟡
- EDGE-104: changepoint ゼロ → 木探索は一度も呼ばれない (呼び出し回数で検証) 🔵 *REQ-101*

## M2 スコープ外 (明示)

- operando 電池モード (FR-310 系: 電気化学同期・吸収補正・固溶体判別) — M3
- IC ペナルティ付き区間自動分割 (FR-316) — M3 (FR-323 は M2 では転移点推定のみ)
- GSAS-II ネイティブ sequential の実装 (インターフェースのみ、REQ-105)
- Review Queue の Web UI 表示 (FR-421 モバイルカード等) — キューのデータ構造と API のみ
- マルチスタート (FR-230)、parquet 出力、Debye-Grüneisen ベースライン
