## 自律確定した論点

### Q1: 作業規模

**カテゴリ**: スコープ
**確定**: フル機能開発
**根拠**: M1 は仕様のコアマイルストーン (多仮説主義 P1 の実装)。仕様書に FR 番号付きの
詳細要件が既にあり、EARS 化のコストに見合う。🔵

### Q2: Web UI 最小版の範囲と技術スタック

**カテゴリ**: 未定義部分詳細化
**確定**: FastAPI + uvicorn (optional extra `web`) で読み取り専用の結果閲覧
(ランキング・メトリクス・確率・未知相フラグ)。同梱静的 HTML 1 枚 + JSON API。
localhost バインド既定。仮説の accept/revert 操作 UI は M2 (FR-402/421) に委譲。
**根拠**: 仕様は「Web UI最小版」とのみ記載 🟡。閲覧系 FR-421/422 の M2 配置から、
M1 は read-only が妥当と推測。スタックは Python 単体で完結し依存が軽いものを推奨案として採用。

### Q3: 既存コードベースの詳細分析

**カテゴリ**: 既存設計確認
**確定**: 不要 (note.md の収集で充足)
**根拠**: M0 は本セッションで実装したばかりで、tasknote (note.md) に API 署名まで整理済み。🔵

### Q4: 候補相の供給方法

**カテゴリ**: 入出力定義
**確定**: `Sequence[PhaseInstance]` (または相候補メタの薄いラッパ) を API 引数で受領。
相ライブラリ (FR-100 系: COD/ICSD 取り込み・重複排除・hull フィルタ) は M1 スコープ外。
**根拠**: §13 の M1 定義に FR-100 は含まれない 🔵。木探索の入力界面のみ先に確定 🟡。

### Q5: 観測ピーク検出の実装

**カテゴリ**: 技術選定
**確定**: numpy による自前実装 (局所極大 + プロミネンス閾値)。scipy には依存しない
(scipy は gsas extra のみで、コア依存は numpy に保つ)。
**根拠**: CLAUDE.md の依存最小方針から推測 🟡。

### Q6: .gpx 書き出しの実装経路

**カテゴリ**: 技術選定
**確定**: GSASIIBackend の gpx 生成経路 (M0 実装の一時 gpx) を永続化 API
`export_gpx(...)` として公開。GSAS-II 未導入時は `GSASUnavailableError`。
テストは `@pytest.mark.gsas`。
**根拠**: M0 の GSASIIBackend 設計と FR-505 🔵。

### Q7: 探索モード精密化の設定

**カテゴリ**: 未定義部分詳細化
**確定**: scale + 格子のみ解放・max_cycles 小 (既定 5)・ガードレール有効。
段階テンプレートのフル実行 (profile 以降) は生存仮説の最終検証時のみ。
**根拠**: FR-113「保守的設定の制約付き精密化」 🔵、サイクル数の具体値は推測 🟡。

### Q8: FR-112 動的枝刈り閾値の「変曲点」実装

**カテゴリ**: アルゴリズム詳細
**確定**: スコア降順の累積分布に対する最大曲率点 (二階差分最大) で閾値を決定。
候補が少数 (<4) の場合は枝刈りなし。
**根拠**: 仕様は「累積分布の変曲点」とのみ記載 🔵、実装式は推測 🟡。
