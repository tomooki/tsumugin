## エピック1: 多仮説木探索

### ストーリー 1.1: 相組合せの自動同定 🔵

**信頼性**: 🔵 *仕様 §1.1 目的・FR-110*

**私は** 粉末回折の研究者 **として**
**観測パターンと候補相リストを与えるだけで、妥当な相組合せ仮説を全て列挙・ランキングしてほしい**
**そうすることで** 単一解の思い込みによる誤同定を避け、曖昧さを定量的に把握できる

**関連要件**: REQ-001, REQ-003, REQ-004

**詳細シナリオ**:
1. 観測パターン (2θ, I) と候補相 (数〜数百) を `search_hypotheses()` に渡す
2. システムがピークマッチング → 枝刈り → 探索モード精密化 → BIC 評価の木探索を実行
3. `RankedHypothesis` のタプル (確率・僅差競合フラグ付き) が返る

**前提条件**: 候補相は PhaseInstance 形式で供給済み (相ライブラリは M-later)
**優先度**: Must Have

### ストーリー 1.2: 計算コストの制御 🔵

**信頼性**: 🔵 *FR-111/112/115*

**私は** 解析パイプラインの運用者 **として**
**見込みのない相組合せを早期に枝刈りしてほしい**
**そうすることで** 候補数が多くても現実的な時間で解析が終わる

**関連要件**: REQ-101, REQ-102, REQ-401
**詳細シナリオ**:
1. マッチングスコアの累積分布から枝刈り閾値が動的に決まる
2. スコア不足の相はノード展開されず、理由が ledger に残る
3. R 改善 2% 未満の枝は打ち切り、最大 5 相で停止

**優先度**: Must Have

---

### ストーリー 1.3: 等構造相の縮約と代替解の保持 🔵

**信頼性**: 🔵 *FR-114/116*

**私は** 研究者 **として**
**等構造の候補 (例: 同型の類縁組成) は代表 1 つに縮約しつつ、代替候補も見えるようにしてほしい**
**そうすることで** 探索が高速になり、かつ「実は別の類縁相かもしれない」可能性を見落とさない

**関連要件**: REQ-103, REQ-104
**優先度**: Must Have

---

### ストーリー 1.4: 未知相の明示 🔵

**信頼性**: 🔵 *FR-117/§14「候補DBに正解相が無い誤誘導」緩和*

**私は** 研究者 **として**
**どの仮説でも説明できない残差ピークを構造化された形で提示してほしい**
**そうすることで** 未知相の存在に気づき、ab initio 解析等の外部手段に引き渡せる

**関連要件**: REQ-005, REQ-106
**優先度**: Must Have

## エピック2: 相互運用 (.gpx)

### ストーリー 2.1: GSAS-II GUI への引き渡し 🔵

**信頼性**: 🔵 *FR-505*

**私は** GSAS-II に習熟した研究者 **として**
**自動解析の任意の結果を .gpx として保存し GSAS-II GUI で開きたい**
**そうすることで** 自動解析を出発点に、手動での詳細検討へシームレスに移行できる

**関連要件**: REQ-006, REQ-105
**優先度**: Must Have

## エピック3: 結果閲覧 (Web UI 最小版)

### ストーリー 3.1: 解析結果のブラウザ閲覧 🟡

**信頼性**: 🟡 *§13「Web UI最小版」から read-only 閲覧と推測*

**私は** 研究者 **として**
**解析結果 (仮説ランキング・R値・確率・未知相フラグ) をブラウザで一覧したい**
**そうすることで** ターミナルに不慣れでも結果を確認・共有できる

**関連要件**: REQ-007, REQ-301, NFR-101
**詳細シナリオ**:
1. `tsumugin.webui.serve(result)` (または CLI) でローカルサーバ起動
2. ブラウザで localhost を開くとランキングテーブルと詳細が表示される
3. 表示のみで、accept 等の操作はできない (M2 で FR-402/421)

**優先度**: Should Have
