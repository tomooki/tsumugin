## REQ-001/003/004: 多仮説木探索の基本動作 🔵

### Given
- SimulatedBackend で生成した合成パターン (真の構成: 2 相 A+B)
- 候補相: A, B, C, D (C, D はピーク位置が合わない)

### When
- `search_hypotheses(two_theta, intensity, candidates)` を実行

### Then
- 真の構成 {A,B} を含む仮説が最上位ランクになる
- 各 refined 仮説の metrics.evidence に "bic" キーが存在する
- 仮説の parent_id が探索木の系譜を成す

### テストケース

- [ ] **TC-001-01**: 2 相合成データ・4 候補で {A,B} が 1 位 🔵
- [ ] **TC-001-02**: 1 相合成データ・3 候補で {A} が 1 位、余剰相追加仮説は R 改善 2% 未満で
      打ち切られている (ledger に prune 記録) 🔵
- [ ] **TC-001-03**: 全 refined 仮説に evidence("bic") が付与される 🔵
- [ ] **TC-001-04**: 子仮説の parent_id が親 ID と一致する 🔵
- [ ] **TC-001-05** (決定論): 同一入力で 2 回実行し、ランキング・確率がビット同一 🔵 *REQ-403*

## REQ-002/101: ピークマッチングと動的枝刈り 🔵
