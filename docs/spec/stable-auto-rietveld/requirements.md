# 安定自動 Rietveld — 要件 (stable-auto-rietveld)

**位置づけ**: `tsumugin.autorietveld` の段階解放エンジンを「**収束安定性最優先**」の自動解析
アルゴリズムへ作り直す。M7 で確立した適応レシピ (`recipe.build_recipe`) は各データに手で
合わせ込んだ結果であり、**データが変わると壊れる**ことが 2026-07-27 の実測で判明したため。

**前提 (ユーザー判断, 2026-07-27)**:
> 自動リートベルト解析ソフトなので、**安定性が最優先で多少の解析時間は無視できます
> (Operando 以外)**。したがって、収束安定性の高いレシピを規定にする意義は大きいです。

したがって本作業は**計算時間を安定性と引き換えに支払う**方針を採る。operando (`tsumugin.insitu`)
のみ従来の軽量レシピを既定に残す。

---

## 背景 — なぜ作り直すか (実測された事実)

### F1. 単一の段順序で全データを満たすことはできない

試料変位段の配置を 4 通り実測した結果 (実 GSAS):

| 変位段の配置 | T1 | T3 (PbSO4 joint) | T4 (NAC+CaF2) | CaTeO3 |
|---|---|---|---|---|
| cell と同段 (M7 既定) | ✓ 9.83% | ✓ 6.66% | ✓ ~12.8% | ✓ 12.43% |
| cell → …構造段… → displacement (末尾) | ✓ | ✗ 14.38% + 格子発散 | ✓ | ✓ |
| cell → displacement (直後) | ✓ | ✓ | ✗ 17.53% | ✓ |
| cell → displacement(格子凍結) → cell | ✓ | ✗ 14.38% | ✓ | ✓ |

**どの配置でも 4 ベンチマーク全部は通らない。** T3 は変位を遅らせると壊れ、T4 は早めると壊れる。
→ 順序を*当てる*のではなく、**探索して測る**しかない (REQ-SAR-500)。

### F2. 相関するパラメータ群を割ると壊れる

Caglioti の U, V, W は独立の knob ではなく **1 つの物理量の係数**である:

  FWHM² = U·tan²θ + V·tan θ + W

「W 単独 → 凍結 → U 単独 → 凍結 → V 単独」にすると **U 段と V 段が両方 revert** し、以降
Lorentzian も効かず頭打ちになる (CaTeO3 18.07%)。W から**足していく** (W → W,U → W,U,V) と
12.19% まで落ちる。

### F3. 「超丁寧な順次解放/凍結」は既定レシピを上回る

15 手順 (順次解放/凍結 2 周 → 累積 → 全開放, 59 段) の実測:

| | チュートリアル | M7 既定 | 本気 (U,V,W 単独) | 本気 (U,V,W 累積) |
|---|---|---|---|---|
| T1 fluoroapatite | 10.38% | 9.83% | **9.69%** | 10.45% |
| T3 PbSO4 joint | 6.71% | 6.66% | **6.02%** | 6.10% |
| CaTeO3 frame030 | 9.4% | 12.43% | 18.07% | **12.19%** |
| T4 NAC+CaF2 | 6.83% | ~12.8% | 未測定 | 未測定 |

**T3 は段の並べ替えでは 14.38% 止まりだったのに、本気フィットで 6.02%** = チュートリアル値を
大きく下回った。順次解放/凍結という**手順の質**が効いている。

### F4. engine のフラグは累積 (enable のみ) だった

`engine._apply_stage` は解放しかせず、段を分けても前段の解放が残る。つまり
「cell 段 → displacement 段」は実質 `cell` → `cell+displacement` であり、**段を分けただけでは
相関は一切切れていなかった**。凍結機構が要る。

### F5. GSAS-II の restraint は既定 headless 経路で非機能 (ただし回避可能)

`GSASIIstrMath.errRefine` 5203 行:

```python
if len(pVals) and dlg:            # ← dlg = wx プログレスダイアログ
    Nobs += len(pVals)
    M = np.concatenate((M, np.sqrt(pWt)*pVals))   # penalty を残差へ足すのはここだけ
Histograms['RestraintSum'] = pSum  # ← 報告はゲートの外 (効いているように見える)
```

一方 `dervRefine` (4807-4810) と `HessRefine` (4935-4939) は**ゲートされていない**。
→ headless では **目的関数は拘束を見ないのに勾配/Hessian だけが引っ張られる**不整合な最適化。
Issue #112 で実測した「小飽和摂動・target-invariant」の正体。

**回避口**: `G2strMain.Refine(GPXfile, dlg=…)` は公開パラメータ。`G2Project.refine()` が
渡していないだけなので、duck-typed スタブを渡せば有効化できる。
⚠ ただし `GSASIIstrMain` 430 行 `if dlg: break  # refining interactively` により、
**特異行列時の自動パラメータ削除+再試行を失う**。

## 設計原則

### P-SAR-1. 箱拘束は「装置・幾何」に限る — 構造パラメータは拘束しない

**構造パラメータ (占有率・Uiso・座標) の異常値は「モデルの誤り」を示唆する情報である。**
クランプするとこの診断信号を握り潰す。

実証: NaCuHCF の model5 は Na2/O1 が **Na>1 / O<0 に発散したこと自体が「Ow が要る」証拠**で、
ΔBIC + 物理妥当性ゲートがそれを拾って model6 を選んだ。占有率を [0,1] に箱拘束していれば
model5 は「一見まとも」になり判別できなかった。

| 対象 | 方針 |
|---|---|
| 格子 (初期値 ±X%)・試料変位・Size/Mustrain の正値性 | **箱拘束する** (発散は数値的事故で情報ではない) |
| **占有率・Uiso・座標** | **拘束しない。逸脱を検出して報告する** |
| やむを得ず数値上限が要る場合 | **物理的必要値を十分上回る**値にし、**境界到達自体を所見として報告** |

最後の項は実測教訓による: 低い cap は境界不安定を生み「偽の"改善せず"」を作る
(NaCuHCF: ADP cap を上げたら ND 18.0→14.7%)。

### P-SAR-2. 検出できない失敗を作らない

段が「何もしていない」「収束していない」を**検出して報告する**。Rwp が動かないことを
「改善しなかった」と解釈してはならない — silent failure と区別が付かない。

### P-SAR-3. 提案 ≠ 適用

除外領域の自動検出など、**解析の解釈を変える操作は提案に留め**、適用は人間/③ の承認を要する。
未知相のピークをアーチファクトとして消すと相同定を殺す。

### P-SAR-4. 決定論 (NFR-102)

探索を導入しても、候補の列挙・実行順・選択はすべて seed 固定でビット同一に再現できること。

## 要件

### 診断層

| ID | 要件 |
|---|---|
| REQ-SAR-101 | 段の受理判定に **`Rvals['Max shft/sig']` による収束判定**を加える。未収束なら追加サイクルで再実行し、それでも収束しなければ revert する |
| REQ-SAR-102 | 段の適用後、`n_params` が増えず rwp/gof が**ビット同一**なら「no-op 段」として警告を記録する (silent failure のクラス検出) |
| REQ-SAR-103 | `esd > \|値\|` のパラメータを検出し**自動的に凍結**する。凍結した変数と理由を ledger に残す |
| REQ-SAR-104 | 共分散行列から **\|r\| > 閾値 の高相関ペアを検出**し、同時解放を避ける (片方を凍結)。閾値は設定可能 |
| REQ-SAR-105 | 上記の情報源 (`Rvals` / `covMatrix` / `varyList` / `sig`) を読む**共通の読み出し層**を numpy-only で提供する |

### 拘束・境界

| ID | 要件 |
|---|---|
| REQ-SAR-201 | 装置・幾何パラメータに**箱拘束** (`parmMin`/`parmMax`) を張る。**構造パラメータには張らない** (P-SAR-1) |
| REQ-SAR-202 | 箱の**境界に到達した**ことを検出し所見として報告する (握り潰さない) |
| REQ-SAR-203 | restraint を `dlg` スタブ経由で有効化できるようにする。**既定は OFF**。有効時は REQ-SAR-103 の自動プルーニングが必須前提 (GSAS 側の自動削除を失うため) |
| REQ-SAR-204 | restraint が実際に χ² に寄与することを**対照実験で検証**するテストを持つ (Issue #112 のカナリアを意味反転して書き直す) |

### レシピ規則

| ID | 要件 |
|---|---|
| REQ-SAR-301 | **相関群の分割禁止**: {U,V,W} / {X,Y} / {Size,Mustrain} / {Shift,Transparency} / 格子。段は群を丸ごと足せるが、群の一部だけを解放してはならない |
| REQ-SAR-302 | 段のフラグに**凍結**を表現できる (`freeze_others`)。既定の累積セマンティクスは非回帰で維持する |
| REQ-SAR-303 | 座標/占有率の「重原子から順」解放を、**実際の元素数に応じて engine 側で展開**する (固定ランク数の no-op 段を作らない) |
| REQ-SAR-304 | 周回の入口で**その時点の最良状態へ戻す** |
| REQ-SAR-305 | Uiso 等値拘束を**段階的に緩める** (全原子 → 元素ごと → 個別) 選択肢を持つ |

### データ前処理の自動化

| ID | 要件 |
|---|---|
| REQ-SAR-401 | 背景項数を自動エスカレーション (6→12→24…) し、改善が止まったら確定する |
| REQ-SAR-402 | データレンジ (`two_theta_limits`) を自動決定する。ノイズ支配域が最小二乗を支配する問題 (T4 の非収束主因) への対処 |
| REQ-SAR-403 | 除外領域候補を**提案する** (自動適用しない, P-SAR-3) |
| REQ-SAR-404 | Le Bail (格子固定・プロファイル+背景のみ) で「**到達可能 Rwp**」を算出し、構造モデルの説明力の基準線として報告する |

### 探索

| ID | 要件 |
|---|---|
| REQ-SAR-500 | 複数のレシピ候補を実行し、**収束判定を満たすもののうち最良**を採用する。単一順序に賭けない (F1) |
| REQ-SAR-501 | 候補間で結果が割れた場合、「**順序依存 = 信頼度が低い**」という警告を出す |
| REQ-SAR-502 | operando 経路 (`tsumugin.insitu`) は従来の軽量レシピを既定に維持する (時間予算がある唯一の経路) |
