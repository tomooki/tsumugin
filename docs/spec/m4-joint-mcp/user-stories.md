## エピック1: 中性子・マルチヒストグラム joint 精密化

### ストーリー 1.1: X線と中性子の同時フィット 🔵
**信頼性**: 🔵 *FR-242/§12-6 joint ベンチ*

**私は** Ni/Fe/Mn 系電極を精密化する研究者 **として**
**X線と中性子のヒストグラムを同一構造モデルで同時フィットしたい**
**そうすることで** 単一線源では分離できない占有率を、散乱コントラストで精度良く決められる

**関連要件**: REQ-003, REQ-004, REQ-005, REQ-006 / **優先度**: Must Have

### ストーリー 1.2: TOF マルチバンクの取り込み 🔵
**信頼性**: 🔵 *FR-241*

**私は** TOF 中性子回折の利用者 **として**
**バンクごとの instprm・DIFC/DIFA/ZERO を管理した上でヒストグラムを取り込みたい**
**そうすることで** マルチバンク TOF データを正しく joint 精密化に載せられる

**関連要件**: REQ-001, REQ-002 / **優先度**: Must Have

### ストーリー 1.3: ヒストグラム重みの制御 🔵
**信頼性**: 🔵 *FR-243*

**私は** データ品質が異なる複数線源を扱う研究者 **として**
**既定は統計重み、必要なら経験重み (信頼度) でヒストの寄与を調整したい**
**そうすることで** 低品質ヒストが構造解を歪めるのを防げる

**関連要件**: REQ-008, REQ-009, REQ-301 / **優先度**: Should Have

### ストーリー 1.4: コントラストに基づく占有率解放の推奨 🔵
**信頼性**: 🔵 *FR-244*

**私は** 混合席占有を疑う研究者 **として**
**X線/中性子コントラストが十分なサイトを自動検出し、joint データがあるときだけ占有率解放を提案してほしい**
**そうすることで** 解放して意味のあるサイトだけを戦略に追加でき、過剰パラメータ化を避けられる

**関連要件**: REQ-010, REQ-011, REQ-012, REQ-104 / **優先度**: Must Have

### ストーリー 1.5: 探索は軽く、検証は厚く 🔵
**信頼性**: 🔵 *FR-245*

**私は** 計算コストを気にする研究者 **として**
**木探索はプライマリヒストグラム 1 本で回し、生き残った仮説だけを joint で検証してほしい**
**そうすることで** joint の高コストを最終検証に集中でき、探索が破綻しない

**関連要件**: REQ-013, REQ-014, REQ-202 / **優先度**: Must Have

## エピック2: ChemPlausibility プラグイン境界

### ストーリー 2.1: 化学的にありえない相の降格 🔵
**信頼性**: 🔵 *FR-412/P1 Dara 教訓*

**私は** 自動同定の妥当性を担保したい研究者 **として**
**合成文脈 (元素系・雰囲気・温度履歴・電気化学窓) から化学的妥当性をスコア化し、順位に反映してほしい**
**そうすることで** 大気下の単体アルカリ金属のような非現実的な相が上位に来にくくなる

**関連要件**: REQ-015, REQ-016, REQ-017 / **優先度**: Must Have

### ストーリー 2.2: 降格はしても除外はしない 🔵
**信頼性**: 🔵 *FR-412 (Dara 教訓・最重要不変条件)*

**私は** 見落としを恐れる研究者 **として**
**低スコアの相を降格はしても候補から消さないでほしい**
**そうすることで** 化学直感が外れていた場合でも真の相を取りこぼさない (Dara の失敗を繰り返さない)

**関連要件**: REQ-019, EDGE-005 / **優先度**: Must Have

### ストーリー 2.3: 複数の妥当性モジュールの合成 🔵
**信頼性**: 🔵 *FR-412*

**私は** 複数の予測器 (ルール / 熱力学 / LLM 判断) を併用したい研究者 **として**
**各モジュールのスコアを重み付き幾何平均で合成してほしい**
**そうすることで** 外部予測モジュールを同一インターフェースで後付けし、根拠を統合できる

**関連要件**: REQ-018, REQ-105, EDGE-006, EDGE-007 / **優先度**: Should Have

## エピック3: MCP Server

### ストーリー 3.1: エージェントからの解析投入と閲覧 🔵
**信頼性**: 🔵 *FR-513*

**私は** AI エージェント / 外部ツールの開発者 **として**
**MCP 経由で解析投入・仮説一覧・仮説比較・トラジェクトリ取得・gpx 書き出しを呼びたい**
**そうすることで** Tsumugin を標準プロトコルで自動化ワークフローに組み込める

**関連要件**: REQ-021, REQ-022 / **優先度**: Must Have

### ストーリー 3.2: MCP 経由でも壊さない・改変しない 🔵
**信頼性**: 🔵 *FR-513/P2/FR-402*

**私は** 監査可能性を重視する運用者 **として**
**MCP の accept/revert が追記型で、final_selection_mode を同一適用し、破壊的操作を一切持たないことを保証してほしい**
**そうすることで** エージェントに解析を任せても履歴が改変されず、human モードでは人間裁定が守られる

**関連要件**: REQ-023, REQ-024, REQ-025, REQ-106, REQ-201, REQ-405 / **優先度**: Must Have

### ストーリー 3.3: MEM は将来だが受け口は今 🔵
**信頼性**: 🔵 *FR-513/FR-600系 M5 委譲*

**私は** 将来 MEM を使う予定の研究者 **として**
**run_mem ツールの受け口を今用意しつつ、未実装は明示エラーで安全に返してほしい**
**そうすることで** M5 で MEM が入っても MCP クライアント側の接続を変えずに済む

**関連要件**: REQ-101, EDGE-008 / **優先度**: Should Have

### ストーリー 3.4: SDK 非依存でも動く安心感 🔵
**信頼性**: 🟡 *設計裁量 (optional extra 方式)*

**私は** MCP SDK を入れていない環境の開発者 **として**
**MCP サーバ起動は friendly error になっても、ツール実処理関数は通常どおり呼べてほしい**
**そうすることで** SDK 未導入でもコア解析とテストが動き、段階的に MCP を導入できる

**関連要件**: REQ-102, EDGE-009, REQ-403 / **優先度**: Should Have
