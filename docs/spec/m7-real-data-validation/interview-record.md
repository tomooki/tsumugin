## 意思決定と根拠

### D1: 作業規模 = フル機能開発

**背景**: M7 はマイルストーン規模 (実構造 Rietveld コア新設 + 4 例検証 + 成果物 2 種)。
**判断**: フル機能開発。要件・受け入れ基準を網羅。
**信頼性**: 🔵 PLAN §5 のフェーズ計画・成果物定義より。

### D2: 実構造精密化は新経路として実装 (既存 GSASIIBackend は温存)

**背景**: 現行 `GSASIIBackend` は P m m m + Ni ダミー構造で `scale`/`lattice.*` のみ精密化する
M0/M1 の格子同定用。`PhaseInstance` モデルは原子座標を持たず、実構造をそのまま表現できない。
**判断**: M7 は「実 CIF/相ファイル + データ + instprm を入力に GSAS-II を直接駆動する自動 Rietveld
経路」を新モジュールとして追加する。既存バックエンド (格子同定・相同定 M6) は破壊しない (P2)。
**信頼性**: 🔵 src/tsumugin/backends/gsasii.py と model.py の確認より。

### D3: 段階解放レシピは T1–T4 手順の一般化

**背景**: 4 チュートリアルの手順は共通の骨格 (scale+背景 → 格子+幾何補正 → プロファイル →
座標 → Uiso → 占有率/相分率) を持ち、幾何・温度差・多相で分岐する。
**判断**: 普遍系列 + ジオメトリ/温度/多相アダプタとして設計 (PLAN §4)。Rwp 悪化時 revert は
既存 FR-202 を実構造精密化にも適用。
**信頼性**: 🔵 各チュートリアル手順 (WebFetch 要約) より。

### D4: 検証データは docs/benchmark/testdata/m7/ に取得済み・gitignore 慣例踏襲

**背景**: 既存 benchmark データは容量/ライセンスで gitignore。
**判断**: M7 データも同ディレクトリ配下に取得し、取得手順を README に記録。テストは未取得時 skip。
**信頼性**: 🔵 docs/benchmark/README.md の既存慣例より。

### D5: 合格基準はチュートリアル値 + 許容マージン

**背景**: DFT 由来 CIF の格子ズレ・自動化の制約でチュートリアル完全一致は困難。
**判断**: 各例でチュートリアル Rwp/GOF + 妥当マージン (NFR-101〜104) を合格線とし、物理的妥当性
(格子・Uiso・占有率・制約充足) を必須とする。
**信頼性**: 🔵 PLAN §2 合格基準。
