## Overview

Tsumugin — 粉末回折の多仮説・全自動 Rietveld 解析プラットフォーム。
バックエンドは GSAS-II (`GSASIIscriptable`) を想定するが、コアは `RefinementBackend`
抽象で分離し、GSAS-II 非導入環境でも `SimulatedBackend` で全パイプラインを検証できる。
本コンテキストは **M0 (PoC) + M1 (多仮説木探索) + M2 (シーケンシャル解析) + M3 (operando 解析)** スコープ。仕様は [docs/tsumugin_spec_v0.3.md](../tsumugin_spec_v0.3.md)。

## Coding Conventions

### Naming

| Target | Convention | Example |
|--------|-----------|---------|
| Variables/Functions | snake_case | `refine_stage`, `wt_frac` |
| Classes/Types | PascalCase | `RefinementBackend`, `PhaseInstance` |
| Files/Modules | snake_case | `staged.py`, `guardrails.py` |
| Constants | UPPER_SNAKE | `DEFAULT_STAGE_TEMPLATE` |

### Data Modeling
- `dataclasses` を基本とする。バックエンド境界は `typing.Protocol` で定義（🔵 spec P7）。
- 不変性を優先: モデルの更新は新インスタンス生成 + Snapshot 追記（🔵 spec P2）。

### Error Handling
- ドメイン例外は `tsumugin.errors` に集約（`TsumuginError` 基底）。
- ガードレール発動は例外を投げず結果オブジェクト(`GuardOutcome`)で表現し ledger 記録（🔵 FR-214）。

### Non-negotiable Invariants (spec 由来)
- **P2 / NFR-101**: 破壊的操作の API を実装しない。全状態は追記 + Snapshot で revert 可能。
- **NFR-105**: ledger は追記専用 + ハッシュチェーン。
- **NFR-102**: 乱数種固定で再現性（ビット同一を目標）。
- **FR-412 教訓**: スコアは降格のみ、候補の除外はしない（M0 では evidence ランキングに反映のみ）。

## Additional Notes

- GSAS-II 2.0 導入済み。方式: ソースツリー (C:\Users\tomoo\G2) + venv の `gsas2-source.pth` +
  ビルド済みバイナリ (~/.GSASII/GSASII-bin/win_64_p3.12_n2.2、buildtools リリース由来)。
  import は `from GSASII import GSASIIscriptable` (パッケージ形式)。
  ランタイム依存は `uv sync --extra gsas`（プレーンな `uv sync` は extra を外すので注意）。
- `GSASIIBackend` は refine (scale=HAP相分率 / lattice.*=Cell) と simulate (noise-free Ycalc) を実装済み。
  profile 以降の suffix は M2+ で拡張。
- 既知の無害な警告: `~/.GSASII/config.ini` (ユーザーの既存ファイル、cp932) を GSAS-II が UTF-8 で
  読めず起動時に "Error reading {cfgfile}" を出すが動作に影響なし (upstream の表示バグ含む)。
- M1 実装済み: 多仮説木探索 (`tsumugin.search`)、`.gpx` 書き出し (`tsumugin.export`)、
  read-only Web UI (`tsumugin.webui`、optional extra `web`)。
- M2 実装済み: 時系列フレーム列の逐次精密化 (`tsumugin.sequential`: changepoint 検出・
  lifecycle・転移温度推定・trajectory/CSV)、agent/human 2 モードの最終選択とエスカレーション
  (`tsumugin.selection`)、JSONL 永続化 (`tsumugin.store` の `PersistentLedger` /
  `PersistentSnapshotStore`、追記専用・再オープン時にハッシュチェーン再検証)。
- M3 実装済み: 電池 operando 解析。echem CSV の frame 同期 + 容量→組成 x 換算 (`tsumugin.operando`
  の `read_echem_csv`/`EchemData`)、セル固定相プリセット (`CELL_PHASE_PRESETS`、scale のみ解放)、
  Evidence (BIC) の IC 区間分割 (`segment_series`)、区間ごとの固溶体/二相判別 (`discriminate_interval`、
  端点マルチスタート必須・僅差/高 R は `undecided` でエスカレーション)、trajectory + echem の
  結合出力 CSV (`combined_csv`)/ヒステリシス、摂動マルチスタート大域最適化 (`tsumugin.multistart`)、
  透過配置の吸収補正 (`tsumugin.absorption`、A = exp(-μt/cosθ))。公開 API は `from tsumugin import
  MultistartEngine, segment_series, discriminate_interval, read_echem_csv, combined_csv, ...` で
  トップレベル公開 (M0/M1/M2 の公開面は非破壊維持 = REQ-404)。
- M3 以降スコープ外（M4+）: joint refinement、MCP、MEM、nested sampling、REST、OED、永続化 DB (RDB)。
