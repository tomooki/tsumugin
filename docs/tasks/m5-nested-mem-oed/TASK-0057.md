## タスク概要
M4 の `run_mem` MCP 委譲境界 (`mcp/mem.py::run_mem_boundary`, プレースホルダ) を MEMBackend 委譲へ実体化する
(D8)。**M4 placeholder 契約を後方互換維持** (REQ-033)。
- `run_mem_boundary(session, *, placeholder=False, mem_backend: MEMBackend | None = None, hypothesis_id=None,
  frame_index=None, **params) -> dict` へ `mem_backend` を**末尾・既定 None で非破壊追加**する。
  - **後方互換** (REQ-033): `placeholder=True` は M4 の
    `{"status":"not_implemented","milestone":"M5","tool":"run_mem"}` を返す (契約不変)。
  - **MEMBackend 委譲** (REQ-034/EDGE-013): mem_backend 供給時は `build_mem_input`→`mem_backend.run` で密度マップ
    パス・断面・最小密度・警告を**素の型 dict** で返す。子スナップショット追記のみで破壊操作なし (P2/NFR-101)。
    非有限値は既存 `_json.finite_or_none` で純化し `json.dumps(allow_nan=False)` 安全にする (TC-511-04)。
  - **未導入** (REQ-104/EDGE-006): `MEMUnavailableError` を捕捉し `{"status":"error","error":"mem_unavailable"}`
    へ変換 (クラッシュ・破壊操作なし)。M4 の export_gpx→GSASUnavailableError→error dict 変換パターンと対称。
- `mcp/tools.py`: 既存 `run_mem` ツール実処理を `run_mem_boundary` へ委譲する接続を実体化 (M4 では
  MEMUnavailable/placeholder を返すだけだった経路を MEMBackend 供給時に実行へ)。`MCP_TOOLS` レジストリ・
  8 ツール構成は不変 (run_mem の中身のみ実体化)。

**このタスクのみが `mcp/mem.py` / `mcp/tools.py` を編集** (M4 後方互換ホットスポットの隔離)。トップレベル
`__all__` (AnalysisSession/create_mcp_server) は不変。
