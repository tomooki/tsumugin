## タスク概要
`nested/arbitration.py` に木探索 bic 固定・僅差競合のみ nested 再裁定の 2 段構え裁定を新設する (D4)。
- `ArbitrationConfig` frozen dataclass (full_nested=False / close_threshold=10.0 / temperature=1.0)。
  既定は 2 段構え、full_nested=True で全生存仮説を nested 裁定 (REQ-012/EDGE-004)、close_threshold は既存
  `rank` と共有 (ΔBIC<10, REQ-011)。
- `ArbitratedHypothesis` frozen dataclass (ranked: RankedHypothesis / adjudicated_by: bic|nested|laplace /
  logz_err)。裁定に用いた backend を明示 (REQ-013/015)。
- `ArbitrationResult` frozen dataclass (arbitrated (evidence 昇順) / nested_ids (昇順) / primary_backend="bic"
  / warnings)。
- `arbitrate(hypotheses, *, problems=None, nested=None, config=ArbitrationConfig(), ledger=None)`:
  1. **一次**: `evidence.ranking.rank` (BICBackend) で順位・確率・close_competitor を得る。木探索/枝刈りは bic
     のまま・nested で書き換えない (探索段不変, REQ-010/201)。
  2. **再裁定対象抽出**: close_competitor=True (ΔBIC<10) 群のみ nested 対象。full_nested=True なら全生存仮説
     (REQ-011/012/EDGE-004)。
  3. **nested 再裁定**: 対象 ID の `EvidenceProblem` を problems から引き `nested.run_with_fallback` で value=-logZ
     を得て evidence を差し替え、統合ランキングを再構成 (確率再計算)。
  4. **僅差なし** (REQ-102/EDGE-003): close_competitor が無い/problems・nested 未供給なら nested 発動せず bic
     一次を最終結果 (下段スキップ)。
  5. **記録** (REQ-013): どの仮説を bic 一次確定・どの競合を nested 再裁定したかを理由付きで
     `ledger.append("arbitration", {...})` に追記 (NFR-105)。決定論: 仮説 ID 昇順で処理 (REQ-402)。

final_selection_mode=human では accepted 化せず推奨提示に留める (TC-513-01/REQ-203/D10。裁定は評価のみで
既存 FinalSelectionEngine の人間操作経路を新設しない)。`nested/__init__.py` で re-export。
