### (1) OED レイヤ (D9・非破壊・提案のみ)
- `oed/proposal.py`: `MeasurementKind` Literal (high_statistics_remeasure / additional_temperature_point /
  neutron_for_joint / composition_analysis)。`OEDProposal` frozen dataclass (kind / target_hypothesis_ids
  (昇順) / rationale / estimated_information_gain / parameters)。
  `propose_measurements(ranked, *, close_threshold=10.0, ledger=None) -> tuple[OEDProposal, ...]` — rank の
  `close_competitor` (ΔBIC/ΔlogZ<閾値) が存在するときのみ判別測定提案を `estimated_information_gain` 降順で
  生成。僅差競合が無ければ**空 tuple** (状態変更なし, REQ-038/EDGE-010)。**非破壊**: accepted/rejected 化・
  データ改変を伴わず、ledger 非 None のとき `ledger.append("oed_proposal", {...})` 追記記録のみ (REQ-037/P2)。
  決定論: 対象仮説 ID 昇順・(利得降順, kind 昇順) 安定順で固定 (REQ-402)。
  `proposals_to_json(proposals) -> list[dict]` — 情報利得順・非有限は finite_or_none 純化。
- `oed/pyboed.py`: `acquire(proposals, *, config=None) -> tuple[OEDProposal, ...]` — pyboed を**遅延 import**
  (実行時のみ)。未導入なら `OEDUnavailableError` を送出。propose_measurements (v1 スコープ) は本境界に非依存で
  動作 (REQ-036/105/EDGE-011)。
