## タスク概要
`nested/calibration.py` に reliability diagram / ECE による確率較正評価を新設する。**bic と nested を別系列で
評価**する (§12-5)。本タスクは evidence 値・nested サンプラに**非依存** (予測確率入力のみ) で独立実装可能。
- `CalibrationSample` frozen dataclass (predicted_probability / correct / backend="bic")。backend フィールドで
  bic/nested 系列分離キーとする (REQ-016/106/EDGE-012)。
- `ReliabilityBin` frozen dataclass (lower / upper / mean_predicted / observed_frequency / count)。
- `CalibrationReport` frozen dataclass (backend / bins (下端昇順) / ece / n_samples / probability_semantics)。
  backend 名 + 確率の意味 (BIC 近似 vs logZ) を明記 (REQ-015/NFR-004)。
- `reliability_diagram(samples, *, n_bins=10) -> tuple[ReliabilityBin, ...]`: [0,1] を n_bins 等分し下端昇順で
  返す。空ビンは count=0 で保持 (ビン順固定, 決定論, REQ-017/402)。
- `expected_calibration_error(samples, *, n_bins=10) -> float`: ECE = Σ (count_b/N)·|acc_b − conf_b| を決定論的
  に計算 (REQ-016/017)。
- `calibrate_by_backend(samples, *, n_bins=10) -> tuple[CalibrationReport, ...]`: samples を backend でグルーピング
  し各系列に CalibrationReport を生成。返す tuple は backend 名昇順で決定論化。nested 系列があれば別 report と
  して分離出力 (EDGE-012)。

確率較正の温度較正パラメータ (softmax temperature) は既存 `rank` の temperature を再利用する (REQ-014。確率
出力そのものは rank 側・本タスクは較正評価ユーティリティ)。確率出力に用いた evidence backend 名をレポートに
含める (REQ-015)。`nested/__init__.py` で re-export。
