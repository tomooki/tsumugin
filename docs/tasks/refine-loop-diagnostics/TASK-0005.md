## タスク概要

`src/tsumugin/refine_loop/diagnostics.py` の `propose_next_actions` に、背景プロファイルの過剰な
wiggle (極値過多 = overfit) を検出したときの**背景係数の減項**提案を追加する (REQ-104)。現行は
低周波系統背景残差 → **増項** (`AdjustBackground(n+step)`) のみだが、これに**減項** (`AdjustBackground(n-step)`)
を加える。`AdjustBackground` は既に `n_coeffs` を任意に取れる (`dataclasses.replace(inp,
background_coeffs=n)`) ため Action 側の変更は不要 (最小)。増項規則 (背景不足) と減項規則 (背景 overfit)
は独立トリガで両立させ、既存の増項提案を非回帰にする。減項が下限 (`background_min`) を下回らないよう
ガードする。

## 実装詳細（項目ごと 🔵 + 実装ファイルパス + Python コード例）

### 1. AdjustBackground は既存のまま減項可 🔵
**信頼性**: 🔵 *action.py `AdjustBackground.apply` = dataclasses.replace(inp, background_coeffs=n)*

`AdjustBackground(n_coeffs)` は `background_coeffs=n_coeffs` に置換するだけなので、`n < 現在値` を
渡せば減項になる。**Action 側のコード変更は不要** (最小)。
**実装ファイル (参照)**: `src/tsumugin/refine_loop/action.py`

### 2. propose_next_actions に背景 overfit → 減項規則を追加 (REQ-104) 🔵
**信頼性**: 🔵 *interfaces.py REQ-104 節 / dataflow.md S4 (C4) / GAP 表B*

`propose_next_actions` に `bg_extrema_tol` (既定 例 8) と `background_min` (既定 例 3) 引数を追加し、
極値過多 + 下限余地のとき減項を提案する。既存の増項規則とは別トリガで両立させる。
**実装ファイル**: `src/tsumugin/refine_loop/diagnostics.py`

```python
# 背景プロファイルの過剰な wiggle(極値過多) → 背景係数の減項 (REQ-104, 増項と両立)
if f.bg_extrema_count > bg_extrema_tol and f.n_background_coeffs > background_min:
    new_n = max(f.n_background_coeffs - background_step, background_min)
    proposals.append(
        ActionProposal(
            action=AdjustBackground(new_n),
            rationale=f"hist{f.hist_id}: 背景極値 {f.bg_extrema_count} 過多(overfit) "
            f"→ 背景 {f.n_background_coeffs}→{new_n} 項に減項を試行",
            priority=float(f.bg_extrema_count),
            evidence={"signal": "background_overfit", "bg_extrema_count": f.bg_extrema_count,
                      "hist_id": f.hist_id, "direction": "decrease"},
            safe=True,
        )
    )
```

- 既存の増項規則 (`low_freq_bg_residual > bg_residual_tol and n_background_coeffs < background_max`)
  はそのまま残す。増項/減項は独立トリガのため通常は同時発火しない (背景不足 vs 背景過剰)。
- `new_n = max(..., background_min)` で下限を割らない (下限ガード)。
- 末尾ソートキー (`(not p.safe, -p.priority, type(p.action).__name__)`) は不変 (REQ-402)。

### TC-104-01: 背景 overfit で減項提案 🔵
**Given** `bg_extrema_count > tol` かつ `n_background_coeffs`(例 12) `> background_min` の
`ResidualFeatures`。
**When** `propose_next_actions(result, features)` を呼ぶ。
**Then** `AdjustBackground(減らした項数)` の減項提案が含まれ (`evidence["direction"] == "decrease"`)、
`proposal.safe is True`。減項後の項数 < 元の項数。

### TC-104-02: 背景不足では従来どおり増項 (非回帰) 🔵
**Given** `low_freq_bg_residual > tol` かつ `n_background_coeffs`(例 6) `< background_max`、
`bg_extrema_count = 0` の feature。
**When** 提案を得る。
**Then** 従来どおり `AdjustBackground(増やした項数)` の増項提案が出て、減項提案は出ない (非回帰)。

### TC-104-B01: 下限ガード 🔵
**Given** `bg_extrema_count > tol` かつ `n_background_coeffs` が `background_min` に近い
(例 min=3, coeffs=4, step=3) feature。
**When** 提案を得る。
**Then** 減項後の項数が `background_min`(=3) を下回らない (=3 に飽和)。`n_background_coeffs <=
background_min` のときは減項提案自体を出さない。

## 注意事項（numpy コア/GSAS 遅延/frozen 非破壊/決定論 NFR-102/材料固有結論を焼き込まない REQ-405）
- numpy コア + GSAS 遅延: `diagnostics.py` は numpy のみ。`bg_extrema_count` の算出は runner
  (GSAS 側) / diagnose_residual (TASK-0002) が担い、本規則は値を消費するだけ。
- frozen 非破壊: `ActionProposal`/`AdjustBackground` は frozen のまま。`apply` は
  `dataclasses.replace` の純変換。上書き API を足さない (P2)。
- 決定論 (NFR-102/REQ-402): 末尾ソートキーは不変。乱数なし。同一入力でビット同一。
- 材料固有結論を焼き込まない (REQ-405): 「この試料は N 項が最適」等は結論せず、増項/減項の**候補**を
  出すだけ。採否は try→revert (`_accept` = Rwp 改善 ∧ validity 維持) が決める。
