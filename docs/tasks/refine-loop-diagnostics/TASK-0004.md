## タスク概要

`src/tsumugin/refine_loop/diagnostics.py` の `propose_next_actions` に 2 つの診断規則を追加する。
(1) 系統的な obs>calc のピーク強度 (`intensity_bias`) を検出したら**選択配向**
(`preferred_orientation`) 解放を提案 (REQ-102)。(2) ピーク幅の系統ずれ (`fwhm_ratio`) を検出したら、
Gaussian (U,V,W)・Lorentzian (X,Y)・size/mustrain を**束ねず 3 つの別々の `ReleaseParams` 候補**として
列挙する (REQ-103)。従来は幅ずれで `size_strain` のみを 1 提案していたが、これを **3 候補に拡張/置換**し、
どの幅成分が効くかは結論を焼き込まず policy が個別に試して `_accept` が採否を決める (DD-2/REQ-405)。
順序は既存どおり決定論 (REQ-402)。

## 実装詳細（項目ごと 🔵 + 実装ファイルパス + Python コード例）

### 1. 選択配向 (PO) 提案 (REQ-102) 🔵
**信頼性**: 🔵 *interfaces.py REQ-102 節 / dataflow.md「診断シグナル→トライ候補」S2*

`propose_next_actions` の `for f in features:` ループ内に、系統 obs>calc 検出規則を足す。
`intensity_bias_tol` 引数 (既定 0.1 程度) を追加する。
**実装ファイル**: `src/tsumugin/refine_loop/diagnostics.py`

```python
# 系統的な obs>calc のピーク強度 → 選択配向(PO)解放 (REQ-102)
if f.intensity_bias > intensity_bias_tol:
    proposals.append(
        ActionProposal(
            action=ReleaseParams("po", {"preferred_orientation": 4}),
            rationale=f"hist{f.hist_id}: 系統 obs>calc 強度 {f.intensity_bias:.2f} "
            f"→ 選択配向(preferred_orientation)解放を試行",
            priority=float(f.intensity_bias),
            evidence={"signal": "intensity_bias", "intensity_bias": f.intensity_bias,
                      "hist_id": f.hist_id},
            safe=True,
        )
    )
```

### 2. ピーク幅を U,V,W / X,Y / size に別々の候補で列挙 (REQ-103) 🔵
**信頼性**: 🔵 *interfaces.py REQ-103 節 / dataflow.md S3 (C3a/C3b/C3c) / DD-2*

既存の「`fwhm_ratio` ずれ → `size_strain` のみ」提案を、**3 つの別々の候補**に置換/拡張する。
Gaussian 幅 (U,V,W)・Lorentzian 幅 (X,Y)・size/mustrain を独立に列挙し、どれが効くかは焼き込まない。
**実装ファイル**: `src/tsumugin/refine_loop/diagnostics.py`

```python
# obs/calc FWHM 比の系統ずれ → Gaussian(U,V,W) / Lorentzian(X,Y) / size を「別々の候補」で列挙 (REQ-103, DD-2)
if abs(f.fwhm_ratio - 1.0) > fwhm_tol:
    prio = float(abs(f.fwhm_ratio - 1.0))
    for label, flags, note in (
        ("uvw", {"profile": ["U", "V", "W"]}, "Gaussian 幅(U,V,W)"),
        ("xy", {"profile_lorentzian": True}, "Lorentzian 幅(X,Y)"),
        ("size", {"size_strain": True}, "結晶子サイズ/微小歪み"),
    ):
        proposals.append(
            ActionProposal(
                action=ReleaseParams(label, flags),
                rationale=f"hist{f.hist_id}: obs/calc FWHM 比 {f.fwhm_ratio:.2f} → {note} 解放を試行 "
                f"(別候補; 採否は try→revert)",
                priority=prio,
                evidence={"signal": "fwhm", "kind": label, "fwhm_ratio": f.fwhm_ratio,
                          "hist_id": f.hist_id},
                safe=True,
            )
        )
```

- これは既存の `ReleaseParams("size_strain", {"size_strain": True})` 単独提案を**置換/拡張**する。
  `size` 候補として同等物 (`{"size_strain": True}`) を残すので機能後退はない。
- 3 候補は同 priority のため末尾ソートで安定に並ぶ (両者 `ReleaseParams`、列挙順を保つ安定ソート)。
- 末尾ソートキー (`(not p.safe, -p.priority, type(p.action).__name__)`) は不変 (REQ-402)。

### TC-102-01: 系統 obs>calc で PO 提案 🔵
**Given** `intensity_bias > tol` の `ResidualFeatures`。
**When** `propose_next_actions(result, features)` を呼ぶ。

`intensity_bias <= tol` では出ない。

### TC-103-01: 幅ずれで U,V,W・X,Y・size の 3 別提案 🔵
**Given** `|fwhm_ratio - 1.0| > tol` の feature。
**When** 提案を得る。
**Then** `ReleaseParams("uvw", {"profile": ["U","V","W"]})` / `ReleaseParams("xy",
{"profile_lorentzian": True})` / `ReleaseParams("size", {"size_strain": True})` の **3 候補**が
別々に含まれる。すべて `proposal.safe is True`。幅ずれなしでは 3 候補とも出ない。

### TC-103-02: 決定論順序 + 非回帰 🔵
**Given** 同一の feature 列 (幅ずれ + PO を含む)。
**When** `propose_next_actions` を 2 回呼ぶ。
**Then** 提案順序がビット同一 (REQ-402)。既存の背景/未指数/validity/非対称(TASK-0003) 提案は非回帰。

## 注意事項（numpy コア/GSAS 遅延/frozen 非破壊/決定論 NFR-102/材料固有結論を焼き込まない REQ-405）
- numpy コア + GSAS 遅延: `diagnostics.py` は numpy のみ。`intensity_bias`/`fwhm_ratio` の算出は
  runner (GSAS 側) / diagnose_residual (TASK-0002) が担い、本規則は値を消費するだけ。
- frozen 非破壊: `ResidualFeatures`/`ActionProposal` は frozen のまま。新提案は追記のみ。
- 決定論 (NFR-102/REQ-402): 末尾ソートキーは不変。乱数なし。同一入力でビット同一。
- 材料固有結論を焼き込まない (REQ-405 / DD-2): どの幅成分 (U,V,W か X,Y か size) が効くかは
  結論せず 3 候補を列挙し、採否は try→revert (`_accept`) が決める。
