## タスク概要

`src/tsumugin/refine_loop/orchestrator.py` の `run_refinement_loop` の **既定 diagnose** を、従来の
`_default_diagnose`（背景シグナルのみ）から `diagnose_residual`（TASK-0002 で新設した拡張診断）へ
差し替え、拡張診断規則をループに結線する統合タスク。

核心の `_accept`（Rwp 改善 ∧ validity 維持）・`RuleBasedPolicy`・ループ制御は **不変**。
`RuleBasedPolicy` は SafeAction の増加（`RestrictUiso`/`SetAbsorption`/新 `ReleaseParams`）を型で
自動吸収するため変更不要である点を確認する。`ModelAction`（`SetLimits` 等）は従来どおり
`open_proposals` へ送られる（自律適用しない, REQ-403/404）。統合後の決定論・非回帰を確認する。

## 注意事項（numpy コア/GSAS 遅延/決定論 NFR-102/台帳 verify True NFR-105）

- **numpy コア / GSAS 遅延**: `orchestrator`/`diagnose_residual`/`policy`/`action` は numpy のみ。
  GSAS は runner 内で遅延 import（REQ-401）。統合テストは runner スタブ注入で GSAS 非依存に green。
- **決定論（NFR-102 / REQ-402）**: 乱数なし。提案順序は safe 優先→優先度降順→型名昇順で安定ソート
  （既存踏襲）。同一入力・種でビット同一。
- **台帳（NFR-105）**: ledger は追記専用・ハッシュチェーン。`verify()` が常に True。上書き/削除しない
  （P2 非破壊）。
- **`_accept` 不変（REQ-201）**: 差し替えは既定 diagnose の一点に限定し、accept/revert エンジン・
  ループ制御・policy のロジックは改変しない。EDGE-002（既解放/既試行の再選択なしで終了保証）を維持。
- **材料固有結論の非焼き込み（REQ-405）**: 統合後も診断規則は汎用 try→observe 形を保つ。
