## タスク概要

新モジュール `src/tsumugin/refine_loop/model_compare.py` を新設する。構造モデル変種
（`compare.ModelVariant` 列）を runner で精密化し、既存の `autorietveld.compare.compare_models`
に委譲して BIC + 物理妥当性で序列化し、ledger に各変種評価を追記する **薄い上位オーケストレータ**。

単一モデル調律ループ（`orchestrator.run_refinement_loop`）の **外側** に位置する第3層コンポーネント
（DD-6）。`compare_models` は既に「妥当なうち最小 BIC を best・`best_is_valid`・`delta_bic`」を実装
済みのため、本タスクは (1) 変種の精密化ドライブ、(2) `compare_models` への委譲、(3) best 変種の相
tuple の取り出し、(4) ledger 追記の 4 点を薄く束ねるのみ。裁定ロジック自体は再実装しない。

### 実装項目

- 🔵 **`ModelCompareResult`（frozen dataclass）**: `comparison`（`compare.ModelComparison`：scores/
  best/best_is_valid/delta_bic を保持）、`best_phases`（best 変種の相 `tuple[PhaseSpec, ...]`：継続
  精密化用）、`ledger`（`object | None = None`）。
- 🔵 **`run_model_comparison`**: `histograms`, `variants` を受け、`runner`（None なら
  `run_auto_rietveld`）で各変種を精密化し `compare_models` に委譲。best 変種の phases を返す。
- 🔵 **best_phases の取り出し**: `comparison.best`（best 変種）が指す `ModelVariant.phases` を tuple 化。
- 🔵 **ledger 追記**: `ledger` があれば各変種の `{name, bic, validity}` を追記し、`verify()` True を保つ
  （P2 非破壊・追記専用 NFR-105）。
- 🔵 **フォールバック（REQ-202/EDGE-101）**: 妥当なうち最小 BIC を best、妥当皆無なら全体最小へ
  フォールバック（`best_is_valid=False`）。この判定は `compare_models` 側に既に実装済みのため委譲する。
- 🔵 **runner 未指定の遅延 import**: `run_auto_rietveld` は既定 runner。GSAS は runner 内で遅延 import
  され、コアは numpy のみ（REQ-401）。

### Python コード例

```python
"""refine_loop モデル比較オーケストレータ (REQ-005/202)。"""
from __future__ import annotations

from dataclasses import dataclass
from typing import Sequence

from tsumugin.autorietveld.compare import ModelComparison, ModelVariant, compare_models
from tsumugin.autorietveld.model import HistogramSpec, PhaseSpec


@dataclass(frozen=True)
class ModelCompareResult:
    """モデル比較の結果 (compare.ModelComparison + best 相 + ledger)。"""

    comparison: ModelComparison
    best_phases: tuple[PhaseSpec, ...]
    ledger: object | None = None


def run_model_comparison(
    histograms: Sequence[HistogramSpec],
    variants: Sequence[ModelVariant],
    *,
    runner: object | None = None,
    ledger: object | None = None,
    **run_kwargs: object,
) -> ModelCompareResult:
    """変種を精密化し compare_models で BIC+妥当性裁定 + ledger 追記する薄い上位。

    単一モデル調律ループ (run_refinement_loop) の外側 (DD-6)。妥当なうち最小 BIC を best、
    妥当皆無なら全体最小へフォールバック (best_is_valid=False, EDGE-101)。ledger verify True。
    """
    if runner is None:
        from tsumugin.autorietveld.engine import run_auto_rietveld

        runner = run_auto_rietveld

    comparison = compare_models(
        histograms, variants, runner=runner, **run_kwargs
    )  # 裁定は compare_models に委譲 (best/best_is_valid/delta_bic)

    best_phases = tuple(comparison.best.phases)

    if ledger is not None:
        for score in comparison.scores:  # 各変種 {name, bic, validity} を追記
            ledger = ledger.append(
                {"name": score.name, "bic": score.bic, "validity": score.validity}
            )
        assert ledger.verify()  # NFR-105 ハッシュチェーン

    return ModelCompareResult(
        comparison=comparison, best_phases=best_phases, ledger=ledger
    )
```

> 注: `compare_models` / `ModelVariant` / `ModelComparison` の実 API シグネチャ・属性名
> （`scores`/`best`/`best_is_valid`/`delta_bic`・変種の `phases`/`name`/`validity`）は
> `src/tsumugin/autorietveld/compare.py` を実装時に確認し合わせること。ledger の追記 API 名
> （`append`/`add` 等）も既存 `tsumugin.store` に合わせる。

## 注意事項（numpy コア/GSAS 遅延/決定論 NFR-102/台帳 verify True NFR-105）

- **numpy コア / GSAS 遅延**: `model_compare` は numpy のみに依存。`run_auto_rietveld`（GSAS 駆動）は
  runner 未指定時にのみ関数内で遅延 import する（REQ-401）。テストは常に runner スタブ注入で GSAS 非依存。
- **決定論（NFR-102）**: 乱数を使わない。同一入力・種でビット同一。`compare_models` の決定論性に依存し、
  変種の反復順序も入力順を保つ。
- **台帳（NFR-105）**: ledger は追記専用・ハッシュチェーン。上書き/削除 API を使わない。追記後
  `verify()` が常に True であること（P2 非破壊）。
- **裁定の非再実装**: best/best_is_valid/フォールバックの判定は `compare_models` に既に実装済み。
  本モジュールで再実装せず委譲する（薄い上位に徹する, DD-6）。
