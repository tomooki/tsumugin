## 目的

P2 (hold-out での 1 回だけの評価) の前に、**評価に効くものを全部決めて、ハッシュで固定する**。

- 調整してよいのは開発用のデータだけ: 合成 `S-dev`・未公開の開発用実測データ・開発に使ってよい公開チュートリアル (P0 §3.1)。
  (準) hold-out・RRUFF の測定パターンは使わない (`tests/test_holdout_guard.py`)。
- 凍結の成果物は **凍結 manifest** (各ファイルの sha256 と、従う P0 の版の commit)。P0 §0 の表の項目を 1 つも欠かさない。
- **⚠ §8-6**: このフェーズで初めて開発用の実データでテンプレートを走らせる。**それ以後に P0 の数・規則を変えると、結果は in-sample と表示される**。
  P0 で直したいところが見つかったら、テンプレートを実データで走らせる前 (段階 1 の間) に出す。

## 先に分かっている危険

- **参照構造に esd が無いかもしれない**: COD の AMCSD 由来の項目 (ID が 9 で始まる) は座標の esd を持たない (P0 §3.2.1-1 G3)。
  U10 の文献が COD に AMCSD 由来の形でしか無ければ、その事例は σ_ref が無く `unevaluated` になる (第 2 候補へ進む規則は「独立でない」
  ときだけなので、esd の欠如では進まない)。段階 3 で分かる。分かった時点で報告する (規則の変更は P0 の版上げ)。
- **スナップショットの置き場所 (2026-10-15 に解消)**: RRUFF/COD のスナップショットは一時フォルダ (以前のセッションの scratchpad) にしか
  無かった。ユーザーの決定で `Documents/tsumugin-holdout-data/snapshot-2026-10-13/` (リポジトリの外) へ移し、3 ファイルとも P0 §3.2.1-1 の
  sha256 と一致することを確かめた。候補スクリプトは入力の sha256 を照合してから走る。

## 調整で分かったこと (段階 2)

- **GSAS-II は 4 桁の特殊位置を特殊位置と認めない** (2026-10-15 実測): P6₃mc で ``SytSym([0.3333, 0.6667, 0])`` が
  多重度 6 の ``m(110)`` を返す (正しくは 2b・多重度 2)。5 桁以上なら正しい。COD の CIF は 1/3 を 0.3333 と書くことが多く、
  原子が 3 重のまま Rwp 6.4% で完走する (対称で固定の軸の esd が 0.7・4.5、GII 0.51 で結晶化学が全アームで fail)。
  S-dev は生成器で厳密な特殊位置へ射影して直した。**既存の GSAS 経路も同じ穴を持つ** — `H-pub` は COD の CIF を使うので
  P2 の前に直す必要がある (別タスクに切り出した。凍結の前提)。`topas.symmetry` の docstring にある「GSAS-II は特殊位置を
  拘束として扱うので問題にならない」は 4 桁の入力では誤り。
- ~~基準経路の単発 (`B-single`) が欠陥の無い対照で「未収束」になる~~ — **撤回**: 上の特殊位置の誤り (原子が 3 重) の産物だった。
  厳密な特殊位置に直すと `B-single` も収束する (事後検査の max |shift|/esd 0.03)。
- **結晶化学検査の結合原子価 (GII) が正しい構造を fail にした**: pymatgen 同梱の元素パラメータの推定 (O'Keeffe–Brese, b=0.31) が
  Zn–O の R0 を約 0.1 Å 過小に見積もり、正しい wurtzite ZnO で GII 0.51 (閾値 0.3)。ユーザーの決定 (2026-10-15) で
  **Brown の対ごとの表 bvparm2020.cif** (IUCr, sha256 `ec073207…`, リポジトリの外 `~/.tsumugin/` か `TSUMUGIN_BVPARM`) に替えた
  (crystal-chemistry/2)。同じ ZnO で GII 0.006。表に無い対は unevaluated、表が無ければ従来の推定 (witness に method)。
  取得: IUCr のページが bot 確認を返すので内蔵ブラウザで取得し、ブラウザ内で計算した sha256 と一致を確かめた。

- **相集合の証人の窓が刻みより細くなっていた** (residual-window/4): 実験室の細いピーク (FWHM 0.05° / 刻み 0.02°) では
  窓の両側の帯が 2 点を持てず、窓が 1 つも作れなかった → unevaluated → 全値を止めていた (Kα2 比のずれ・選択配向の S-dev)。
  分解されているピークだけ窓を 4.2 刻みまで広げた (境界を格子点に置かず、帯の端が 0.9·w に届く 4 ≤ k ≤ 4.44)。
- **陰イオン同士の結合 (パイライトの S₂)** は結合原子価の模型の適用範囲外 → GII を理由付きで unevaluated に (正しい構造を
  fail にしない)。ただし unevaluated の必須検査は値を止めるので、パイライト型の値は止まったまま (理由が正直になっただけ)。
- **S-dev の forsterite の真値が化学的におかしかった** (COD 1572966: Si–O 1.48 Å・GII 0.50) — 検査器は正しかった。
  S-dev の構造の規則に「凍結版の検査器で fail が無いこと」を足し、1572968 に替えた。
- **H-pub の候補数**: 14 (参照あり)。P0 v1.5 (PR #252, U15) で参照なしの事例 (`H-pub-noref`) で K = 30 まで補う。
  `candidates.py --include-noref` で母集団を作った (2026-10-15、ユーザー承認後に CIF を取得): **参照なしの候補 738**
  (自由座標 3 未満で 128 を除く。取得の失敗・版の不一致は 0)。`K_noref = 30 − 14 = 16` の 3 倍 (48) を超えるので K は下げない。
  `H-priv` は当初どおり 6 件以上。
- 未解決 (S-dev の再実行の後で見る): 異方的な格子の誤差 (sdev06) をテンプレートが回復できず Rwp 40% のまま、しかも `T-single` が
  一部の値を出版可にしていた / 欠陥なしの ZnO で `T-AB` の O1.z が開始点で割れる。
