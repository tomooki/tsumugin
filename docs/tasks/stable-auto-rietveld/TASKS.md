## T4 実測記録 (2026-07-28, 本気フィット・U,V,W 単独版)

```
RESULT T4 serious: Rwp=14.5252 GOF=5.5698 n_stages=60 reverted=21 (10120s = 2.8h)
```

**⚠ 既定レシピ (~12.8%) より悪い。** ただし**測定したのは U,V,W 単独版**であり、CaTeO3 で
18.07% → 12.19% の差を生んだ**累積版は未測定**。段のログに同じ病理が出ている:

```
STAGE   S4 profile_W    rwp= 38.9858 n_params=25
STAGE R S5 profile_U    rwp= 38.9858 n_params=25   ← revert
STAGE   S6 profile_V    rwp= 38.9848 n_params=25   ← ほぼ不変
```

CaTeO3 と同一の「U 単独段が revert し V もほぼ効かない」形なので、**累積版で改善する見込みが
高い**。Phase 0-3 で測定して確認する。

### 副次的な所見 (計画への含意)

1. **終盤 5 段が rwp ビット同一の no-op** — `cum_profile_lorentzian` 以降 14.5252 のまま
   n_params=27 で不変。**REQ-SAR-102 (no-op 段検出) が実際に発火すべき事例**であり、
   本要件の実データ裏付けになる。
2. **2.8 時間**かかった。安定性優先で時間を払う方針でも、多相 3 ヒストグラム × 60 段は
   現実的な上限に近い。**Phase 0-1 の並列ハーネスは必須**であり、加えて 3-3 (元素ランク展開に
   よる no-op 段の一掃) の優先度を上げる価値がある。
3. **GOF 5.57 が高い** (T1 1.87 / T3 2.06 に対し)。多相 + TOF で母数が足りていない可能性。
   `all_open` でも n_params=27 は 2 相にしては少なく、**何かが解放されていない**疑いがある —
   REQ-SAR-102 の検出対象。

## 検証ゲート (全タスク共通)

各タスクは以下を満たして初めて完了とする。

1. **6 データすべてで非回帰** — T1 / T2 / T3 / T4 / CaTeO3 / NaCuHCF
2. **改善は単独で測る** — 合成すると原因が切り分けられない (U,V,W の件を特定できたのは 1 変数ずつ測ったから)
3. **ガードテストは変異させて fail することを実証**する
4. `uv run pytest -m "not gsas"` が green
5. `uv run ruff check src tests` が clean
6. ベンチマーク結果を `docs/benchmark/stable-auto-rietveld/` に追記
