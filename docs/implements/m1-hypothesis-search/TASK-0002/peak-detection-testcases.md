## 対象シグネチャ（interfaces.py 準拠）

```python
@dataclass(frozen=True)
class Peak:
    position: float  # 2θ (deg) 🔵 FR-111 のマッチング単位
    height: float    # 強度 🔵

def find_peaks(
    two_theta: np.ndarray,
    intensity: np.ndarray,
    *,
    min_height_frac: float = 0.05,  # 最大強度に対する検出下限
) -> tuple[Peak, ...]:
    """局所極大 + 高さ閾値による観測ピーク検出。numpy のみ。"""
```

- 検出式（`tests/test_simulated_backend.py::_count_local_maxima` を手本）:
  `interior = (y[1:-1] > y[:-2]) & (y[1:-1] > y[2:]) & (y[1:-1] > min_height)`
  ここで `min_height = min_height_frac * y.max()`（`y.max() <= 0` は安全にゼロ扱い）。
- 端点（index 0, N-1）は極大判定から除外。戻りは **position 昇順の不変タプル**、失敗は例外化せず空タプル。

def _phase(a: float = 5.0, scale: float = 1.0, ref: str = "P") -> PhaseInstance:

def _backend() -> SimulatedBackend:

### TC-0002-N01: 単相合成パターンで検出ピーク数が真のピーク数と一致

- **テスト名**: 単相合成パターンで find_peaks の検出件数が `backend.peak_positions` の件数と一致する
  - **何をテストするか**: `SimulatedBackend.simulate` が生成した既知ピーク数と、`find_peaks` が返すピーク数が一致すること。
  - **期待される動作**: 各反射に対応する局所極大が過不足なく検出される（過検出・見落としがない）。
- **入力値**:
  - `tt = np.arange(15.0, 80.0, 0.02)`
  - `y = backend.simulate((_phase(a=5.0),), tt)`
  - `min_height_frac` は既定 `0.05`
  - **入力データの意味**: FWHM 0.2° のガウシアン列は各中心で 1 個の鋭い極大を持つ。`peak_positions` が範囲内反射の真の位置を返すため、教師データとして最適（note.md 3 章）。
- **期待される結果**: `len(find_peaks(tt, y)) == len(backend.peak_positions(_phase(a=5.0), tt))`
  - **期待結果の理由**: `_count_local_maxima(y, min_height=0.1*y.max())` が `len(positions)` と一致することが既存テストで実証済み。既定 `min_height_frac=0.05` は 0.1 より緩く、真ピーク（高さ ≈ scale）は全て閾値超過のため件数は保存される。
- **テストの目的**: 完了条件 1（ピーク数を正しく検出）の検証。
  - **確認ポイント**: ガウシアン裾のサンプル点を極大と誤検出しないこと（厳密不等号 `>` により隣接点比較で単一極大に収束）。
- 🔵 信頼性レベル: 完了条件 1・note.md 5 章の推奨ケース・既存 `test_simulate_produces_one_maximum_per_in_range_reflection` に直接依拠。

### TC-0002-N02: 検出ピーク位置が真の位置 ±1 グリッド以内

  - **入力データの意味**: グリッド刻み 0.02°。ガウシアン中心はグリッド上にあるとは限らないため、最寄りグリッド点（誤差 ≤ 半刻み〜1刻み）に極大が立つ。
- **期待される結果**: 各 `p.position` について `min(abs(p.position - t) for t in positions) <= (tt[1]-tt[0]) + 1e-9`
  - **期待結果の理由**: 完了条件 1「位置（±1 グリッド）を正しく検出」。要件定義 4 章「真の位置から ±1 グリッド以内」。
- **テストの目的**: 完了条件 1（位置精度）の検証。
  - **確認ポイント**: 位置の単位が 2θ(deg) であること（FR-111 のマッチング単位）。浮動小数比較は許容誤差 `abs` を付す。
- 🔵 信頼性レベル: 完了条件 1・要件定義 4 章・`peak_positions` 実装に直接依拠。

def test_single_phase_peak_positions_within_one_grid():

### TC-0002-E01: 全ゼロ強度で空タプル・例外なし（EDGE-003）

- **テスト名**: `intensity` が全ゼロのとき空タプルを返し例外を送出しない

  - **エラー処理の重要性**: `min_height = min_height_frac * y.max()` の計算や比較でゼロ除算・破綻を起こさず、下流（TC-005-03 の「フラットで例外なく空の良好解」）の基盤挙動を保証するため。
- **入力値**: `tt = _grid()`, `y = np.zeros_like(tt)`
  - **不正な理由**: 検出すべきピークが存在しない（内部極大なし・`max<=0`）。関数の正常な検出対象を欠く縮退入力。
  - **実際の発生シナリオ**: 測定失敗・空データ・バックグラウンド差引きで全域ゼロになった観測パターン（EDGE-003）。
- **期待される結果**: `find_peaks(tt, y) == ()`（空タプル）。例外を送出しない。
  - **エラーメッセージの内容**: 例外を出さない設計のためメッセージは不要（沈黙して空を返す）。
  - **システムの安全性**: 例外で探索全体を止めず、上位で「良好解 + 警告」に縮退できる安全状態を維持。
- **テストの目的**: 完了条件 2・EDGE-003（フラット/全ゼロ → 空タプル・例外なし）の検証。
  - **品質保証の観点**: ゼロ除算・空配列演算などの実装バグを早期検出し、探索エンジンの完走性（TC-005-03）を担保。

  - **品質保証の観点**: `>` を `>=` と誤実装した場合に全点検出してしまうバグを検出。
- 🔵 信頼性レベル: EDGE-003・要件定義 4 章「一定値 → 空タプル」に直接依拠。

### TC-0002-E03: 全負値（max ≤ 0）で空タプル・比較破綻なし

- **テスト名**: `intensity` が全て負値（`max <= 0`）のとき空タプルを返す
  - **エラーケースの概要**: `y.max() <= 0` で高さ閾値が非正になる縮退ケース。
  - **エラー処理の重要性**: note.md 6 章「`intensity.max() <= 0` のとき閾値計算で例外を出さない」を保証。
- **入力値**: `tt = _grid()`, `y = np.full_like(tt, -5.0)`
  - **不正な理由**: 物理的にありえない負強度だが、バックグラウンド過剰差引きで発生しうる。極大も閾値超過も成立しない。
  - **実際の発生シナリオ**: 過補正・オフセット誤りで負に振れた強度配列。
- **期待される結果**: `find_peaks(tt, y) == ()`、例外なし
  - **システムの安全性**: 閾値が負になっても比較・除算で破綻せず空を返す。
- **テストの目的**: 縮退入力（`max<=0`）の安全処理（note.md 6 章・要件定義 3 章）の検証。
  - **品質保証の観点**: 閾値をゼロクランプせず負のまま比較すると「谷でも極大」と誤検出する可能性を排除。
- 🟡 信頼性レベル: note.md 6 章・要件定義 3 章「max<=0 で例外を出さず空」からの妥当な推測（具体値 -5.0 はテスト設計上の選択）。

### TC-0002-E04: 単調増加配列（内部極大なし）で空タプル

- **テスト名**: 単調増加（および単調減少）で内部極大が存在せず空タプル
  - **エラーケースの概要**: `y = tt` のような単調配列。各内部点は片側の隣より小さく極大にならない。端点は判定除外。
  - **エラー処理の重要性**: 端点を誤って極大に含めない（端点除外仕様）ことの確認。
- **入力値**: `tt = _grid()`, `y = np.linspace(1.0, 100.0, tt.size)`（単調増加）
  - **不正な理由**: ピーク（山）が存在しない。最大値は端点（右端）にありこれは検出対象外。
  - **実際の発生シナリオ**: 低角側の連続バックグラウンド上昇のみで反射が無い区間。
- **期待される結果**: `find_peaks(tt, y) == ()`
  - **システムの安全性**: 端点を極大扱いしないため、右端の最大値を誤検出しない。
- **テストの目的**: 端点除外（要件定義 3 章「端点は極大判定から除外」）と内部極大なしの空返却検証。
  - **品質保証の観点**: 端点処理のオフバイワンバグ（`y[0]`/`y[-1]` を含める誤り）を検出。
- 🟡 信頼性レベル: 要件定義 3 章「端点は極大判定から除外」・note.md 6 章からの妥当な推測（単調配列は代表的検証入力）。

## 3. 境界値テストケース（最小値・最大値・閾値境界等）

### TC-0002-B01: 配列長 < 3（内部点が存在しない）で空タプル

- **テスト名**: 配列長 0 / 1 / 2 のとき空タプルを返す
  - **境界値の意味**: 局所極大は「内部点（index 1..N-2）」のみで判定するため、内部点が存在する最小長は 3。長さ < 3 は検出不能の境界。
  - **境界値での動作保証**: `y[1:-1]` が空スライスになり `count_nonzero` がゼロ、例外なく空を返すこと。
- **入力値**:
  - 長さ0: `find_peaks(np.array([]), np.array([]))`
  - 長さ1: `find_peaks(np.array([20.0]), np.array([5.0]))`
  - 長さ2: `find_peaks(np.array([20.0, 20.02]), np.array([5.0, 9.0]))`
  - **境界値選択の根拠**: 内部点数 = N-2。N=0,1,2 で内部点 0 個 → 検出不能の直下境界。N=3 が検出可能な最小長。
  - **実際の使用場面**: 極端に狭い 2θ 窓・切り出しミスで数点しかない配列。
- **期待される結果**: いずれも `find_peaks(...) == ()`、例外なし
  - **境界での正確性**: 空スライス・単要素スライスでも numpy 比較が破綻しない。
  - **一貫した動作**: N<3 は常に空、N>=3 で初めて検出が起こりうる。
- **テストの目的**: 極小入力（要件定義 4 章「配列長 < 3 → 空タプル」）の堅牢性確認。
  - **堅牢性の確認**: 空配列 `y.max()`（ValueError）を踏まないガードの存在を検証。
- 🟡 信頼性レベル: 要件定義 4 章・note.md 6 章「配列長 < 3 の極小入力」からの妥当な推測。

```python
@pytest.mark.parametrize("x,y", [
    (np.array([]), np.array([])),                       # 長さ0
    (np.array([20.0]), np.array([5.0])),                # 長さ1
    (np.array([20.0, 20.02]), np.array([5.0, 9.0])),    # 長さ2
])
def test_too_short_returns_empty(x, y):
    # 【テスト目的】: 内部点が存在しない極小入力で空タプルを返すことを確認
    # 🟡 信頼性レベル: 要件定義4章「配列長<3→空」からの妥当な推測
    assert find_peaks(x, y) == ()  # 【検証項目】: 空配列 max() 等で例外を出さず空を返す 🟡
```

### TC-0002-B02: 内部にちょうど 1 個の極大（最小の有意ピーク）で 1 件検出

- **テスト名**: 内部に単一の山を持つ最小配列で 1 個の Peak を返す
  - **境界値の意味**: 「検出が起こる最小構成」の境界。N=3 の三角形 `[1, 9, 1]` は index 1 が唯一の極大。
  - **境界値での動作保証**: 内部点が 1 つだけ存在し、それが閾値を超えるとき、ちょうど 1 件返ること。
- **入力値**: `x = np.array([20.0, 20.02, 20.04])`, `y = np.array([1.0, 9.0, 1.0])`, `min_height_frac=0.05`
  - **境界値選択の根拠**: N=3 は検出可能な最小長（TC-0002-B01 の直上）。閾値 = 0.05*9 = 0.45 で頂点 9.0 は明確に超過。
  - **実際の使用場面**: 単一反射のみを含む狭窓観測。
- **期待される結果**: `len(find_peaks(x, y)) == 1`、`peaks[0].position == pytest.approx(20.02)`、`peaks[0].height == pytest.approx(9.0)`
  - **境界での正確性**: 位置は頂点グリッド、height は頂点強度。
  - **一貫した動作**: N=2（TC-0002-B01）で 0 件 → N=3 で 1 件、と境界の内外で一貫。
- **テストの目的**: 最小検出構成での position/height 正確性の確認。
  - **堅牢性の確認**: スライス境界（`y[1:-1]` が長さ1）でインデックス写像が正しいこと。
- 🟡 信頼性レベル: 検出アルゴリズム（局所極大式）からの妥当な推測（具体配列はテスト設計上の選択）。

### TC-0002-B03: min_height_frac を上げると微小ピークが検出から落ちる（閾値単調性）

- **テスト名**: 高さ閾値比率の増加に対する検出件数の単調非増加
  - **境界値の意味**: `min_height_frac` は 0（全極大採用）〜 1（最大点も `>` で不採用）の境界を持つフィルタ強度パラメータ。
  - **境界値での動作保証**: 大きな主ピークと小さな副ピークが混在するとき、閾値を上げると副ピークが消えること（完了条件 3）。
- **入力値**:
  - `x = np.arange(15.0, 80.0, 0.02)`
  - `y` = 高さ 10.0 の主ピーク（gauss, center=30）+ 高さ 0.3 の副ピーク（gauss, center=50）を重ねた合成
  - 比較: `find_peaks(x, y, min_height_frac=0.01)` vs `find_peaks(x, y, min_height_frac=0.1)`
  - **境界値選択の根拠**: 副ピーク高さ 0.3 は `0.01*10=0.1`（採用）と `0.1*10=1.0`（不採用）の間に位置し、閾値を跨ぐ境界を作る。
  - **実際の使用場面**: 微小な不純物ピークやノイズ由来の小山を除外したい解析（SearchConfig.min_peak_height_frac のチューニング）。
- **期待される結果**:
  - `n_low = len(find_peaks(x, y, min_height_frac=0.01))`
  - `n_high = len(find_peaks(x, y, min_height_frac=0.1))`
  - `n_low > n_high`（副ピークが high で脱落）かつ `n_high >= 1`（主ピークは残る）
  - **境界での正確性**: 閾値をちょうど跨いだ副ピークのみが増減する。
  - **一貫した動作**: `min_height_frac` に対し検出件数は単調非増加。
- **テストの目的**: 完了条件 3（閾値未満の微小ピークは検出しない）・閾値挙動の単調性の検証。
  - **堅牢性の確認**: 閾値 = `min_height_frac * max` の適用が正しいこと。
- 🟡 信頼性レベル: 完了条件 3・要件定義 4 章「min_height_frac を上げると微小ピークが落ちる」からの妥当な推測（合成の具体設計は選択）。

```python
def _two_peak_pattern(tt, big=10.0, small=0.3):
    # 【テストデータ準備】: 主ピーク(高10)と微小ピーク(高0.3)を重ねた合成
    def g(center, h):
        return h * np.exp(-0.5 * ((tt - center) / 0.08) ** 2)
    return g(30.0, big) + g(50.0, small)

def test_higher_threshold_drops_small_peaks():
    # 【テスト目的】: min_height_frac を上げると微小ピークが検出から落ちることを確認
    # 🟡 信頼性レベル: 完了条件3（閾値未満は検出しない）からの妥当な推測
    tt = _grid()
    y = _two_peak_pattern(tt)
    n_low = len(find_peaks(tt, y, min_height_frac=0.01))   # 微小ピーク採用
    n_high = len(find_peaks(tt, y, min_height_frac=0.1))   # 微小ピーク脱落
    assert n_low > n_high   # 【検証項目】: 閾値上昇で件数が減る 🟡
    assert n_high >= 1      # 【検証項目】: 主ピークは残る 🟡
```

### TC-0002-B04: 高さが閾値ちょうど（height == min_height）は厳密不等号で除外

- **テスト名**: 極大の高さが閾値と厳密に等しいとき検出されない（`>` の境界）
  - **境界値の意味**: 検出条件 `y[i] > min_height` は**厳密不等号**。等値（`==`）は採用境界のちょうど外側。
  - **境界値での動作保証**: 閾値と同値のピークを採用/不採用のどちらに倒すかの仕様確定（保守的に不採用）。
- **入力値**:
  - `x = np.array([20.0, 20.02, 20.04, 20.06, 20.08])`
  - `y = np.array([0.0, 2.0, 0.0, 1.0, 0.0])`
  - `min_height_frac = 0.5` → `min_height = 0.5 * max(=2.0) = 1.0`。副ピーク高さ = 1.0 = 閾値ちょうど。
  - **境界値選択の根拠**: 副ピーク高さを閾値と完全一致させ、`>`（除外）と `>=`（採用）の実装差を切り分ける。
  - **実際の使用場面**: 閾値近傍のピーク採否の一貫性（浮動小数の等値境界）。
- **期待される結果**: 検出は主ピーク（高さ 2.0）のみ 1 件。閾値同値の副ピーク（1.0）は含まれない。
  `positions = [p.position for p in find_peaks(x, y, min_height_frac=0.5)]` に `20.06` を含まない。
  - **境界での正確性**: `>` により等値は不採用。過検出を避ける保守的挙動（note.md 6 章プラトー同様の思想）。
  - **一貫した動作**: 閾値をわずかに下げれば（例 0.49）副ピークが採用に転じること（内側は採用）。
- **テストの目的**: 閾値の厳密不等号境界（採用/不採用の分かれ目）の確認。
  - **堅牢性の確認**: `>=` 誤実装や浮動小数丸め方向の取り違えを検出。
- 🟡 信頼性レベル: 検出式 `y[1:-1] > min_height`（note.md/要件定義 2 章）からの妥当な推測（厳密不等号は手本コードに依拠 🔵 寄り、等値時挙動の仕様確定は 🟡）。

### TC-0002-B05: プラトー頂点（隣接サンプル等値の平坦な山）は極大とみなさない

- **テスト名**: 頂点が 2 点以上の等値プラトーになっている山を検出しない
  - **境界値の意味**: 厳密不等号 `>` は「両隣より真に大きい」点のみを極大とする。頂点が平坦（`y[i] == y[i+1]`）だと成立しない境界。
  - **境界値での動作保証**: プラトー型の山で過検出（0 件 or 実装依存）せず、仕様（保守的に不検出）で一貫すること。
- **入力値**:
  - `x = np.array([20.0, 20.02, 20.04, 20.06, 20.08])`
  - `y = np.array([1.0, 9.0, 9.0, 1.0, 1.0])`（index 1,2 が等値の平坦頂点）
  - **境界値選択の根拠**: `y[1] > y[0]` は真だが `y[1] > y[2]`（9>9）が偽、`y[2] > y[1]` も偽。どの内部点も極大条件を満たさない。
  - **実際の使用場面**: 飽和・量子化で頂点が複数サンプル同値になった実測ピーク。
- **期待される結果**: `find_peaks(x, y) == ()`（プラトーは極大とみなさない、note.md 6 章「厳密不等号 `>` により極大とみなされない」）
  - **境界での正確性**: 過検出（左右エッジを 2 個検出する等）を起こさない。
  - **一貫した動作**: 頂点を単一点にすれば（`[1,9,8,1,1]`）1 件検出、という内外一貫性。
- **テストの目的**: プラトー頂点の保守的（不検出）挙動（note.md 6 章・要件定義 4 章）の確認。
  - **堅牢性の確認**: プラトーで NaN/例外/多重検出を起こさないこと。
- 🟡 信頼性レベル: note.md 6 章・要件定義 4 章「プラトー頂点は極大とみなされない」からの妥当な推測（保守的不検出を仕様とする）。
