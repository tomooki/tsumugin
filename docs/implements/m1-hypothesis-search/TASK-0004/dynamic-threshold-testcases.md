## 契約サマリー (テスト設計の前提)

```python
def dynamic_threshold(scores: Sequence[float], *, min_candidates: int = 4) -> float:
    """スコア降順の累積分布の変曲点 (二階差分最大) で枝刈り閾値を返す。
    縮退時 (全同値等) は -inf (全展開)。🔵 FR-112 (実装式は 🟡)"""
```

- **アルゴリズム (🟡 interview Q8)**: `scores` を降順ソート → 累積和 `c` → 二階差分 `d2[i]=c[i+1]-2c[i]+c[i-1]` → **二階差分最大 (最大曲率=変曲点)** 位置のスコアを閾値とする。タイは一意規則で固定。
- **境界セマンティクス (🟡)**: 呼び出し側 (TASK-0006) は「スコア **< 閾値** の相を展開しない」。閾値そのものは**展開側に含む** (REQ-101、境界は「未満」)。
- **縮退 → `float("-inf")`**: (a) `len(scores) < min_candidates`、(b) 全同値等で二階差分が全ゼロ (変曲点が一意に定まらない)。NaN・例外は返さない。
- **決定論 (🔵 REQ-403/NFR-102)**: ソートは関数内で行い、同一集合なら入力順に依存せずビット同一。
- **非破壊 (🔵 NFR-101)**: 入力 `scores` を破壊しない (コピーに対してソート)。

**参照元**: `docs/design/m1-hypothesis-search/interfaces.py` L88-95、`dynamic-threshold-requirements.md`、`note.md` §4/§6、`acceptance-criteria.md` L37-40 (TC-002-02〜04)

## 1. 正常系テストケース（基本的な動作）

### TC-N01: 二群分離入力で閾値が高群と低群の間に決まる (TC-002-02)

- **テスト名**: 高スコア群と低スコア群が明確に分かれる入力で閾値が両群の間に決まる
  - **何をテストするか**: 累積分布の変曲点で決めた閾値が、高群 (残す) と低群 (枝刈り) の**間**に入ること
  - **期待される動作**: 閾値 `t` が `max(低群) < t <= min(高群)` を満たし、低群スコアが全て `< t` (枝刈り対象) になる
- **入力値**: `scores = [0.9, 0.85, 0.8, 0.2, 0.15]`, `min_candidates=4` (既定)
  - **入力データの意味**: 高群 `{0.9,0.85,0.8}` と低群 `{0.2,0.15}` が明確に分離する典型入力 (requirements §4 基本パターン)
- **期待される結果**: `0.2 < threshold <= 0.8` かつ `all(s < threshold for s in [0.2, 0.15])` かつ `all(s >= threshold for s in [0.9,0.85,0.8])`
  - **期待結果の理由**: 累積分布の傾きが急変する変曲点は高群→低群の境界に立つ。閾値未満 (低群) のみが展開対象外になる (REQ-101)
- **テストの目的**: 変曲点ベースの閾値が枝刈り境界として機能することの確認
  - **確認ポイント**: 閾値が低群最大 (0.2) を上回り、高群最小 (0.8) を下回らない (ギャップに入る)
- 🔵 信頼性レベル: 受け入れ基準 TC-002-02・requirements §4 基本パターンに直接依拠

### TC-N02: 正常時は有限 float を値域内で返す

- **テスト名**: 変曲点が定まる入力で有限の Python float を返す
  - **何をテストするか**: 縮退しない入力で戻り値が `-inf` でない有限値、かつ `[min(scores), max(scores)]` の範囲内、型が素の `float`
  - **期待される動作**: `type(result) is float`、`math.isfinite(result)`、`min(scores) <= result <= max(scores)`
- **入力値**: `scores = [1.0, 0.7, 0.65, 0.6, 0.1]`, `min_candidates=4`
  - **入力データの意味**: 変曲点が一意に定まる非縮退入力。numpy スカラーでなく Python float を返す契約 (requirements §2 出力) を検証
- **期待される結果**: `isinstance(result, float)` かつ numpy 型でない、`math.isfinite(result)` が True、`0.1 <= result <= 1.0`
  - **期待結果の理由**: 閾値は必ず既存スコア準位 (または累積分布上の値) であり、入力値域を逸脱しない。契約は素の float を返す
- **テストの目的**: 正常系の戻り値型・値域の健全性確認
  - **確認ポイント**: `numpy.float64` をそのまま返さず `float()` 変換していること (`type(result) is float`)
- 🟡 信頼性レベル: requirements §2 出力仕様「素の float」🔵 + 値域内は妥当な推測 🟡

### TC-N03: 入力順を入れ替えても同一閾値 (完了条件4 / 決定論)

- **テスト名**: 入力順を並べ替えても同一閾値を返す (関数内ソートによる決定論)
  - **何をテストするか**: 同一集合を異なる順序で渡したとき、閾値が `==` でビット同一になること
  - **期待される動作**: `dynamic_threshold(seq) == dynamic_threshold(shuffled(seq))`
- **入力値**: `base = [0.9, 0.85, 0.8, 0.2, 0.15]` と、その並べ替え `shuf = [0.2, 0.9, 0.15, 0.8, 0.85]`
  - **入力データの意味**: 同一多重集合で順序のみ異なる 2 系列。関数内で降順ソートするため結果は不変であるべき
- **期待される結果**: `dynamic_threshold(base) == dynamic_threshold(shuf)` (approx でなく `==`)
  - **期待結果の理由**: REQ-403/NFR-102 のビット同一要求。ソートを関数内で行えば入力順は結果に影響しない
- **テストの目的**: 決定論 (入力順非依存) の確認
  - **確認ポイント**: 浮動小数の等値比較を `==` で行い、順序由来の揺れが 1ulp も出ないこと
- 🔵 信頼性レベル: 完了条件4・REQ-403/NFR-102・acceptance-criteria に直接依拠

## 2. 異常系テストケース（縮退・エラーハンドリング）

### TC-E01: 候補 3 以下 (< min_candidates=4) で -inf を返す (TC-002-03)

- **テスト名**: 候補数が min_candidates 未満のとき枝刈り無効 (-inf) に縮退する
  - **エラーケースの概要**: 候補が少なすぎて変曲点を統計的に決められない状況
  - **エラー処理の重要性**: 少数候補で誤った閾値を出すと有効な相を誤って枝刈りしてしまう。全展開へフォールバックが安全
- **入力値**: `scores = [0.9, 0.5, 0.1]` (len=3), `min_candidates=4` (既定)
  - **不正な理由**: `len(scores)=3 < min_candidates=4` で枝刈りを有効化する最小候補数に満たない
  - **実際の発生シナリオ**: 上流マッチングで範囲内候補相が 3 相以下しか残らなかったノード
- **期待される結果**: `result == float("-inf")` (`math.isinf(result)` かつ `result < 0`)。例外は送出しない
  - **エラーメッセージの内容**: 例外でなく `-inf` 返却で「全展開」を表現 (M0 規約: 失敗の非例外化)
  - **システムの安全性**: `-inf` により全スコア `>= -inf` となり、どの相も枝刈られず探索の網羅性が保たれる
- **テストの目的**: 候補不足時の枝刈り無効フォールバックの確認
  - **品質保証の観点**: 少数候補で過剰枝刈りによる真の相の取りこぼしを防ぐ
- 🟡 信頼性レベル: 受け入れ基準 TC-002-03 (資料上 🟡)・requirements §4 に依拠

### TC-E02: 空入力 [] で -inf を返し例外を出さない (EDGE-001)

- **テスト名**: 空のスコア列を渡しても例外なく -inf に縮退する
  - **エラーケースの概要**: 候補相ゼロ (空列) の縮退入力
  - **エラー処理の重要性**: 空配列に対する `max()`/`argmax()`/ソートで `ValueError`/`IndexError` を出さない安全性が必要
- **入力値**: `scores = []`, `min_candidates=4`
  - **不正な理由**: 要素ゼロで累積分布・二階差分が構成不能
  - **実際の発生シナリオ**: EDGE-001「候補相ゼロ」— 範囲内に候補が 1 相も残らなかったノード
- **期待される結果**: `result == float("-inf")`、例外送出なし
  - **エラーメッセージの内容**: 例外でなく `-inf`。`len < min_candidates` の縮退経路に含まれる
  - **システムの安全性**: 空入力でもクラッシュせず全展開を意味する `-inf` を返す
- **テストの目的**: 空入力の安全縮退の確認
  - **品質保証の観点**: EDGE-001「候補ゼロで例外を投げない」精神との整合
- 🟡 信頼性レベル: requirements §4 空入力 (🟡)・EDGE-001 (🔵) からの整合

### TC-E03: あらゆる縮退で NaN・例外を出さず必ず float("-inf") に一元化する

- **テスト名**: 縮退経路で NaN・None・例外を返さず -inf のみを返す
  - **エラーケースの概要**: 複数の縮退トリガ (候補不足・全同値・min_candidates 過小指定) を横断した戻り値の一貫性
  - **エラー処理の重要性**: 呼び出し側 (TASK-0006) は `-inf` を「全展開」と一意に解釈する。NaN が混入すると比較が全て False になり探索が破綻する
- **入力値**: 複数ケースを parametrize — `([], 4)`, `([0.5, 0.5], 4)`, `([0.9, 0.5], 2)` (min_candidates=2, len=2 で二階差分の最小点数 3 に満たない)
  - **不正な理由**: それぞれ候補不足 / 全同値 / 二階差分不能 (点数不足) の縮退。特に `min_candidates=2` は既定より小さく、点数不足で `IndexError` を誘発しうる境界
  - **実際の発生シナリオ**: 呼び出し側が `min_candidates` を小さく設定した場合の防御
- **期待される結果**: 全ケースで `result == float("-inf")`、`not math.isnan(result)`、例外送出なし
  - **エラーメッセージの内容**: 縮退値を `float("-inf")` に一元化 (NaN・例外・None を返さない)
  - **システムの安全性**: `min_candidates` を小さくしても `IndexError` を出さず縮退するガード (note §6) を検証
- **テストの目的**: 縮退値の一元化と点数不足ガードの確認
  - **品質保証の観点**: 二階差分は内部点 (両隣) が最低 1 つ = 実質 3 点以上必要。3 点未満でも例外にせず縮退
- 🔵 信頼性レベル: 失敗の非例外化 (EDGE/M0 規約)・note §6 点数不足ガードに直接依拠

## 3. 境界値テストケース（全同値・候補数境界・タイ処理）

### TC-B01: 全候補同スコアで閾値決定が破綻せず -inf にフォールバック (TC-002-04)

- **テスト名**: 全スコアが同値のとき二階差分全ゼロで -inf へフォールバックする
  - **境界値の意味**: 変曲点が一意に定まらない (二階差分が恒等的にゼロ) 極限ケース
  - **境界値での動作保証**: `argmax` が全ゼロ配列で先頭を選ぶような曖昧な閾値を返さず、明示的に縮退すること
- **入力値**: `scores = [0.5, 0.5, 0.5, 0.5, 0.5]` (len=5 で min_candidates=4 の候補数ガードは通過)
  - **境界値選択の根拠**: 候補数は十分 (5>=4) だが分布が平坦で変曲点が存在しない。候補数ガードでなく**変曲点ガード**が発火する経路を狙う
  - **実際の使用場面**: 全候補が同程度にマッチする (優劣がつかない) ノード
- **期待される結果**: `result == float("-inf")` (候補数は足りるが二階差分全ゼロで縮退)、例外なし
  - **境界での正確性**: 二階差分の最大値が 0 (全ゼロ) のとき「変曲点なし」と判定し `-inf` を返す
  - **一貫した動作**: 候補数が足りても分布が縮退していれば全展開へ倒す
- **テストの目的**: 変曲点非存在時のフォールバック確認
  - **堅牢性の確認**: 平坦分布で偽の閾値を出さず安全に全展開する
- 🟡 信頼性レベル: 受け入れ基準 TC-002-04 (資料上 🟡)・note §6 に依拠

### TC-B02: 候補数がちょうど min_candidates (=4) で有効閾値を算出する

- **テスト名**: 候補数が min_candidates ちょうどのとき縮退せず閾値を算出する (候補数ガード境界)
  - **境界値の意味**: 候補数ガードの境界 `len(scores) >= min_candidates` (以上は通過、未満は縮退) の内側ちょうど
  - **境界値での動作保証**: `len==min_candidates` で `< min_candidates` に誤分類 (オフバイワン) しないこと
- **入力値**: `scores = [0.9, 0.85, 0.3, 0.25]` (len=4 == min_candidates), `min_candidates=4`
  - **境界値選択の根拠**: 候補数がガード境界ちょうど、かつ高群 `{0.9,0.85}`/低群 `{0.3,0.25}` に分離し変曲点が定まる
  - **実際の使用場面**: 枝刈りが有効化される最小の候補数 (4 相) を持つノード
- **期待される結果**: `result != float("-inf")` (有限値)、`0.3 < result <= 0.85`
  - **境界での正確性**: `len==min_candidates` は縮退させず正常に閾値を返す (`>=` 判定)
  - **一貫した動作**: 境界の内側 (4) は算出、外側 (3, TC-E01) は縮退で一貫
- **テストの目的**: 候補数ガードのオフバイワン検証
  - **堅牢性の確認**: `<` と `<=` の取り違えで正常入力を誤縮退させない
- 🟡 信頼性レベル: requirements §2/§4・note §6 の候補数境界からの妥当な推測

### TC-B03: min_candidates=3 指定 + 3 点 (二階差分の最小点数) で有効閾値を算出する

- **テスト名**: 二階差分に必要な最小点数 (3 点) を min_candidates=3 で明示指定したとき算出できる
  - **境界値の意味**: 二階差分は内部点 1 つ = 実質 3 点が最小。この最小点数ちょうどで計算が成立する境界
  - **境界値での動作保証**: 3 点 (内部点 1 つ) で `IndexError` を出さず 1 個の二階差分から閾値を決める
- **入力値**: `scores = [1.0, 0.9, 0.1]`, `min_candidates=3`
  - **境界値選択の根拠**: 候補数ガードを 3 に緩めた上で、二階差分が計算可能な最小構成 (内部 index=1 の 1 点のみ) を与える
  - **実際の使用場面**: 呼び出し側が枝刈りを積極化するため min_candidates を下げた設定
- **期待される結果**: `result != float("-inf")` (有限値)、`0.1 <= result <= 1.0`、例外なし
  - **境界での正確性**: 内部点 1 つでも二階差分 `c[2]-2c[1]+c[0]` を計算し閾値を返す
  - **一貫した動作**: 3 点で成立、2 点以下 (TC-E03 の `min_candidates=2` ケース) は縮退で一貫
- **テストの目的**: 二階差分の最小点数境界の確認
  - **堅牢性の確認**: 内部点が 1 つしかない極小配列でスライス破綻しない
- 🟡 信頼性レベル: note §6「二階差分に必要な最小点数 = 3 点」からの妥当な推測

### TC-B04: 二階差分最大がタイのとき採用位置を一意規則で固定し決定論を保つ

- **テスト名**: 変曲点候補 (二階差分最大) が複数タイでも決定論的に同一閾値を返す
  - **境界値の意味**: 二階差分の最大値が複数位置で同値になる (タイ) 曖昧ケース
  - **境界値での動作保証**: タイ時の採用位置を一意規則 (例: 最初 / 最大スコア側) で固定し、入力順で揺れないこと
- **入力値**: 二階差分が対称にタイになる入力 `scores = [1.0, 0.9, 0.5, 0.1, 0.0]` と、その並べ替えを 2 回・複数順序で評価
  - **境界値選択の根拠**: 対称的な階段状分布は二階差分の最大が複数位置で並びやすく、タイ処理の一意性を試せる
  - **実際の使用場面**: 等間隔にスコアが並ぶノード。タイ処理が甘いと入力順で閾値が揺れる
- **期待される結果**: 同一集合の複数順序に対し全て `==` で同一閾値。2 回連続実行でもビット同一
  - **境界での正確性**: タイ時も一意規則で 1 位置を確定し、`argmax` の順序依存を排除
  - **一貫した動作**: 入力順・呼び出し回数に依らず結果が不変
- **テストの目的**: タイ処理の決定論確認 (完了条件4 の深掘り)
  - **堅牢性の確認**: `np.argmax` のタイ時挙動 (最初のインデックス) に依存しても、関数内ソートで入力順非依存が保たれること
- 🟡 信頼性レベル: note §6 タイ処理・REQ-403 決定論 (🔵) からのタイ特化推測

### TC-B05: 閾値そのものは展開側に含む (境界は「未満」で枝刈り)

- **テスト名**: 返す閾値が既存スコア準位に一致し、閾値と等しいスコアは枝刈られない境界を確認
  - **境界値の意味**: REQ-101 の「スコア **< 閾値** なら展開しない」= 閾値ちょうどのスコアは**展開側**に残る境界
  - **境界値での動作保証**: 閾値が高群の最小スコアに一致し、`score == threshold` の相が枝刈り対象に入らないこと
- **入力値**: `scores = [0.9, 0.85, 0.8, 0.2, 0.15]`, `min_candidates=4` (TC-N01 と同一入力で境界セマンティクスを特化検証)
  - **境界値選択の根拠**: 高群最小 0.8 が閾値になれば、`< 0.8` の低群のみ枝刈られ 0.8 は残る (展開側)
  - **実際の使用場面**: 閾値ちょうどのスコアを持つ相の扱い (残すか枝刈るか) が探索網羅性を左右する
- **期待される結果**: `threshold <= 0.8` かつ、高群 `{0.9,0.85,0.8}` は全て `>= threshold` (枝刈られない)。低群 `{0.2,0.15}` は `< threshold`
  - **境界での正確性**: 「未満」判定で境界スコア (閾値と等しい相) を展開側に含める
  - **一貫した動作**: 呼び出し側の `score < threshold` 枝刈り規則と整合する閾値準位を返す
- **テストの目的**: 境界セマンティクス (閾値の等号側の扱い) の確定
