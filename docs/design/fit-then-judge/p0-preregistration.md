### 1.2 アームの失敗と `unevaluated` (全指標に共通の数え方)

- **アームの失敗** = 例外・error dict・χ² が非有限・最終段の未収束 (各経路自身の収束判定)。**比較では失敗したアームの負け**として数える
  (未収束を除外しない — v4 3 巡目の処置)。両方が失敗した事例は「両方失敗」として別に数え、劣化には数えない。
- **`unevaluated`** = 比較そのものが成り立たない (参照構造が無い・観測集合が違う・検査器が評価できない・反証の fit が失敗した)。
  **すべての指標で分母から外し、件数を必ず併記する**。`unevaluated` を `pass` にも「反証なし」にも数えない。
- ある指標の `unevaluated` が対象の **50% を超えたら、その指標は「判定不能」**。合否に使う指標が判定不能なら P2 は通過しない (§2.3)。
  合否の指標は**事例ごとの `W_i` 全体** (§2.1) と、その構造の部分 ((c)(d)(e) をまとめたもの。(c) と (e) は参照の有無で相補なので 1 つの指標) で数える。
  (c) だけを取り出して 50% 規則を当てない (参照のある事例の下限は N_ref = 10 (U7) で、事例の半数に満たないことがあり、それだけで判定不能になってしまう)。
- **N に数えない事例**: 事例ごと `unevaluated` のもの・「両方失敗」のもの。どちらも件数を別に報告する。
- **収束の判定はアーム間で揃える**: 経路ごとの収束判定に加え、評価スクリプトが**全アームの最終 gpx に同じ事後検査** (追加サイクルでの |shift|/esd。
  閾値は P1.5 で凍結。結果のファイルは書き換えず写しで行う) を掛け、外れたアームを未収束 = 失敗とする (テンプレートだけが自前の収束確認を持つ非対称を消す)。

### 1.3 構造の悪化 — 独立参照がある事例

- **参照構造の独立性**: 出発構造と**別の出版物かつ別の測定** (同じデータの再精密化は不可)。出典 (書誌・DB ID・sha256) は P1.5 の凍結で登録する。
  さらに機械的な照合を掛ける: 比較集合の値が参照と出発構造で**印字精度の範囲ですべて一致**したら独立でないとみなす
  (出発構造の出所が不明な公開 CIF への対策)。独立参照が無い事例は §1.4 に回し、**出発構造を参照の代わりに使わない**
  (何も動かさない fit が最良になり、凍結の多い手順に有利になる — proposal §6)。
- **比較集合**: 参照と原子を対応づけた (対応表は凍結時に登録) 全原子の**自由座標** (`GetCSxinel` の自由軸) と、どちらかのアームで占有率を
  精密化した席または参照で部分占有の席の**占有率**。格子は**両方のアームが `scope = absolute` のときだけ**入れる (proposal §3.1・§6)。
  比較集合は事例ごとに 1 つで、全アームに同じものを使う。**精密化しなかった値も含める** (凍結に無料の得点を与えない)。
- **規格化偏差**: `u = |Δ| / max(σ_c, f/3)`、`σ_c = √(σ_ref² + σ_fit²)` (proposal §5。**GOF を掛けない** — review-response 3 巡目の
  `√(σ_ref² + (GOF·σ_fit)²)` は v5 で訂正済み)。精密化しなかった値は σ_fit = 0。σ_ref の無い参照値は `unevaluated`。
  床 f は既存の一致判定 (`AgreementTolerances`, commit e824e75) と同じ値と単位: 座標は**原子ごとの変位の Å 距離** |Δr| に **0.02 Å**
  (その σ は軸ごとの esd を対角近似で伝播)・占有率 **0.02**・格子 相対 **1e-4**。
  **アーム間の比較 (§2.1 (c)) では分母をアーム間で共通にする**: `σ_c = √(σ_ref² + max(σ_fit,T, σ_fit,B)²)`。各アーム自身の esd を使うと、
  GOF の悪いアーム・決まらない母数を解放したアームほど σ_c が大きく偏差が小さく見え、悪いフィットが得をするため。
  1A の外れ率 (§1.6) は値ごとの主張の較正なので、そのアーム自身の σ_fit を使う。
  **外れ** = `u > 3` (= `|Δ| > max(3σ_c, f)`; k = 3 は同じ一致判定の `k_esd`)。
- **事例の指標**: `D` = 比較集合の u の RMS、`n_out` = 外れの件数 (アーム間の比較では上の共通の分母で計算する)。
- 極性群は、極性方向の並進を散乱能で重み付けた平均ずれで除いてから比べる (両アーム同じ手続き)。設定・原点の違いは凍結時に登録した変換で参照側を写す。
- **Uiso は合否に入れない** (吸収・表面粗さを吸収し、測定系の違う参照との差が解釈できない)。相分率も参照が無いので入れない。どちらも報告はする。
- **分けて報告する**: 主相/副相 (主相 = 比較相手の結果で Σ Fc²·Icorr が最大の相)・`provenance` 別 (`refined`/`pruned`/`input`/`symmetry`) — review-response 1 巡目。

### 1.4 構造の悪化 — 独立参照が無い事例 (主に未公開データ)

- **fail 件数** `f` = `check_validity` の違反と、P1-1A の結晶化学検査器 (凍結版) の `fail` を (検査, 相) 単位で数えたもの。`unevaluated` は別集計。
  参照のある事例でも数える (安くて保守的)。
- **短結合の外れ** `b` = 検査器が第一配位圏とする結合のうち `d_fit + 3σ_d < d_min` のもの。d_min は検査器の表 (凍結版) の最短許容距離、
  σ_d は精密化結果から求めた結合長の esd。**片側 (短すぎる側) だけ** — 歪んだ多面体の長い結合は誤りでないことが多い。
  表に無い原子対は `unevaluated`。

### 1.5 フィットの質

- χ² (GSAS の値) を、**観測集合のハッシュが一致する**ときだけ比べる (proposal §5: 除外区間の内容ハッシュ)。一致しなければ `unevaluated`。
- 比較は `T-*/bkg` で行う (背景を揃えたアームに限る — review-response 1 巡目)。揃えないアームの値は報告だけ。
- Rwp は報告用 (同一観測集合・同一重みなら `Rwp 比 = √(χ² 比)`)。

### 1.6 1A の指標

- **値の集合 V** (事例 × アームごと): 各相の独立な格子定数 (結晶系で約したもの)・自由座標・精密化した占有率・Uiso・相分率。
  プロファイル・背景・装置の値は入れない (出版しない nuisance — STANDARD-PROCEDURE §2)。結晶子サイズ/微小歪みは別に報告する。
- **`provisional` 割合**: V のうち `publishable` でない値の割合 (proposal §3.1 の導出規則)。人の回答経路は無い前提 (D だけ)。
  - 値単位 `P_val` (全事例をまとめた割合) と、**全止め事例の割合** `P_case` (主相 (§1.3) の V がすべて `provisional` の事例)。
  - 主たる経路は `B-AB` (1A が最初に被さる標準経路)。`B-single`・`T-AB` も報告する。
  - **原因の帰属表**: `provisional` の値ごとに、止めた判断要求 id または検査を報告する (1 つの過敏な検出器が全体を止めているかを見分けるため)。
- **外れ率** (独立参照がある事例・§1.3 の外れの定義):
  - `O_det` = `determinacy = determined` の値のうち外れの割合 (σ_c はそのアーム自身の esd。`determined` は Phase B の証人がある経路だけで立つ)
  - `O_pub` = `publishable` の値のうち外れの割合
  - 報告のみ: `O_esd_only` (`esd_only` の値の外れ率。`determined` の方が外れやすければ、そのラベルは情報を逆向きに伝えている)・
    **止めすぎ率** (`provisional` の値のうち参照と一致するものの割合)
  - 点推定は全事例をまとめた割合。区間は**事例単位のブートストラップ** (10,000 回、乱数の種 20261012) の 95% パーセンタイル区間

## 2. P2 の同値幅と通過基準

### 2.1 事例ごとの劣化の判定 `W_i` (テンプレート対 比較相手 1 つ)

`W_i = 1` (テンプレートが悪い) となるのは、次のいずれか:

| | 条件 | 同値幅の根拠 |
|---|---|---|
| (a) | テンプレートのアームが失敗し、比較相手は失敗していない | §1.2 |
| (b) | `χ²(T-*/bkg) / χ²(比較相手) > 1.10` | U3: 「同等以上のフィット」(proposal §1) を崩さない実用上の幅。Rwp で約 5% (10.0 → 10.5)。**有意性の検定は使わない** — 母数の数が違う非入れ子の比較で、dof ~ 数千では実用上無意味な差でもほぼ必ず有意になるため。§5 の検定は run の中の判断のためのもの |
| (c) | 参照あり: `D_T − D_B > 1.0` または `n_out,T − n_out,B ≥ 2` | U4: 比較集合全体が 1σ_c ずれるのは、値ごとの雑音と区別できる最小の系統的なずれ。外れ 1 件の差は、esd が 1.5 倍過小なら 3σ の外れが 4.6% 起きるので、値が数十ある事例では偶然に起きる |
| (d) | `f_T > f_B` (全事例) | fail は範疇的な誤り (粗大誤差・物理違反) なので 1 件でも数える |
| (e) | 参照なし: `b_T − b_B ≥ 2` | (c) と同じ理由 |

- 判定できない小項目は飛ばして残りで決める。全小項目が判定できない事例は事例ごと `unevaluated`。
- 比較の組: `T-single` 対 `B-single`、`T-AB` 対 `B-AB` (フィットは各 `/bkg` 版)。

### 2.2 通過基準 (hold-out だけで判定する)

- 判定する集合は **`H` = `H-pub` ∪ `H-priv`** (§3.1)。**P2 の合否は `H` 全体だけで決める**。`H-pub`・`H-priv`・多相の部分集合は
  別にも集計し、評価可能な事例が 11 件以上ある部分集合には同じ基準での判定を**報告として**付ける (全体の合否を覆さない — 結果を見てから
  どの集合で判定するかを選べないように)。多相の部分集合が 11 件に届かなければ「多相については判定不能」と明記する (U8d)。
  R1A-2 (外れ率) も部分集合ごとに報告する (`H-pub` は天然の標本と参照の標本の組成差が混ざりうるため)。
- 比較相手ごとに、評価可能な事例数 N で **`Σ W_i ≤ c(N)`**。c(N) は「劣化率の Clopper–Pearson 片側 95% 上限 < **M = 0.25**」を満たす最大の数
  (N = 24 → 2 / 30 → 3 / 40 → 5。付録 B)。
- **2 つの比較相手の両方で満たす** (積集合-和集合検定なので多重性の補正は要らない)。
- 加えて §7 の **1B の反証条件 (R1-1〜R1-4・R3)** が 1 つも発火していないこと。1A の反証 (R1A-1/2) は **1A の採否だけ**に効き、1B の通過を
  妨げない (proposal 冒頭: 1A と 1B は独立に採否できる)。
- 準 hold-out は**合否に使わない** (§3.1 — 基準経路もテンプレートの設計もこれらを見ている)。反証条件は **`H` 単独**と
  **`H` ∪ 準 hold-out の合算**の両方で評価し、**どちらかで発火したら発火** (準 hold-out 単独は 5 件で、1 件で率 0.20 になるので単独では判定しない)。

### 2.3 P2 の結論は 3 値

`通過` / `不通過` / **`判定不能`** (評価可能な事例が N_min に届かない・合否に使う指標が判定不能・反証条件が判定不能)。判定不能は通過ではない。

### 2.4 片側性の方針

合格には**区間推定による積極的な証拠**を要求し、反証は**点推定が閾値を超えたら発火**させる (U13)。原理 3 (主張のコストと反証のコストは非対称)
の適用。反証条件が多いことによる多重性は、提案にとって不利な向き (発火しやすい) なので補正しない。

       CIF をスクリプトで検査し、値は表示しない。

   - **自由座標が 3 以上** (出発構造の `GetCSxinel` の自由軸の数)。岩塩型・蛍石型のように自由座標の無い種は比較集合が空になるので除く。

     石英・方解石・コランダム) は候補一覧から除く。**開発用の未公開データの化合物はここでは除かない** (公開の一覧から除くと、規則を再計算した人に

3. **抽出**: 候補を RRUFF の ID の数字部分の昇順に並べる。凍結 commit を GitHub に push した時刻 (サーバー側で確認できる時刻) の **24 時間後以降で最初の
   drand の round** を種に使う (git の commit 時刻は書き換えられるので使わない。`S-eval` の種も同じ規則に揃える)。その round の値 r から
   `seed = int(sha256("<r>:h-pub")[:8], 16)`、`numpy.random.default_rng(seed).permutation(len(候補))` の順に先頭から採り、**K 件** (既定 30、G5) にする。
   取得できない・読めない・処理済みと分かった・開発用の化合物に当たった事例は、理由を記録して**置換の順で次の候補**に置き換える。
4. **記録と公開**: 候補一覧・置換の順・採否は、**秘密の salt を付けた ID のハッシュ** (`sha256(salt ‖ ID)`) と件数・除外理由の種類だけを public の
   抽出 manifest に commit する。salt と平文の ID は私的 ledger に置き、ユーザーが監査できる。採用した事例の ID は P2 の後に結果と一緒に公開してよい
   (開発用の化合物は含まれていない)。
5. **取得**: 採用した事例のファイルは、1. で固定したスナップショットから**スクリプトで取り出して sha256 を計算するだけ**で、P2 まで中身を開かない・
   読み込まない・描かない。ファイルの sha256 を抽出 manifest に記録してから P2 を走らせる。P2 で解析に渡すときは、凍結版の変換スクリプトが
   **ヘッダを丸ごと除いて** 2 列にする (ヘッダの `CELL PARAMETERS` をどのアームにも渡さない)。
6. **対応づけ**: 参照構造との原子の対応・設定/原点の変換 (§1.3) は、**凍結版に含めたスクリプト**が抽出後に機械的に作る (手で作ると参照構造の値を
   読むことになる)。スクリプトが対応を作れない事例は構造の指標を `unevaluated` にする。
7. **共通の宣言**: 装置の較正ファイルが無く、ヘッダに波長も無い (G1) ので、全事例に**共通の汎用の実験室 Bragg-Brentano Cu Kα1/Kα2 の装置パラメータ**を使う。値は `S-dev`

   幅は各アームのレシピどおりに精密化する。内部標準は無いので格子は `scope = relative` (§1.3 の格子比較は `unevaluated`)。
8. **比較の範囲**: 占有率は構造の比較集合 (§1.3) と 1A の外れ率 (§1.6) から外し、報告だけにする (天然の標本と参照の標本で組成が少し違いうるため)。
   相の純度はパターンを見ないと判定できないので入り口では絞らない (不純物は相集合の完全性の証人が拾うべきもので、両アームに等しく効く)。
9. **以後の開発で RRUFF の測定パターンを使わない** (候補一覧に入りうるため)。`tests/test_holdout_guard.py` の `HOLDOUT_TOKENS` に RRUFF の
   パスの印を足すのは P1.5 の凍結の作業に含める。

    `STATUS`/`SOURCE`/`FILETYPE` の値の分布 / 蛍石の RAW 1 件 (GSAS-II の読み込みと Kα2 の比) / `Refinement_Data` の項目名 / 蛍石・硫酸鉛鉱・石英・方解石・
    コランダムの COD の CIF (座標の esd の有無と温度・圧力のタグを数えただけ) / COD の全メタデータ (候補数の上限を数えただけ。種名は表示していない)。
    どの事例の強度・セル・座標も表示していない。ただし 2θ の軸の統計を取るために全 RAW ファイルのデータ行を読んでおり、強度の列もメモリには載った
    (表示・保存はしていない)。確認に使った 5 種は候補から除く (2.)。**蛍石は準 hold-out (T4) の化合物でもあり**、その COD の CIF を読んだことは
    U10 の参照構造の候補に触れたことになる (自由座標が無いので比較集合には効かないが、明記しておく)。今後のゲート確認には hold-out と無関係な化合物を使う。

11. **候補が 3K に届かないときの補い方 (v1.5, U15)**:

      選択の余地は無い)。3K 以上なら従来どおり 3. で K 件を抽出し、`H-pub-noref` は使わない。
    - **参照なし (`H-pub-noref`)**: 2. の規則のうち**参照構造の条件だけを満たさない種** (出発構造が条件を満たし・自由座標 3 以上・除外に当たらない。
      参照の候補が無い種と、候補はあるが esd・空間群・別出版物のどれかを満たさない種) を候補とする。`H-pub` の合計が K = 30 になるように
      `K_noref = 30 − |H-pub-ref|` 件を 3. と同じ手続き (RRUFF の ID の昇順 → drand の round の値 r から `seed = int(sha256("<r>:h-pub-noref")[:8], 16)`
      → 置換の順) で抽出する。`H-pub-ref` と同じ round を使う。候補が `3·K_noref` に届かなければ `K_noref = ⌊候補数/3⌋` に下げ、不足は P2 の前に

    - **集計**: `H-pub-ref` と `H-pub-noref` を別にも報告する (§2.2 の部分集合の扱い — 11 件以上なら同じ基準での判定を**報告として**付ける)。

#### 3.2.2 `H-priv` — 未公開・新規測定

1. 範囲内 (proposal §2): CW X 線・単一ヒストグラム・単一パターン・GSAS-II で読める。出発構造の出所が記録できる。
2. **測定日と受領日の両方が P1.5 の凍結 commit より後** (自分の研究室で測るデータは「受領」だけでは未見を保証しない)。受領時に sha256・測定日・
   受領日を私的 ledger に記録し、**P2 の実行前に sha256 と日付だけの一覧 (名前なし) を public に commit する** (ledger を監査できるように)。
   最初の処理が P2 の実行であること (U8c)。
3. **6 件以上** (U8c)。実際の用途 (手元の多相・電池材料など) に近い難しさを確かめるための集合なので、**多相を推奨**する。
   構造が出版済みの化合物を測るなら、**内部標準を混ぜることを推奨**する (格子が `scope = absolute` になり、格子も比較できる)。
4. 開発用データと同じ試料の再測定は不可。**開発用の化合物 (別試料) は `H-priv` の 1/3 まで** (開発用の化合物への適合を汎化と取り違えないため。
   `H-pub` は開発用の化合物を含まないので、上限は `H-priv` の中で数える)。

#### 3.2.3 `H` 全体に掛ける条件

1. **独立参照構造のある事例を N_ref = 10 件以上** (U7)。`H-pub-ref` の事例は候補の条件として参照構造を持つ (§3.2.1-2)。
   `H-pub-noref` (v1.5, §3.2.1-11) は参照を持たない — N_ref には `H-pub-ref` と参照のある `H-priv` だけを数える。
2. **多相**: `H-pub` はほぼ単相になる (鉱物の単相標本から引くため)。多相の事例は実質 `H-priv` だけから来るので、**`H-priv` が多相を 11 件以上
   含まない限り、P2 の判定は「多相については判定不能」になる見込み**であることを予め記録しておく (U8d)。
3. `S-dev`・`S-eval` と同じ化合物 (組成と空間群が同じ) の事例は測るが **N に数えない** (proposal §6: 合成は hold-out と別の構造から作る)。
   `S-eval` は抽出した `H-pub` の化合物を母集団から除いて引く (§6.3)。

### 3.3 最小件数と検出力

- 事例ごとの劣化 `W_i` の率 p について「p < 0.25 を 95% 片側で示す」には、劣化 0 件でも **N ≥ 11** が要る。公開の 4–5 件では劣化 0 件でも
  上限が 0.45 で何も言えない (proposal §6 の「公開 4–5 件では検出力が無い」の定量化)。
- N と許容件数 c(N)・通過確率 (付録 B に全表):

| N | c(N) | 真の劣化率 2% | 5% | 10% | 25% (誤って通る確率) |
|---|---|---|---|---|---|
| 20 | 1 | 0.94 | 0.74 | 0.39 | 0.024 |
| **24** | **2** | 0.99 | **0.88** | 0.56 | 0.040 |
| 30 | 3 | 1.00 | 0.94 | 0.65 | 0.037 |

- **N_min = 24** (U1): 真の劣化率 5% で 0.88 の確率で通る最小級。20 だと 0.74 に落ちる。比較相手が 2 つあり両方で通る必要があるので、
  独立と仮定しても 24 件で ≈ 0.77 (20 件だと ≈ 0.55)。
- N_ref = 10 (U7) は外れ率 (§4.2) のため: まとめた率の 1 事例あたりの重みが 10% を超えないようにする最小。区間は事例ブートストラップで報告する。
- **`H` の適格事例が 30 件に届き、かつ `H-priv` が 6 件そろうまで P2 は実行しない** (U1・U8c。`H-pub` の抽出が既定の K = 30 なら前者は満たす。K を下げたら不足分を `H-priv` で補う — §3.2.1-1 G5)。
  `H-pub` と `H-priv` は同じ凍結版で一度に測る (片方だけ先に測ると、もう片方の結果を見てから解釈を変えられる)。N_min は評価可能な件数 (§1.2) なので実行後にしか分からず、少ない件数で 1 回
  使うとその事例は二度と hold-out にならない。実行後に評価可能な件数が 24 未満なら P2 は「判定不能」で、使った事例は以後 in-sample。

### 3.4 「1 回だけ」の定義

- 凍結版 (テンプレート・D・検査器・評価スクリプト) で、各 (事例, アーム) を**1 回実行**する。環境の指紋 (Python・numpy・BLAS とスレッド数・
  GSAS-II の版) を結果と一緒に記録する。BLAS のスレッド数は固定する (proposal §6 P1a 部品 8)。
- 再実行は**基盤の故障** (分析と無関係な異常終了・停電・ディスク) のときだけ。理由を ledger に記録する。**結果を見ての再実行は禁止**。
- (準) hold-out のファイルを P2 の前に開く・読み込む・プロットすることを禁止する (`H-pub` の取得スクリプトが sha256 を計算するのは例外)。テストは `tests/test_holdout_guard.py` が縛る
  (テンプレートの部品を使うテストが (準) hold-out を参照しない)。既存経路のゴールデンは読んでよい (P1a で決めた例外)。
- P1-1A の検査器の陽性/陰性対照には、準 hold-out の構造ファイル・参照構造を使わない (§6 の `S-dev` か、範囲外の公開構造)。

## 4. 1A の上限 (proposal §7 の 1A の反証)

### 4.1 `provisional` 割合

- **`P_val ≤ 0.50` かつ `P_case ≤ 0.50`** (`B-AB` の経路。`H` 単独と、`H` ∪ 準 hold-out の合算で — §2.2)。
- 理由 (U5): 値の過半が止まるなら、1A の出力は「全部 hold」と比べて情報を持たない。データが本当に悪くて止めるのは正しいので、
  上限は緩めに置き、**止めすぎ率と原因の帰属表**で「正しい止め」と「過敏な検出器」を見分ける。
- 例外を作らない: 相集合の完全性の証人が `unevaluated` で全値が止まる事例も `provisional` として数える (証人を計算できないことも 1A の性能)。

### 4.2 外れ率

- **`O_det ≤ 0.10` かつ `O_pub ≤ 0.10`** (独立参照のある事例。`O_det` は `B-AB` と `T-AB`、`O_pub` は全アーム)。
- 理由 (U6): 外れを 3σ_c で定義したとき、esd が正しければ外れ率は 0.27%。Rietveld の esd は系列相関などで過小になりやすく (principles §3.2
  の実効自由度)、過小評価 1.5 倍で 4.6%、1.8 倍で約 10%、2 倍で 13%。σ_ref と床 f が参照側の違いをある程度吸収する。
  「`determined` と言った値の 1 割が参照から 3σ_c を超えて外れる」なら、そのラベルは較正されていない。
- 参照のある値が 30 未満なら「判定不能」(率の 1 件の重みが 3% を超える)。

## 5. 反証の検出力の報告形式と、失敗した反証の数え方

### 5.1 報告形式 (反証プローブ 1 回ごとに 1 行)

| 列 | 内容 |
|---|---|
| `probe_id` / `case` / `arm` | どの既定・凍結に対する反証か (例: `zero_fixed`・`cell_frozen:<相>`) |
| `test` | `hamilton` (入れ子) / `vuong` (同数母数) |
| `k` / `alpha` / `critical` | 足す母数の数・有意水準 (凍結版の値と、比較用に 0.05 の両方)・χ²_k 分位点 |
| `statistic` | `Δχ²/GOF²` (Hamilton)。GOF² は**大きい方 (反証側) のモデル**の値。実効自由度の補正 (Bérar–Lelann 型の係数) を使ったら、その係数と、同じ係数を λ にも掛けたことを明記 |
| `gof2` | GOF² |
| `delta_registered` | 登録した効果量 Δ (§5.2) |
| `lambda` / `power` | 非心度 `λ = Δᵀ Σ₂₂⁻¹ Δ` と検出力 `P(χ²_k(λ) > critical)`。Σ₂₂ は反証側 (大きい方) の fit の共分散のうち足した母数の部分。**GSAS の共分散は既に GOF² を含むので GOF で割り直さない** (proposal §5) |
| `phase_role` | 主相 / 副相 |
| `outcome` | `refuted` (proposal・review-response の `default_refuted` に当たる) / `not_refuted` / `not_refuted_low_power` / `unevaluated(<理由>)` |

- k = 1 なら `power ≥ 0.8 ⇔ σ ≤ Δ / 2.80` (λ ≥ 7.85)。副相は相関で σ が大きくなり検出力が下がる — **それを隠さず列に出す** (proposal §5)。
- `not_refuted_low_power` (power < 0.8) は既定の**支持に数えない**。

### 5.2 登録する効果量 (最小の関心のある効果)

| プローブ | Δ | 理由 (U11) |
|---|---|---|
| ゼロ点の固定 (`Shift` のみ vs `Shift + Zero`) | **0.01° (2θ)** | 2θ = 60° でゼロ点 0.01° (Δθ = 0.005°) が格子に与える相対誤差 ≈ cot θ·Δθ ≈ 1.5e-4 で、格子の一致判定の床 (1e-4) を超える最小級 |
| 副相の格子の凍結 (凍結 vs 解放) | 独立な格子定数の**すべてに 0.5%** (符号の組み合わせのうち λ が最小のものを報告) | Phase B の格子摂動 (±0.7%) より小さく、解放すれば Rietveld が追える範囲 (収束半径 ~2%) の誤差 = 凍結しなければ直っていたはずの、凍結で隠れる誤差の規模。準 hold-out の実測値からは決めていない |
| P1-1B で足すプローブ | P1.5 の凍結で登録 | 同じ原則: 「出版する値を一致判定の床の外へ動かす最小のずれ」 |

### 5.3 失敗した反証の数え方

- 反証の fit が発散・例外・非有限・未収束・物理ゲート違反 (proposal §5) → **`unevaluated(<理由>)`**。「反証なし」にしない。
- その既定に依存する値は 1A では `checks` が `unevaluated` のまま = `provisional` (proposal §3.1)。評価ではプローブの `unevaluated` 率を報告する。
- プローブの `unevaluated` が 50% を超えたら §7 の R3 は判定不能 (§1.2)。

## 6. 合成ケースの作り方と出所の記録 (proposal §9 の未決を閉じる)

### 6.1 構造の出所

- 出典は**再配布できる公開 DB** (COD 等)。記録: DB の ID・版/取得日・CIF の sha256・ライセンス。
- **除外**: 準 hold-out の化合物 (Ca₅(PO₄)₃F・CaTeO₃ とその水和物・PbSO₄・Na₂Ca₃Al₂F₁₄・CaF₂)、開発用の未公開データの化合物
  (照合は私的リストで行い、名前は書かない)。`H-priv` と重なったら §3.2.3-4 で hold-out 側を N から外す (`H-pub` は抽出時に `S-dev` を除き、
  `S-eval` は `H-pub` を除いて引くので重ならない)。
- 必ず含める型: **混合占有** (2 元素が席を共有)・**極性空間群** (点群 1, 2, m, mm2, 4, 4mm, 3, 3m, 6, 6mm)・結合した特殊位置 ((x,x,x) 等)・
  **多相** (2–3 相、副相 1–10 wt%)。

### 6.2 パターンの生成

- 計算は GSAS-II の calc-only (同じエンジン)。そのままでは理想化されすぎる (GOF ≈ 1) ので、**事例の半数以上にモデルの不一致を 1 つ以上入れる**:
  非対称・Kα2 比のずれ / 最大の 1% 以下の未モデルの不純物ピーク / 多項式の族の外の背景 (非晶質のこぶ)。
- 装置パラメータは生成器の中で宣言した**合成の値** (実験室 Bragg-Brentano Cu Kα1/Kα2・放射光 Debye-Scherrer の 2 種)。
  **準 hold-out の装置ファイルを流用しない** (T3 の装置ファイルはガードの `HOLDOUT_TOKENS` に入っている)。
- 雑音は Poisson。最大計数は 1e4 と 1e5 の 2 水準。

### 6.3 注入する既知の欠陥 (出発モデルを真値から外す)

| # | 欠陥 | 期待する検出器・挙動 (実行前に manifest に書く) |
|---|---|---|
| 1 | 席の元素の取り違え | 結晶化学検査の `fail` または短結合 |
| 2 | 原子の欠落 | 残差 / 判断要求 |
| 3 | 混合占有の比の誤り | 和 = 1 + Uiso 等価で回復 |
| 4 | 1 原子の変位 (0.2–0.4 Å、短結合を作る) | 回復するか検査器が `fail` |
| 5 | 欠落相 (真値に副相 2–10 wt%、モデルに無し) | 相集合の完全性の証人が `fail` (`pass` なら見逃し) |
| 6 | 格子の異方的な誤差 (軸ごと 1–3%、DFT 型) | 収束半径内で回復 |
| 7 | ゼロ点の誤差 (1, 3 × Δ_zero。0 は無注入の組で扱う) | ゼロ点固定の反証 (§5.2) |
| 8 | 副相の格子の誤差 (Δ_cell) と格子の凍結 | 凍結の反証 (§5.2) |
| 9 | 極性群で極性方向に並進した出発 | 原点固定・並進を除いて同じ解 |
| 10 | 選択配向 (March–Dollase r = 0.8) | 段 8 / 8R |

- 大きさは登録した範囲から乱数で引く。
- **`S-dev`** (開発用): P1・P1.5 で自由に使ってよい。種も構造も自由。
- **`S-eval`** (検出器の較正用): P1.5 の凍結の**後で**生成する。乱数の種は**開発者が制御できない外部の公開乱数**から取る:
  凍結 commit を GitHub に push した時刻 (サーバー側で確認できる時刻) の 24 時間後以降で最初の drand (League of Entropy の公開ビーコン) の round
  を凍結 manifest に記録し (git の commit 時刻は書き換えられるので使わない)、その round の値 r から
  `int(sha256("<r>:s-eval")[:8], 16)` とする (凍結 commit のハッシュは commit 文の書き換えで選び直せるので使わない)。構造は §6.1 の条件を満たす母集団 (凍結時にスナップショットのハッシュを登録・`S-dev` の構造と、**先に抽出した `H-pub` の化合物**を除く) からこの種で引く。
  したがって順序は「凍結 → `H-pub` の抽出 → `S-eval` の生成」。
  反証プローブの種類ごとに**注入 20 件 + 無注入 20 件**。用途は §7 R3 の検出率・誤発火率だけ。

### 6.4 出所の記録 (事例ごとの manifest)

事例 id・集合 (`S-dev`/`S-eval`)・生成器の commit・tsumugin と GSAS-II の版・構造の出所 (§6.1)・相と wt%・装置パラメータ (値を直書き)・
2θ 範囲と刻み・最大計数・乱数の種・注入した欠陥 (種類・対象・大きさ・真値・出発値)・モデルの不一致の種類・**期待する検出器の結果
(実行前に記入)**・生成したパターンの sha256。

- 置き場所は `docs/benchmark/fit-then-judge-synthetic/` (初めて追跡ファイルを置くときに `provenance.toml` へ `synthetic` で宣言)。
  生成器と manifest を追跡し、**パターンは追跡しない** (manifest から再生成でき、sha256 で同一性を確かめる)。結果は `results/` (gitignore)。

## 8. 変更管理

1. この文書は commit した時点で**版 v1.0** として固定する。以後の変更は**新しい版** (v1.1, v2.0 …) として、変更点・理由・日付を
   付録 C に追記し、旧版の内容は git の履歴で参照する。
2. **数・規則・一覧・定義のどれかを変えたら、新しい版の下で得た結果は「新しい版の commit より後に受領した hold-out」で測るまで in-sample と表示する**。
   既に触れた (準) hold-out をその版で測り直しても out-of-sample にならない。
   `H-pub` に当たる新しい hold-out は、**新しい版の凍結の後に §3.2.1 の手続きで新しい drand round から引き直した、以前に抽出されていない候補**
   (以前の抽出で使った・置換で飛ばした候補を母集団から除く)。
3. 文言だけの修正 (数・規則・一覧・定義を一切変えない) は版の末尾を上げて「編集のみ」と明記してよい。diff で判断できないものは編集とみなさない。
4. P1.5 の凍結 manifest は、従う P0 の版 (commit ハッシュ) を記録する。P2 の結果は、P0 の版・凍結 manifest のハッシュ・環境の指紋を記録する。
5. **hold-out に触れた後は、その hold-out の評価についてこの文書を変えられない** (変えるなら上の 2. に従い新しい hold-out を要する)。
6. U1–U13 の確認による変更も同じ手続き。**開発用の実データでテンプレートを初めて走らせる前**の変更なら in-sample の表示は不要。
   それより後の変更は、開発の結果を見て評価の規則を選べてしまうので、新しい版として 2. に従う。
