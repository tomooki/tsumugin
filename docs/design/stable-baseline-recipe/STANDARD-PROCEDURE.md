# 規定の自動解析手順 (2026-07-30 決定)

**目的**: 全自動解析のための**安定な**ベースライン精密化手順。

**決定の前提となった実測**: `docs/benchmark/stable-baseline-recipe/FINDINGS.md` (10 案 × 4 データ)
および `PHASE-B-FINDINGS.md` (初期値摂動)。

---

## 0. 決定を形づくった 1 つの事実

**ピーク幅を支配するパラメータ (結晶子サイズ・微小歪み・Caglioti U/V/W) は互いに縮退しており、
標準試料による装置分解能の固定なしには分離できない。** 実測 (T1, 同一手順の 3 開始点):

| start | Rwp | サイズ (µm) | 微小歪み |
|---|---|---|---|
| 0 | 12.54 | 0.176 | 229 |
| 1 | **9.67** | 0.284 | 572 |
| 2 | 19.59 | **0.0010** (1 nm) | 1447 |

これは手順の不備ではなく**問題の性質**である。したがって規定は「縮退を解く」のではなく
**「解けない前提で正しく振る舞う」**形にする。

---

## 1. 規定の手順

```
Phase A  手順最適化        run_recipe_search(DEFAULT_CANDIDATES)  → 収束した候補を採用
Phase B  収束確認          run_multistart_rietveld(5 開始点, 並列) → クラス別に収束を判定
出力     採用解 + 何が収束し、何が初期値依存かの明示
```

`optimize_then_confirm()` が両段を配線する。`run_auto_rietveld` は**単発プリミティブのまま**
(operando は per-frame で呼ぶため, REQ-SAR-502)。

### 1.0 ②③ からの呼び方

```json
{"search": true, "multistart": {"n_starts": 5, "coord_jitter_ang": 0.05, "jobs": 5}}
```

② `auto_rietveld` の `multistart` 引数。キーは**すべてスカラ**なので他ツールの出力を要しない
(§4.5 到達可能性)。渡すと必ず Phase A → Phase B の順で回り、返り値は通常の形 + `search` +
`convergence`。`convergence.structure_is_corroborated` / `class_convergence` /
`undetermined_by_initial_values` を読む。③ の手順書は `skills/analyze` の「収束を確認する」節
(手順 3′) と M7 `AGENT_PLAYBOOK.md` §5.1。

⚠ `optimize_then_confirm` の `search_runner`/`multistart_runner` は**テスト注入専用**で ② には
出さない (callable は JSON にできない)。⚠ `extra_stages` との併用は ValueError — 収束確認は
候補を名前で固定するので追加段階を運ぶ口が無く、黙って無視すると「追加段階つきで確認した」と
読まれる。

### 1.1 Phase A — 手順最適化

- 候補 = `DEFAULT_CANDIDATES` = `default` / `sizestrain_last` / `polish` / `serious1` / `adaptive`。
  **実測でデータ毎に勝った手順を覆う**集合である (T1・CaTeO3 = `polish` / T2 = `serious1` /
  T3 = `sizestrain_last`)。単一の手順で全データを満たすことはできない (F1)。
- 採用規則は既存の `rank_outcomes` をそのまま使う: **収束したものを優先**し、同層内は Rwp、
  観測集合を跨いだ Rwp/BIC 比較はしない、同点は BIC、最後は列挙順。
- **「一つでも収束すれば採用」**でよい。手順どうしの一致は採用条件にしない — 手順差と
  ベイスン差を交絡させるため (実測: T3 の手順間一致は rounds だけが違う 2 案から来て、
  最良解は孤立した)。

### 1.2 Phase B — 収束確認 (規定で回す)

- 開始点 **5**、格子 **±0.7%** の決定論グリッド、座標ジッタ **0.05 Å** (対称性が自由な軸のみ)。
  ジッタ量は掃引で決めた (`PHASE-B-FINDINGS.md` §3)。
- **並列 (`jobs = n_starts`)**。開始点は独立なので**壁時計は 1 開始点分**になる。
  ⚠ その 1 開始点は**平均ではなく最悪** — 摂動された開始点は無摂動より数倍長くかかる
  (実測 T1: 直列 295s → 並列 222s = 1.33×、律速は最遅の開始点)。
- BLAS は 1 スレッドに固定 (親で設定し子が継承)。過剰購読の回避が半分、**縮約順序が
  スレッド数で変わるとビット同一性が壊れる**のが本質 (NFR-102)。
- 判定は `agreement(basis="start")`: 初期値が違えば独立。**軌跡の同一もビット同一も
  DUPLICATE にしない** — 全開始点が同じ手順を走るので軌跡は構造的に同一であり、別の初期値から
  ビット同一の解へ来ることは収束の最強の証拠である。

### 1.3 出力の規約 — **単一の bool を headline にしない**

実測が示したのは、有用な情報は「収束したか」ではなく**どのクラスが割れたか**だということ。
T1 は歪で、T3 は格子で割れており、**処方が違う**。

| 出力 | 意味 | 使い方 |
|---|---|---|
| `structure_is_corroborated` | 格子・座標・占有率が収束した | **解を採用してよいかの判断** |
| `class_convergence` | クラスごとの収束 | **何をすべきか**を決める |
| `undetermined_by_initial_values` | 開始点間で esd を超えて割れた値 | **出版してはならない値** |
| `is_corroborated` | 全クラスの厳密 AND | 参考 (縮退のあるデータでは滅多に真にならない) |

## 2. 採用の判断規則

> **構造 (格子・座標・占有率) が収束していれば、解を採用してよい。**
> **割れたクラスの値は「決まっていない」として報告し、出版しない。**

全クラスの収束を採用条件にすると、縮退のあるデータでは**どの手順でも解が出せなくなる**
(実測: T1 は歪が常に割れる)。一方で割れた値をそのまま出版すると、esd が付いているだけに
「決まった値」として読まれる。両方を避ける唯一の形が上記である。

これは既存の規律の延長でもある — `undetermined_parameters` (単発の esd 判定) が
「決まらなかったパラメータは失敗ではなく所見」としているのと同じで、
`undetermined_by_initial_values` は**複数開始点でしか見えない**種類の未決定を拾う。

**プロファイル (Caglioti U/V/W) の扱い**: 構造と歪が収束していれば、プロファイルについては
**最良フィットを選ぶだけでよい**。装置側の nuisance であり、値そのものを出版しない。
Rwp のばらつきは所見として報告する (恒常的なら装置分解能の固定を検討する材料)。

## 3. 現時点で規定が保証しないこと (明示)

| | 状態 |
|---|---|
| **歪 (サイズ/微小歪み) の決定** | **保証しない**。標準試料で装置分解能を固定する (拘束モード #38 / 手順の標準化と ②③ 露出 #170) まで縮退は残る。規定は「決まっていない」と報告するところまで |
| **多相 / TOF** | **未検証**。T4 を除外したため `build_recipe` の多相分岐・`phase_fraction_sum`・全 TOF 経路は傍証の対象外 |
| **結晶子サイズの物理性** | `check_validity` に検査が無く、1 nm への潰れが validity pass する。ベイスン数を水増しする (#169) |
| **T3 型の格子の平坦さ** | Rwp 0.1 ポイントの差で格子が割れる。追加測定 (OED) か情報の追加が要る |

**これらを「収束した」と読ませないことが規定の役割**である。隠して単一の bool を返すより、
何が確かで何が確かでないかを言う方が、全自動解析にとって安全である。

## 4. 実行コスト (実測)

| 段 | 壁時計 (T3 = 最も重い) |
|---|---|
| Phase A (候補 4-5 本を並列) | ≈ 3.7 分 (最遅候補) |
| Phase B (開始点 5 本を並列) | ≈ 1.5–4 分 (最遅開始点) |
| **合計** | **≈ 5–8 分** (T1/T2/CaTeO3 は 1–3 分) |

規定で回して差し支えない範囲である。

⚠ **開始点は 5 から減らさない。** 3 で試したところ T1 は valid な開始点が悪いベイスン
(結晶子サイズが潰れた解) に偏って**座標まで割れ**、T3 は valid が 1 点しか残らず一致判定が
**1 件も成立しなかった** (`insufficient_valid_starts`)。壁時計は最遅開始点で決まるので、
3 に減らしても速くはならない。
