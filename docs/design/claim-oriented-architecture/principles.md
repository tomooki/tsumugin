# 次バージョンの設計原則 — 主張指向の層境界 (claim-oriented boundaries)

**作成日**: 2026-08-21
**ステータス**: Proposed
**対象**: 層境界の返り値型・既定の扱い・判断層 (③) の責務。個別機能の追加ではなく**横断規律**。
**関連実装**: `src/tsumugin/refine_loop/` (②③ 境界) / `src/tsumugin/autorietveld/multistart.py` (判別子) /
`src/tsumugin/autorietveld/diagnostics.py` (検出器) / `src/tsumugin/sequential/engine.py` (系列適用) /
`src/tsumugin/oed/` (終端)

**【信頼性レベル凡例】**: 🔵 コード・実測に依拠 / 🟡 妥当な推論で確定 / 🔴 根拠なし推測

## 0. 先に結論

これまでの実測が示したのは「**全ての試料で収束する安定な手順は存在しない**」ことだった 🔵。
そこから導かれる設計上の帰結は「既定を廃して関数を小さくする」**ではない**。正しくはこう：

> **既定は、それが破れたことを呼び出し側が検出できるときに限り持ってよい。**

そして、そもそも収束しない事例の多くは手順の弱さではなく**問題の不良設定性**だった 🔵。
だから判断層 (③) の仕事は「別の手順を選ぶ」ことではなく「**問題を変える**」ことになる。

現行コードはこの構造を既に半分持っている。`SafeAction` / `ModelAction` の分離
([`refine_loop/action.py`](../../../src/tsumugin/refine_loop/action.py)) と、②が手順空間を掃き尽くしたら
③へ上げる遷移 ([`policy.py:99`](../../../src/tsumugin/refine_loop/policy.py)) は既に実装済み 🔵。
足りないのは層の分割ではなく、**層の境界で何を渡しているか**である。

本書は 6 つの原理と、それを支える単一の境界型 `Claim` を定める。

## 1. 診断 — 何が壊れていたのか

### 1.1 二種類の失敗を混ぜていた 🔵

| 種別 | 内容 | 正しい応答 |
|---|---|---|
| **(a) 数値的失敗** | 解は一意だが、開始点・段順・減衰の都合で到達できない | 手順を変える (② の仕事) |
| **(b) 不良設定性** | 収束すべき点が一意でない。解集合が多様体 or 等適合の別解 | **問題を変える** (③ の仕事) |

実績を振り返ると、突破口はほぼ全て (b) 側だった 🔵 — 3段格子校正 (波長を別データで校正)、
電気化学制約の追加、異方性 mustrain への一般化、NaCuHCF の D 大 U 解放と凍結、
prealign の整合先を既知相減算残差へ変更。**「より良い精密化スケジュールを見つけた」型の勝ちはほとんどない。**

現行の返り値ではこの二つが区別できない。どちらも「Rwp が下がらない」として同じ形で出てくる。

### 1.2 検出器は足りている。着地点が無かった 🔵

不良設定性の観測量は既に計算されている。

| 観測量 | 実体 |
|---|---|
| `weak_variables` (esd/\|値\| 比) | [`autorietveld/diagnostics.py`](../../../src/tsumugin/autorietveld/diagnostics.py) |
| `correlated_pairs` | 同上 |
| `max_shift_esd` / `converged` | 同上 |
| `n_basins` / `rwp_spread` | [`autorietveld/multistart.py`](../../../src/tsumugin/autorietveld/multistart.py) |

にもかかわらず ② → ③ の意思決定記録 `AnalysisStep` は
`(iteration, action, result_rwp, accepted)` しか持たない 🔵。
**検出結果を表現できる型が無いので、警告文字列に溶けて捨てられている。**

### 1.3 判別できるのに潰している具体例 🔵

`n_basins` と `rwp_spread` は独立な軸で、4 象限がそのまま欲しい判別になる。

| | `rwp_spread ≈ 0` | `rwp_spread` 大 |
|---|---|---|
| `n_basins = 1` | 決定済み・収束 | 同じ解・当てはめの良し悪し |
| `n_basins > 1` | **等適合の別解 = 決定不能** | 別々の極小・探索不足 |

`multistart.py:339` は右上を丁寧に判別している (「解が割れているのではなく当てはめの良し悪しである」)。
一方 `multistart.py:309` は下段を `rwp_spread` を見ずに一言へ潰している:

```python
if valid and n_basins > 1:
    warnings.append(f"収束先が {n_basins} ベイスンに分岐 (大域最適は未確定)")
```

**「大域最適が未確定」と「大域最適が一意でない」は別物**である 🟡。前者は探索を続ければ決まる。
後者はいくら続けても決まらない。同じ文言に押し込むと、後者に対して
「開始点を増やす / 段を工夫する」という**無限の努力を誘発する**。
歪の縮退が「原理的に未解決」として残っている形 (#169 / #170) はこれと同型と見る 🟡。

### 1.4 最も危険なのは ③ が出す制約である 🟡

③ が発行する制約 (方向凍結・restraint・格子固定) は、この系で**最も影響範囲が広く、
かつ唯一まだ反証装置を持たない既定**である。
[`sequential/engine.py:118`](../../../src/tsumugin/sequential/engine.py) は frame0 で staged フル確立 →
以降は warm start + direct refine なので、frame0 で決めた制約が系列全体を支配する 🔵。

そして凍結は**縮退を隠すのではなく決定性を捏造する** 🟡：

- Rwp は悪化しない (平坦方向を消しただけ)
- **esd は縮む** (縮退方向を除いたので共分散が健全に見える)
- `weak_variables` は空になり、`correlated_pairs` からその対が消える

つまり不良設定性の検出器が全て「決定済み」を指す。バグではなく設計通りの動作なので、
気づく契機が系の中に存在しない。

## 2. 原理

### 原理 1 — 型の値域を、現実の状態空間と一致させる

> **返り値の型が表現できない世界の状態があるなら、その状態に遭遇したとき系は必ず嘘をつく。**
> 可能性ではなく必然として。

これが最優先の診断規則である。個別のパッチではなく、**全層境界の返り値型に対して
「この型が言えない現実は何か」を機械的に問う**。答が出た場所が、系が静かに嘘をつく場所と一対一に対応する。

現行の棚卸し 🔵：

| 型 | 表現できない状態 | 強制される嘘 |
|---|---|---|
| `float rwp` | 「よく合うが決まっていない」 | 決定性の捏造 |
| `AnalysisStep(rwp, accepted)` | 「悪化で棄却」と「不良設定で棄却」の別 | 手順の問題に見せる |
| `Stop(str)` | 型付きの終了理由 | 文字列に溶かす |
| `n_basins > 1` の一言 | 等適合の別解 vs 別々の極小 | 「もっと回せば決まる」 |
| 格子 vs フレームの折れ線 | 決定不能区間 | 全点を等しい確信度で描く |
| `build_recipe -> tuple[Stage]` | 検証済み試料集合 (T1/T2/T3/CaTeO3) | 万能な既定に見せる |

この規則の利点は、**検出器を作る前に穴の位置が分かる**こと。型は読めば分かるので、
実データを回して踏むまで待つ必要がない。

### 原理 2 — 既定は反証可能なときだけ持ってよい

「安定な手順が存在しない」から導かれるのは「既定を持つな」ではない。

> **既定は反証可能でなければならない。**

既存のガード群 (revert ガード・変異証明・カナリア・ゼロ差分検出器) は、実体としては
**既定の反証装置**である 🔵。これを後付けの安全策ではなく、**アーキテクチャの中心概念**として扱う。

系のあらゆる「既定」が対象になる：関数のデフォルト引数、段列、妥当性閾値、
そして **③ が発行する制約**。

### 原理 3 — 主張のコストと反証のコストは非対称でなければならない

> **安い反証手続きを持たない主張は、系列全体に持ち回してはいけない。**
> 使うたびに再導出する。

実測での非対称 🔵：

| | 手続き | コスト |
|---|---|---|
| 縮退の導出 | 多始点 5 点 × 精密化 | 8 s/frame × 5 |
| 導出した制約の反証 | 凍結方向 ±δ の calc-only 2 点 | 60784 μs × 2 ≈ 0.12 s |

比で約 1:250。**この非対称があるから主張を 754 フレームに持ち回せる。**
754 フレーム全系列で 2 点プローブは約 92 秒。精密化本体 (8 s × 754 ≈ 100 分) に対して
**オーバーヘッド約 1.5%** 🔵。

この原理は工学的な「キャッシュか再計算か」を**認識論的な根拠の上に置き直す**。
持ち回せるかどうかは性能の都合ではなく、その主張が**安く疑えるか**で決まる。
疑えないものを持ち回すのは、検査されない既定を系全体に配ることに等しい。

**分割の粒度もここで決まる** — 関数は「1 つの反証可能な主張」の単位で切るが、
**反証が導出より安くなる単位**であること。切りすぎて反証コストが導出コストに近づいたら、
その分割は間違い (§5 の非目標を参照)。

### 原理 4 — 検査の強度を、影響範囲に比例させる

現行の勾配は逆を向いている 🔵：

| 層 | 現在の検査 | 影響範囲 |
|---|---|---|
| ① 実行原子 | 変異証明 | 1 呼び出し |
| ② 手順 | revert ガード | 1 フレーム |
| ③ 判断 (制約発行) | **なし** | 754 フレーム |

> **問題を変える権限を持つ層ほど、反証可能な痕跡を残す義務が重い。**

受入規則としては：③ の出力は制約単体では受理しない。
**(制約, 有効性の判定条件, 判定に使うスケール δ)** の三つ組でのみ受理する。
**人間が判断した場合も同じ** — 「人間が決めたので検査不要」という抜け道を塞ぐのが要点。

### 原理 5 — 最適化は観測量を売って速度を買ってはならない

> **情報を削る変換は、代替の観測量とセットでのみ許される。**

前例 🔵：

- warm start が esd を消して速度を買った (NaK operando で格子 esd が消失)
- 方向凍結が縮退信号を消して決定性を買った (§1.4)

どちらも意図通りの動作でありバグではない。だから静かに通る。

代替を置けないなら、その最適化は「この観測量は不要である」という**主張を伴っている**ので、
原理 1 に従ってその主張自体を型に出し、反証可能にする。

コードレビューで機械的に問える形にする：
**この差分は観測量を減らしていないか。減らしているなら代替は何か。**

### 原理 6 — 終端は「失敗」ではなく「次の測定の設計」

決定不能は行き止まりではない。縮退方向が得られれば、**その方向に感度を持つ観測**が定義できる。
[`oed/proposal.py:85`](../../../src/tsumugin/oed/proposal.py) `propose_measurements` の入力はまさにそれ 🔵。

> 系の終端状態は「Rwp が下がりませんでした」ではなく、
> **「この量はこのデータでは決まらない。決めるにはこの測定が要る」**。

これは実績と整合する 🔵 — 3段格子校正は CeO2 という別データを足した。異方歪は ND 第 2 バンクを見た。
D/H は決定不能と結論して凍結した。電気化学制約は物理を足した。

解析系が「答えを出す機械」から、**何が決まって何が決まらないかを判定し、
決まらないものについては次の実験を設計する機械**になる。これが到達点。

## 3. 境界型 — `Claim`

層境界で渡すものを「値」から「主張」に変える。**モジュールごとに固有の構造体を作らず、
1 種類の型を全境界で使い回す** (理由は §5)。

```
Claim = (value, evidence, scope, refuter)
```

| 要素 | 内容 | 現状 |
|---|---|---|
| `value` | 何が得られたか | ✅ これだけある |
| `evidence` | なぜそう言えるか (esd・縮退方向・多始点の散らばり) | 計算済だが渡っていない |
| `scope` | どこまで有効か (適用範囲・検証済み集合) | docstring にしかない |
| `refuter` | どう安く壊せるか (±δ プローブ・変異証明・カナリア) | 一部を後付けで実装 |

### 3.1 決定不能の型 — 証人を義務づける

`UNDETERMINABLE` を単なる列挙値として足すと、**うまくいかなかった全部がそこに落ちる**。
NaCuHCF で低 cap による境界不安定が「改善せず」に見えた件 🔵 は、
決定不能型があったらそこに分類して終わっていた可能性が高い。

> **「決定不能」は、縮退方向ベクトルと、その方向に動かしたときの実測 Rwp プロファイルを
> 添えたときにのみ主張できる。**

補間テスト (ベイスン代表を直線補間して calc-only で Rwp を評価) がそのまま証人になる。
平坦なら連続縮退、山が立つなら離散曖昧 🟡。処方が変わる：

- **連続縮退** → 方向を 1 本凍結する
- **離散曖昧** → 両者を分離する観測を足す (原理 6 / OED へ)

証人を出せないものは決定不能ではなく単に「まだ決まっていない」であり、**② に留める**。

### 3.2 「等しい」の判定 — 統計判定の規約

`rwp_spread ≈ 0` の ≈ は恣意的な閾値にせず、
**2 つのベイスンの Rwp 差はノイズで説明できるか**という統計判定にする。

#### ΔBIC はここでは空振りする 🔵

既存の規約は `bic = chi2 + n_params·ln(max(n_obs,1))`
([`segmentation.py:367`](../../../src/tsumugin/operando/segmentation.py))。
同一フレーム上の 2 解を比べる場面 (ベイスン比較・§4.3 の継ぎ目) では
`n_params` も `n_obs` も同一なので、

```
ΔBIC = Δχ²
```

に縮退する。**スケールフリーな許容量が存在しなくなり、どんな微小差でも「小さいほうが勝ち」になる。**
相数比較 (自由度が違う) には効くが、**同一自由度の 2 解の比較には ΔBIC を使ってはいけない** 🟡。

#### 同一自由度の比較には χ² のゆらぎを使う

```
σ(χ²) = sqrt(2·dof)        →  dof ~ 5000 なら約 100
```

**Δχ² が σ(χ²) を下回るなら区別できない**、が素直な許容量になる 🟡。

#### 実効自由度 — 系のどこでも効いている共通弱点 🔵

Rietveld の残差は系列相関しているため名目 `dof = n_obs − n_params` は過大で、
実効自由度はより小さい。現行の BIC は `n_obs` を**生の点数**として使っており、補正が無い。

これは継ぎ目固有の問題ではなく、**相数判定・変化点検出・ベイスン比較のすべてが同じ数に乗っている** 🟡。
対処は結晶学では既知で、残差の自己相関 (Durbin–Watson 統計) から esd / dof を膨らませる
**Bérar–Lelann 型の相関補正**が標準的 🟡。

> 直すなら `evidence/ic.py` の BICBackend 一箇所。外せば全部外れ、直せば全部効く。
> 本設計における統計判定の**単一の弱点**として記録する。

### 3.3 witness は自分の反証装置を較正する

witness を取ったとき「Rwp がノイズ内に留まった範囲」が測れる。これが将来の ±δ プローブの δ になる。
したがって **witness は方向だけでなく平坦区間の長さを記録する** 🟡。

> 証拠は結論の根拠であると同時に、その結論の**有効期限**を定義する。

## 4. 層の再定義

| 層 | 責務 | 出してよい語彙 |
|---|---|---|
| **① 実行原子** | 決定論的実行。政策を持たない。**観測は全域的** (「何も起きなかった」も返す) | 状態 + 診断 |
| **② 手順** | 手順空間の探索。既定はコードでなく**出自付きの値**として受け取る | `SafeAction` |
| **③ 判断** | **問題の再定義**。手順選択器ではない | `ModelAction` + 下記 |

③ の出力語彙に不足している 🔵：

- `FreezeDirection` — 連続縮退に対して方向を凍結する (証人必須)
- `RequestObservation` — 離散曖昧に対して分離測定を要求する (OED へ)
- `DeclareUndeterminable` — **成功終了としての決定不能** (証人必須)

`Stop(str)` を型付き終了に置き換える。現在は「決定不能」が
「Rwp が下がらないまま上限で停止」と同じ形で出てくる 🔵。

### 4.1 制約の失効条件 — 縮退方向の不変性は仮定である

frame0 の制約を系列全体に適用することは「縮退方向はフレーム間で不変」という仮定を置いている。
この仮定は破れる 🟡：

| 経路 | 内容 | 見えるか |
|---|---|---|
| **モデル次元の変化** | 相の増減でパラメタ空間の次元が変わる (K2Mn の monoclinic↔cubic) | 見える (③ イベント) |
| **ピーク交差** | 反射の重なりが変わると分離可能性が変わる。**相転移なしに縮退が生まれ消える** | 見えない |
| **少数相の立ち上がり** | Scale ≈ 0 の相は全パラメタが縮退。共存の中央では健全、**両端で縮退** | 見えない |

3 番目が決定的である 🟡：
**縮退が最も強いフレームは、共存の始まりと終わり — 科学的に最も知りたいフレームと一致する。**
そこがちょうど、frame0 由来の制約が最も強く効いて最も自信を持って誤る場所になる。

したがって：

- ② は制約を「持ち歩く」のではなく「**失効条件つきで持ち歩く**」
- **モデルが変わったら凍結は自動失効させる** (持ち越さない) 🟡
- 系列適用中は ±δ プローブで失効を監視し、破れたときだけ ③ へ上げる

### 4.2 ±δ プローブが catch しないもの (既知の限界)

正直に列挙する。プローブは**既知の制約の反証**であって**未知の縮退の発見**ではない 🟡。

| 限界 | 内容 | 対処 |
|---|---|---|
| (a) 新しい縮退方向 | 別の場所に平坦方向が生えても無反応 | 共分散の固有分解が要る。§4.3 で**発見の遅れを区間長で有界化**する (解消はしない) |
| (b) 低信号での偽陰性 | Scale ≈ 0 では全部平坦なので「制約は有効」と答える。必要条件だが十分でない | (a) と同じ |
| (c) モデル変更をまたぐ持ち越し | 次元が変わると方向ベクトルが意味を失う | §4.1 の自動失効で塞ぐ |
| (d) 全解析をどこで払うか | 共分散フル解析は全フレームでは払えない | §4.3 (アンカー + changepoint) |

### 4.3 サンプリング点の選択 — アンカー + changepoint (暫定方針, 2026-08-21)

> **暫定方針**: 共分散フル解析 (多始点 + 固有分解) は**アンカーポイントと changepoint で実行**する。
> 区間の内部は ±δ プローブで監視する。

支える不変量はこれ 🟡：

> **制約の有効域は区間である。境界は厳密に測り、内部は安く監視する。**

対象集合は既にある 🔵 — [`operando/segmentation.py`](../../../src/tsumugin/operando/segmentation.py) の
`segment_series` と sequential の changepoint 検出、および M10 のアンカー。
意味論だけが変わる (「科学的に面白い点」→「認識論的に疑わしい点」)。
そして §4.1 の (3) からして**一致することに理由がある** — 共存の端は系列が変わる点であり、
縮退が生まれる点でもある。**採択方針と科学的関心の間に緊張がない。**

#### アンカーはどこに置くか — 等間隔ではない 🟡

「何フレームおきか」を問うのが誤りで、正しくは「**縮退構造が変わりうる場所はどこか**」。
§4.1 の 3 経路のうち 2 つは**予測できる**。

| 経路 | 予測方法 | コスト | 循環 |
|---|---|---|---|
| ピーク交差 | アンカー A・B の確定格子から経路を補間 → 各フレームの反射位置を前進計算 → 対の間隔が FWHM を下回る点を拾う | calc-only | **外側** (アンカーの確定結果しか使わない) |
| 少数相の立ち上がり | 対象相の最強反射の積分強度が計数統計ノイズを下回る点を calc-only の二分探索で挟む | calc-only | 外側 |
| モデル次元の変化 | 電気化学等から先験的に既知 | 0 | 外側 |

3 つとも**制約下の内部結果に依存しない**ので、「制約が誤っているせいで検証点を選び損ねる」
という自己隠蔽が起きない。

> **アンカーは交差予測と検出可能性交差に置く。等間隔配置は根拠を持たない。**

#### 予測が外れたときの保険 — 再作業予算は下限しか与えない 🟡

アンカー k で破れが判明したら、前のアンカーから k までが疑わしくなり再実行になる。
**区間長 = 再作業エクスポージャ**。

アンカー 1 点の追加は `5 × 8 s ≈ 40 秒`、再作業は `N × 8 s`。破れ確率 p として
`p·N·8 > 40` すなわち **p·N > 5** でアンカーが得になる。N=100 なら p=5% で分岐 —
つまり**直観よりかなり密にして構わない**。

ただしこの計算は「破れが次のアンカーで検出される」前提なので、
**検出されずに誤った値を出すケースには値段が付かない**。

> 再作業予算は「これ以上疎にするのは損」を言えるだけで、「これで十分」は言えない。
> 十分性の根拠は §4.5 に移る。

#### アンカーを入れることが循環を部分的に破る 🟡

changepoint だけでは不十分で、アンカーが要る理由がここにある。

| 選択基準 | 由来 | 循環 |
|---|---|---|
| changepoint | **制約下の解析結果**から検出される | 循環の内側。制約が間違っていれば変化を吸収して見逃しうる |
| アンカー | **実験設計**から先験的に決まる (充放電の端点など) | **循環の外側** |

アンカーは解析結果に依存せずに置けるので、「制約が誤っているために検証点が選ばれない」
という自己隠蔽が原理的に起きない。前版で「循環は完全には閉じない」と書いた部分は、
**アンカーの分だけ閉じる**。

#### 未知の縮退は消えないが、沈黙が有界になる 🟡

§4.2 (a)(b) — 区間内部で新しい縮退方向が生えても ±δ プローブは無反応 — は解けない。
しかし全解析が境界で必ず走るので、**発見の遅れが区間長で上から抑えられる**。

> 無限に続きうる沈黙が、**区間長で有界な沈黙**になる。

したがって遅れを詰めたければプローブではなく**アンカーを増やす**。
アンカー密度が認識論的レイテンシのつまみになる。

#### 双方向アンカーの継ぎ目が、無料の反証装置になる 🟡

M10 のアンカー基準解析は**双方向**である 🔵。2 つのアンカーから制約を伝播させると、
2 本の鎖は区間の途中で出会う。継ぎ目のフレームでは
**異なる継承制約の下での 2 つの解**が既に得られており、追加の精密化コストはゼロ。
既存の双方向設計がそのまま原理 3 の「安い反証手続き」になる。
**継ぎ目の一致検査を受入条件に格上げする。**

**枠組みに注意** 🟡 — θ_f と θ_b は「同じ量の 2 つの独立推定」ではない。
同じ観測を共有しているので 2 標本比較としては成立しない。正しくは：

> 継ぎ目の検査は 2 標本比較ではなく、**同一データ上の 2 仮説比較**である。

この枠組みなら独立性は最初から要らない。判定量は §3.2 の Δχ² と σ(χ²) を使う
(**ΔBIC は同一自由度なので空振りする**)。

**パラメタは直接比較しない** 🟡 — θ_f と θ_b は異なる部分空間に拘束されているので
値の直接比較は意味を持たない。代わりに**両方の制約を解放し、θ_f と θ_b を開始点として再精密化する**：

- 同じ点に収束 → 差は制約のバイアスのみ。制約は両立
- 等適合のまま離れる → 継ぎ目に真の縮退がある

コストは精密化 2 回。しかも**ランダム摂動より良い開始点**である —
系列の両端から物理的な軌跡を辿ってきた点なので、jitter ボール内の任意点より意味がある。

**継ぎ目は点ではなく重なり区間にする** 🟡 — 前向きを継ぎ目より先へ、後ろ向きを手前へ
M フレーム余分に走らせると、Δχ² が M サンプル得られる。

| 重なり区間での Δχ² の様子 | 読み |
|---|---|
| 平均ゼロ近傍で散らばるだけ | 一致 |
| 系統的なオフセット | 制約のバイアス |
| 区間内で単調にドリフト | 縮退構造が区間内で変化している |

単一スカラーの許容量より遥かに診断的で、コストは `M × 8 s`
(**多始点が要らないのでアンカーの 1/5**)。

#### コスト 🟡

アンカー数を K、継ぎ目の重なり幅を M フレームとする (754 フレーム・8 s/frame を基準)。

| 項目 | 式 | K=20, M=5 | 本体比 |
|---|---|---|---|
| 本体 (逐次精密化) | `754 × 8 s` | 約 100 分 | — |
| アンカー全解析 | `5 × 8 s × K` | 約 13 分 | 13% |
| ±δ プローブ (全系列) | `2 × 0.061 s × 754` | 約 92 秒 | 1.5% |
| 継ぎ目の解放再精密化 | `2 × 8 s × (K−1)` | 約 5 分 | 5% |
| 継ぎ目の重なり区間 | `M × 8 s × (K−1)` | 約 13 分 | 13% |
| **合計追加** | | **約 32 分** | **約 32%** |

重なり幅 M が最も効く調整代で、M=5 で 13%、M=10 なら 25% になる。
アンカー全解析より重なり区間のほうが高くつきうる点に注意 —
**診断能力を上げたければ M、レイテンシを詰めたければ K** と、つまみが分かれている。

### 4.4 制約下の値の型 (暫定方針, 2026-08-21)

> **暫定方針**: 決定不能区間を帯にも欠測にもせず、**制約下の値であることを型で伝える**。

| 案 | 問題 |
|---|---|
| 帯 (band) | 「不確かさ」と「制約下」を混同する。縮退方向を観測座標へ射影する追加作業も要る |
| 欠測 (gap) | 情報を捨てる。値は**制約下の最良推定**であって、存在しないのではない |
| **型** ✅ | 値も出自も残り、**消費側全員に扱いを強制する** |

帯は失われない — witness が平坦区間長を記録している (§3.3) ので、
必要なら縮退方向を観測座標に射影して**導出できる**。型のほうが厳密に情報量が多い 🟡。

#### タグは真偽値ではなく出自ポインタ

`constrained: bool` では足りない。**隣のアンカーで検証された制約の下の値**と、
**200 フレーム前に検証された制約の下の値**は強度が違うため 🟡：

```
ConstrainedValue = (value, constraint_id, last_verified_frame, verification_method, designed_for_claim)
```

これで **2 つの暫定方針が噛み合う** — §4.3 が検証の場所を決め、§4.4 のタグがそれを指す。
`last_verified_frame` は常にアンカーか changepoint になる。
`designed_for_claim` は §4.5 の帰結で、**このサンプリング密度がどの主張のために設計されたか**を記録する
(別の主張に流用すると密度不足になりうるため)。
図のキャプション (「frames 180–260 は凍結方向 v 下の値、最終検証 frame 178」) が
**機械的に書ける**ことを受入条件にする。

#### 最大のリスクはシリアライズで潰れること 🟡

型は**最終出力まで届いて初めて機能する**。`to_dict()` / CSV / 図の出力で float に潰れたら、
**論文の図という一番効く場所でだけ保証が消える**。これは §1 で列挙した沈黙誤りと同じ形である
(最後の境界が最も平坦化しやすい)。

> **規則**: 制約タグを落とす変換を禁止する。エクスポート層のテストで、
> タグ付き値が素の float に化けないことをピン留めする。

### 4.5 十分性の基準 — 主張に対してのみ定義される

未知の機構に対する十分性は原理的に定義できない (§4.3 の再作業予算は下限しか与えない)。
しかし：

> **十分性は絶対量ではなく、主張に対して定義される。**

「格子定数 a は不連続なく変化する」と主張するなら、気にする大きさの不連続を分解できる密度が要る。
「相 B は x = 0.4 で現れる」なら、その近傍だけ密であればいい。

これは **OED を測定ではなく解析点に適用**しているだけで、原理 6 の再帰である 🟡。
「測定」= 「フレーム k での共分散フル解析」、効用 = 主張についての情報利得。

**ただし主張から決まるのは配置そのものではなく、配置が満たすべき要求の一つである。**
以下、決まる部分と原理的に決まらない部分を分ける。

#### 4.5.1 決まる部分 — 識別可能性プロファイルは計算できる 🟡

主張 H₁ と対立仮説 H₀ が**前進モデルの違い**として書けるなら、各フレームで両者の予測パターンを
計算し、実測 y(k) に対する Δχ²(k) を出せる。全フレームで calc-only、
754 フレーム × 2 で**約 90 秒**。

得られる**系列上の識別可能性プロファイル**のピークが「主張が最も強く言える場所」であり、
そこがアンカーの候補になる。道具は既にある 🔵
([`operando/discrimination.py`](../../../src/tsumugin/operando/discrimination.py))。

**これも循環の外にある** — 制約下の内部結果を使わず、生データと 2 仮説の前進計算だけで決まる。
§4.3 の交差予測と同じ資格。

> **規律**: H₁ / H₀ のパラメタ値は**アンカーの確定結果**から取る。
> 内部の制約下結果から取ると循環の中に落ちる (§4.3 の格子経路補間と同じ)。

#### 4.5.2 決まらない部分 — 効く対立仮説は同一パターンを予測する 🟡

この設計で最も重要な対立仮説はこれである：

> H₀: 「この値はデータが決めたのではなく、**制約が決めた**」

これは前進モデルの違いではない。**縮退方向上の a₁ と a₂ は、定義により同じパターンを与える。**
したがって Δχ²(k) は「小さい」のではなく**恒等的にゼロ**で、識別可能性プロファイルには何も映らない。

| 対立仮説の種類 | 判別に使う量 | 出どころ |
|---|---|---|
| 前進モデルが違う (二相共存 vs 固溶体など) | Δχ² プロファイル | **主張から計算できる** (§4.5.1) |
| 同定可能性が違う (値が制約の産物か) | ヤコビアンのヌル空間 | **§4.3。主張とは無関係** |

後者は前進計算では原理的に見えず、共分散・交差予測という別種の計算からしか出ない。
2 つの要求集合は独立で、どちらも他方を含まない。

```
配置 = (交差予測 ∪ 検出可能性交差)     ← 妥当性駆動・主張非依存 (§4.3)
     ∪ (識別可能性のピーク)            ← 主張駆動・計算可能   (§4.5.1)
     ∪ (先験的な転移点)                ← 実験設計から既知
```

> **「主張から配置が決まる」と書いてはいけない** — 妥当性駆動の側が主張に吸収されるように読める。
> 吸収されない。

#### 4.5.3 副産物 — 主張が答えられるかが事前に分かる 🟡

同じ計算に無料の診断がつく。

> **対立仮説に対する Δχ² プロファイルが全域でほぼゼロなら、その主張はこのデータからは検定できない。**

決定不能 (§3.1) の**系列版**である。しかもアンカーを置く前、解析を走らせる前、
約 90 秒で判る。主張を立てた時点で「そもそも答えが出るのか」が判定できる。

#### 4.5.4 構成手順 — 鶏と卵はブートストラップで解く 🟡

仮説のパラメタ化にアンカーが要り、アンカーを決めるのに仮説が要る。粗→細で解ける。

1. **先験アンカーだけ置く** (系列端点 + 電気化学から既知の転移点)。計算不要
2. そこから仮説をパラメタ化 → **Δχ² プロファイルを計算**
3. プロファイルのピーク + 交差予測点にアンカーを追加し、全解析
4. 必要なら再パラメタ化して 2 へ

各周回のコストは追加した全解析の分だけ。

配置の最適化自体は 1 次元問題なので厳密に解ける — 予算 K のもとで、
**交差予測点を必ず被覆し、最大区間長を L 以下に抑えつつ、識別利得を最大化する** K 点を選ぶ。
[`operando/segmentation.py`](../../../src/tsumugin/operando/segmentation.py) の
`_scan_insertions` / `_best_insertion` と同じ形の問題なので、実装パターンを流用できる 🔵。

#### 4.5.5 重み付けは計算ではなく政策

「証拠の強さ」と「妥当性の被覆」をどう秤にかけるかは目的関数の設計であり、データからは出ない。
③ の仕事である。したがって本書の他の部分と同じ扱いにする：

> **最適化器は配置だけでなく「何を捨てたか」を返す。**
> 「識別ピークを優先したので frame 340–420 の交差予測点を 1 つ落とした」が読めないと、
> 配置の妥当性を後から検査できない (原理 1 = 選ばなかった枝を返す)。

#### 4.5.6 限界 — 主張依存であること

対立仮説を書けなければ密度が決まらない。つまり**主張を書く前にサンプリングを決められない**。
これは制約ではなく規律で、原理 1 の `scope` と同じ方向を向いており、
査読者が配置の妥当性を検査できる形にもなる。

一方で、サンプリングが主張に依存する以上、**後から別の主張をすると密度不足になりうる**。
同じ解析から二次的な結論を引き出すときに効く。
だから §4.4 の `designed_for_claim` が要る — 流用したときに沈黙しないように。

## 5. 非目標 (やらないこと)

明示しておかないと誤読される。

- **「関数を小さくする」ことは目的ではない。** 失敗の真因は関数の大きさではなく
  **判断に必要な情報を握り潰したこと**。過分割は到達可能性を壊す —
  ① を細かくした結果、入力を他ツールの出力から作れない MCP ツールが 1 コミットで 3 件 DOA になった実例がある 🔵。
  原理 3 の「反証が導出より安くなる単位」がこれを事前に落とす基準になる。
- **既定を廃止しない。** 既定を消すのではなく**沈黙をやめさせる**。
  バッチでは ③ が policy を一度発行 → N フレームに適用 → 各関数は前提の成否だけ報告 →
  破れたフレームだけが ③ に戻る。③ の負荷は前提違反の件数に比例する。
- **モジュール固有の主張型を増やさない。** `Claim` は 1 種類。均質性が
  ③ からの到達可能性を守る (上記 DOA と同じ失敗を避けるため)。

## 6. 適用順序

直観は検出器から作りたくなるが、逆である 🟡。

> **検出結果を表現できる型が無いところに検出器を足しても、結果は文字列か警告に溶けて捨てられる。**

`n_basins` / `rwp_spread` / `weak_variables` / `correlated_pairs` が既に計算されているのに
効いていない (§1.2) のがその実例。検出器は足りていて、着地点が無かった。

1. **型の値域を直す** (原理 1) — §1.2 の棚卸し表を潰す。
   最小の入口は `multistart.py:309` の `n_basins > 1` を `rwp_spread` の統計判定で二分し、
   `corroborated` の reason を `multiple_basins` から
   `multiple_basins_distinct_fit` / `equal_fit_multiple_solutions` に割ること。
2. **既存の最適化に観測量保存を課す** (原理 5) — warm start と方向凍結に代替観測量を付ける。
3. **統計判定の規約を直す** (§3.2) — BICBackend の実効自由度補正。
   相数判定・変化点検出・ベイスン比較・継ぎ目検査が**すべて同じ数に乗っている**ので、
   ここを外したまま先へ進むと後段の判定が全部ずれる。
4. **非対称な反証手続きを付ける** (原理 2・3) — ±δ プローブ、補間 witness、継ぎ目の重なり区間。
5. **③ の語彙を拡張し、OED を終端に繋ぐ** (原理 6)。
6. **系列表現に `ConstrainedValue` を導入し、エクスポート層まで通す** (§4.4)。

## 7. 未着手・未決

**決着済 (暫定)**:

| 元の未決 | 決着 | 場所 |
|---|---|---|
| 共分散監視の払い先 | アンカー + changepoint | §4.3 |
| 決定不能区間の表現 | 制約下であることを型で伝える | §4.4 |
| アンカー間隔の上限 | 等間隔をやめ、交差予測 + 検出可能性交差に置く。密度の下限は再作業予算 | §4.3 |
| 継ぎ目の不一致許容量 | 2 標本比較ではなく**同一データ上の 2 仮説比較**。判定量は Δχ² vs σ(χ²)。ΔBIC は同一自由度で空振り | §3.2 / §4.3 |
| 十分性の基準 | 主張に対して定義する (OED を解析点に適用)。主張駆動の要求は**構成的に計算できる**が、妥当性駆動の要求は主張から出ない — 配置は 2 要求の和集合 | §4.5 |

以下は掘った後に残るもの。

- **未知機構に値段が付かない** 🟡 — §4.3 の再作業予算は「これ以上疎にするのは損」しか言えず、
  上限は §4.5 (主張依存) でしか閉じない。**主張の外側は原理的に開いたまま**。
  しかも §4.5.2 のとおり、主張駆動の基準は**同定可能性の対立仮説を被覆できない**
  (同一パターンを予測するため Δχ² が恒等的にゼロ)。
  したがって妥当性側の被覆は §4.3 の予測だけが担っており、その予測が外した分は
  どちらの基準からも拾えない。ここは設計で消せる種類の穴ではないので、
  消せないことを明示して持つ。
- **実効自由度の推定精度** 🟡 — §3.2 の許容量は dof_eff の見積りに乗る。
  Durbin–Watson からの換算がどれだけ効くかは実データで測るしかない。
  そして相数判定・変化点検出も同じ数に乗っているので、**直せば全部効き、外せば全部外れる**。
  本設計における統計判定の単一障害点。
- **アンカー間の格子経路の補間仮定** 🟡 — §4.3 の交差予測は経路が滑らかであることに依存する。
  一次転移で跳べば予測は外れる。転移点は電気化学から先験的に分かるのでそこにアンカーを置けば
  自己整合するが、**未知の転移**には効かない。
- **安い反証を持てない主張** 🟡 — 原理 3 に従えば持ち回せず毎回再導出になる。
  最上位の「モデルが正しい」という主張がおそらくこれで、安く反証できない。常に開いたままにする。
